# Develop on Linux

## Code Quality Tools

The repository uses clang-format and clang-tidy for C/C++, Ruff for Python, and ShellCheck and shfmt for Bash.

On macOS with Homebrew:

```sh
brew install llvm ruff shellcheck shfmt pre-commit
brew install ninja
export PATH="$(brew --prefix llvm)/bin:$PATH"
```

On Ubuntu:

```sh
sudo apt-get install clang-format clang-tidy shellcheck shfmt pre-commit pipx ninja-build
pipx install ruff
```

Run `bash tools/quality.sh --fix` to apply available formatting and lint fixes, then install the pre-commit hook with `pre-commit install` once per clone. The hook quietly runs the quality checks before each commit and prints diagnostics only on failure. Build at least one architecture first so clang-tidy can use `build/<arch>/compile_commands.json`; issues without automatic fixes are reported for manual repair.

## Architecture Builds

An architecture must be specified for `build`, `iso`, `run`, `test`, `debug`, and `all`; there is no implicit architecture default. Select it with `--arch <x86_64|aarch64>` or the `ARCH` environment variable. The command-line option takes precedence if both are supplied.

```sh
./build.sh --arch x86_64 test
ARCH=x86_64 ./build.sh test
./build.sh test-all
```

## Smoke Test

Run `./build.sh --arch x86_64 test` to configure and build the kernel, create the bootable ISO, and boot it in QEMU without a display. The test passes when the kernel emits its ready message over serial without reporting a panic. Build artifacts and compile databases are isolated under `build/x86_64` and `build/aarch64`.

The integration tests use Python's built-in `unittest` framework and keep QEMU as the execution backend. `./build.sh test-all` runs 34 cases across x86-64 and AArch64, covering panic and exception reporting, normal startup, interrupts, memory, timers, cooperative scheduling, user-mode preemption, multi-CPU scheduling, disk-write persistence across two boots on MBR and GPT disks, `shutdown` (QEMU must exit by itself) and `reboot` (the system must boot again; `POWER_TEST=shutdown` or `POWER_TEST=reboot`), shell sessions on QEMU's `max` CPU with hardware protections enabled, UART input, window-keyboard input, and shell sessions that run user programs. Both keyboard cases inject keys through QEMU's QMP interface. Each case builds its kernel and ISO, boots QEMU, and validates serial output. QEMU is stopped as soon as the expected record appears, with a timeout as a fallback. Failures include the captured QEMU output.

## Unit Tests

Run `./build.sh unit-test` for native host tests of USTAR, FAT16 reads and writes, VFS, ELF loading, terminal rendering, syscall dispatch, program-argument parsing, calendar conversion, file-syscall error codes and `Stat`, Spawn environment validation, `init.conf` `env` lines, `Seek` origins, and the C library's integer parsing, sort, environment table, allocator, `printf` and `scanf` engines, `strftime`, and `posix_spawn` requests. CMake fetches the pinned Catch2 `v3.7.1` release on the first run, then CTest runs the cases from `build/unit-tests-ninja`. These tests use an in-memory block device; QEMU remains responsible for exercising real PCI/MMIO and boot integration.

The tests and Catch2 are built with AddressSanitizer and UndefinedBehaviorSanitizer (`-fsanitize=address,undefined -fno-sanitize-recover=all`), so an out-of-bounds access, use after free or undefined behaviour fails the test that hits it. `SANITIZE=OFF ./build.sh unit-test` builds them without. On macOS the sanitized build uses Homebrew LLVM (`brew install llvm`, which `tools/quality.sh` also needs): Apple clang 17's AddressSanitizer runtime deadlocks before `main` on macOS 26. Leak checking is not available on macOS arm64.

## Initramfs

The ISO build packages `initramfs/hello.txt` as `build/<arch>/initramfs.tar` and adds it as a Limine module on both architectures. The kernel mounts the read-only USTAR archive; the shared VFS supports open, read, seek, stat, and close over it. The build also creates `build/<arch>/virtio-disk.img` with an MBR-partitioned FAT16 volume holding a known `BLOCK.TXT`, a long-named `Read Me First.txt`, and empty `home` and `bin` directories (`DISK_LAYOUT=gpt` makes a GPT disk with a protective MBR and a backup table instead); x86-64 attaches the disk through virtio-PCI and AArch64 through virtio-MMIO. Normal startup reads and verifies the test file through VFS. Run `./build.sh --arch x86_64 test` or `./build.sh --arch aarch64 test` to check the full boot path.

Both virtio-blk drivers read and write single sectors (`BlockDevice::ReadSector`/`WriteSector`). Each driver serializes requests with a lock, because one request buffer serves every CPU, and writes fail when the device reports itself read-only. `STORAGE_TEST=ON ./build.sh --arch <arch> test` boots the same disk image twice. On each boot the kernel reads a boot counter from sector 2047, the last sector before the FAT16 partition. It then writes the counter plus one and a byte pattern, checks that a write past the end of the disk fails, and reads the sector back. The second boot must report `boot count 2`, which shows that the first boot's write persisted. The ISO build recreates the disk image, so every test starts from a fresh disk.

`src/kernel/storage/partition.cpp` finds partitions. When the MBR holds a protective `0xEE` entry, it reads the GUID partition table and checks the header and entry-array CRC32s; a damaged table yields no partitions rather than falling back to the MBR. Otherwise it uses the MBR's FAT16 entries. FAT16 mounts the first partition with a valid boot sector.

FAT16 supports subdirectories and VFAT long names, such as `/home/Project Files/Meeting Notes.txt`; `.` and `..` work, and `..` at the root stays at the root. Each path component matches an entry's long name or its 8.3 short name, ignoring case. Names are up to 63 printable ASCII characters without `\ / : * ? " < > |` and may not end in a space or dot. A name that fits 8.3 with a single case in each part is stored as a short entry alone, with lower case recorded in the Windows NT case bits so `notes.txt` lists as `notes.txt`. Any other name gets long-name entries, which `src/kernel/filesystem/fat_names.cpp` encodes and decodes, followed by a generated, unique `BASIS~N` short alias in consecutive free slots; a subdirectory grows when there is no such run. A long name counts only when its sequence is complete and its checksum matches the short entry after it; otherwise the short name is used, and non-ASCII characters read as `?`. Removing a file also marks its long-name entries deleted. `VFS::Create`, `Write`, `Truncate` (shrink only), `Remove`, `MakeDirectory`, and `RemoveDirectory` work on disk paths, while the initramfs under `/system` stays read-only. A directory entry is located by its directory's first cluster (0 for the fixed-size root) and its index. New directories get `.` and `..` entries in a zeroed cluster, which is written before the parent links it, and a full subdirectory grows by one cluster. Only empty directories can be removed, and `Open` and `Remove` refuse directories. Writes may start anywhere up to the end of the file, so files grow only at their end. New clusters are zeroed before use, every FAT copy is updated, and walking a cluster chain is bounded so a looping chain fails instead of hanging. A write that fills the disk stops with the bytes written so far, and the file size covers exactly those bytes. Updates are ordered so an interrupted operation can only leak clusters: data and FAT entries are written before the directory entry that references them, and a directory entry is cleared before its clusters are freed. A `VFS::FileHandle` caches the file's size, so a second handle to the same file does not see the first one's changes, and the filesystem has no lock yet, so only one task may change it at a time. In `STORAGE_TEST`, each boot also checks the previous boot's `PERSIST.TXT`, rewrites it with 200 lines spread over several clusters, and creates and removes `SCRATCH.TMP` to check that its clusters come back. Each `STORAGE_TEST` boot then drives the shell. Boot 1 writes `notes.txt` with `write` and `write -a`, and reads it with `cat` and `ls`. It also reads `Read Me First.txt`, which mtools wrote with a long name, and writes `My Plans.txt`, which needs one. Boot 1 also creates `docs/` with `docs/plan.txt`. Boot 2 must still `cat` all three files after the restart, using a differently cased long name for `My Plans.txt`, checks that `rmdir` refuses the non-empty `docs/`, then removes both files and the directory and checks that `cat`, a second `rm`, and `ls` see them gone. After each boot, the smoke test reads the disk image with mtools: it must see the same `PERSIST.TXT`, no scratch file, `NOTES.TXT`, `DOCS/PLAN.TXT`, and `My Plans.txt` after boot 1 and none of them after boot 2, and matching FAT copies.

## User Programs And Syscalls

The CMake build compiles each program listed in `src/user/CMakeLists.txt` (`src/user/<name>.cpp`) with the matching freestanding cross-compiler and architecture-specific user linker script into `build/<arch>/programs/<name>-<arch>.elf`, and ISO generation packages every program there in the initramfs as `/system/<name>`, staged in `build/<arch>/initramfs/system`. The archive's top-level directories are `system/`, mounted read-only, and `etc/`, from `initramfs/etc`, which the kernel copies into the RAM filesystem at `/etc`. Programs may use floating point and SIMD. The kernel never touches those registers: x86-64 builds it with `-mgeneral-regs-only` and AArch64 with `+nofp+nosimd`. So the registers keep the running program's values through interrupts and syscalls, and the scheduler only saves them into the outgoing task and loads the incoming task's on a context switch (`src/kernel/arch/floating_point.h`): FXSAVE/FXRSTOR on x86-64, and q0–q31 with FPCR and FPSR on AArch64. Each CPU enables them at boot: CR0/CR4 on x86-64, CPACR_EL1 on AArch64. A new task starts with every exception masked and rounding to nearest. x86-64 programs enter `_start` with `rsp` 8 bytes past a 16-byte boundary, as if called, which SSE code on the stack relies on. Each ELF has separate RX, RO, and RW load segments. `src/kernel/process.cpp` loads a program into its own address space, maps a user stack, and enters ring 3 on x86-64 or EL0 on AArch64. A CPU exception in user mode terminates only that program; the kernel reports it with the `ExitStatusFault` or `ExitStatusKernelAccessFault` status from `src/user/syscall_abi.h`.

`src/user/syscall_abi.h` defines the syscall ABI shared by the kernel and programs, and `src/user/syscall.h` wraps it. x86-64 enters through `int 0x80` with the number in `rax` and arguments in `rdi`, `rsi`, and `rdx`; AArch64 uses `svc #0` with the number in `x8` and arguments in `x0`-`x2`. The result returns in `rax` or `x0`. Values at or above `SyscallErrorBase` are errors: as on Linux, the top 4095 values are reserved, which no size, address or process ID reaches. Each error names a cause (`SyscallErrorBadDescriptor`, `SyscallErrorBadAddress`, `SyscallErrorReadOnly`, `SyscallErrorExists`, `SyscallErrorNotDirectory`, and so on), which the C library maps to an `errno` value.

The kernel resolves every user pointer through the caller's page tables before touching it, so unmapped, read-only, or kernel addresses fail with `SyscallErrorBadAddress` instead of faulting. Blocking syscalls re-enable interrupts and yield to other tasks while they wait.

File descriptors live in a per-process table of 32 in `src/kernel/files.cpp` (`SyscallErrorTooManyOpenFiles` past that), and a new descriptor takes the lowest free number. Each names an open file, which keeps the offset and the access mode and closes when its last descriptor does: `Duplicate` and `Spawn` share it, so a copy moves the same offset, as on Unix. A child inherits every descriptor not marked close-on-exec (`OpenCloseOnExec`, `DuplicateCloseOnExec`), so the console reaches it through 0–2 unless the parent put other files there. `OpenAppend` makes every write go to the end, under the filesystem lock. Descriptors 0–2 start as the console, one open file that is readable and writable, like a terminal. A pipe (`src/kernel/pipe.cpp`) is a 4 KiB ring buffer with a read end and a write end. A read waits for data and returns what is there; once every write end is closed, it returns 0. A write waits for room and puts down pieces of up to 512 bytes whole, so writers never interleave within one; with no read end left, it fails with `SyscallErrorBrokenPipe`. Both waits end with `SyscallErrorInterrupted` after Ctrl+C, and neither holds the filesystem lock. An open file that is `OpenNonBlocking` (from `Open`, `PipeNonBlocking`, `SocketNonBlocking`, or later through `FileStatusFlags`) fails with `SyscallErrorWouldBlock` instead of waiting; a non-blocking write puts down the whole pieces that fit. The flag belongs to the open file, so `Duplicate` and `Spawn` share it; on disk files it changes nothing, and the console's cannot be set. Writing prints the bytes as one unit, so another program's output cannot land in the middle; tab prints as a space, bytes above `0x7F` as `?`, and control bytes other than ESC, `\r` and `\b` are dropped. Reading waits for a line, as `ReadLine` does, and only the foreground process may read (`SyscallErrorNotForeground` otherwise). It returns the line with its `\n`, and keeps what does not fit the buffer for the next read. There is no end-of-file key yet. `Seek` on it fails with `SyscallErrorNotSeekable`, and `Duplicate` can put it back on a descriptor that was closed. Paths are at most 63 characters, and the shell's double quotes keep spaces inside one argument (`cat "my notes.txt"`). `/` is the FAT16 disk, and the read-only initramfs's `system/` directory is mounted at `/system`, so `/system/hello.txt` is its `system/hello.txt`. Four virtual filesystems are mounted beside them (see Virtual Files below): `/etc`, a RAM copy of the initramfs's `etc/`, `/dev`, `/proc` and `/tmp`. A disk directory with one of these five names in the root would be hidden by the mount. Every process has a working directory, which starts as its parent's. init starts in `/home`, or in `/` when the disk has none, so the shell does too. Relative paths in file syscalls are joined to it, and `.`, `..`, and repeated slashes collapse lexically (`src/kernel/filesystem/path.cpp`), so `/home/..` is `/`. `ChangeDirectory` accepts only existing directories, but a directory removed afterwards leaves the old path in place, and calls through it then fail. Listing `/` shows `system/`, `etc/`, `dev/`, `proc/` and `tmp/`, followed by the disk's root entries, and `/system` lists its initramfs files. `OpenCreate`, `OpenTruncate`, and `OpenAppend` (start at the end of the file) require `OpenWrite`, and opening an initramfs file for writing fails with `SyscallErrorReadOnly`. A disk, `/tmp` or `/etc` file may have one writer or any number of readers, and an open file cannot be removed; both cases fail with `SyscallErrorBusy`. These rules exist because each descriptor caches the file's size and clusters. When a process exits, including after a fault or Ctrl+C, the kernel closes its descriptors. `Read` and `Write` check the whole user buffer first and then move data through a 512-byte kernel buffer, and a blocking `Sync::Mutex` (`src/kernel/sync/mutex.h`) keeps filesystem calls from different CPUs from interleaving.

`Poll` asks each descriptor for its events: files are always readable and writable as opened; a pipe's read end is readable with data and hangs up without writers, and its write end is writable with 512 bytes free and reports an error without readers; sockets report data, the end of a stream, a waiting connection, buffer space, hang-ups and errors; and the console is writable, and readable for the foreground group when input is waiting (a canonical read may still wait for the rest of the line). Pipes and sockets notify `src/kernel/poll.cpp` whenever their state changes, and a waiting `Poll` checks again after each notification. Console input sends none, so a `Poll` on the console checks again every tick.

Ctrl+C (serial byte `0x03`, or Ctrl+C on the PS/2 or virtio keyboard) interrupts the console's foreground group. Every process belongs to a process group: a child joins its parent's group unless `Spawn` gets `SpawnSetGroup`, which names another group (the caller's, or one holding one of its children) or, with group 0, starts a new one that the child leads; a session leader always leads a new group. A child's group takes the console unless it is spawned with `SpawnBackground`, and only processes in the foreground group may read it (`SyscallErrorNotForeground` otherwise). When the foreground group's last process is reaped, the console returns to the group of the process that waited. `ForegroundGroup` lets init and session leaders move it, as `tcsetpgrp` does. Ctrl+C marks every process in the foreground group except session leaders and init, so Ctrl+C at the shell's own prompt only discards the line. The console echoes `^C` and sends `SIGINT` to each process in the group (see Signals below). The shell prints nothing for a command `SIGINT` ended. Children never outlive their parent: when a process exits, the kernel sends `SIGKILL` to its remaining descendants and reaps its children before the parent's own exit completes.

### Signals

Each program has pending and blocked signal sets and an action per signal (`src/kernel/signals.cpp`), with Linux's numbers; the stop signals 19-22 do not exist, since processes cannot be stopped. A signal is sent by `Kill`, by Ctrl+C (`SIGINT`), by a dying parent (`SIGKILL`), by a write to a pipe with no reader (`SIGPIPE`, besides `SyscallErrorBrokenPipe`), and by a child's exit (`SIGCHLD` to its parent). An ignored signal, or one whose default is to be ignored (`SIGCHLD`, `SIGCONT` and two others), is dropped when sent; the others stay pending until the program returns to user mode, after a syscall or when a timer tick preempts it. Blocking calls (`Sleep`, `Wait`, `Pause`, console and pipe reads, pipe writes) give up with `SyscallErrorInterrupted` once a signal they would take is pending. The program then takes the lowest pending signal it does not block. The default action ends it with exit status `ExitStatusSignalBase + signal`, which `waitpid` reports as `WIFSIGNALED`. A handler runs on the program's own stack: the kernel saves the interrupted registers, its floating-point state (FXSAVE, or q0-q31 with FPCR and FPSR) and the signal mask in a frame below the stack pointer, past a 128-byte red zone, blocks the signal and the action's mask, and enters the handler with the signal number as its argument, returning to the restorer the C library registered. The restorer makes `SignalReturn`, which puts everything back, refusing kernel addresses, flags outside the user-changeable ones, and MXCSR or FPCR/FPSR bits that would fault or are undefined; a frame that cannot be written or read ends the program with `SIGSEGV`. CPU exceptions still end a program as `SIGSEGV` without running a handler. Children start with every handler back at its default action, while ignored signals and the blocked mask carry over, as across exec.

### Virtual Files

The VFS (`src/kernel/filesystem/vfs.cpp`) sends each path to one of five filesystems by its first component, and each open file records which kind it is: archive, disk, device, memory or generated.

- **`/dev`** (`devices.cpp`) holds `null`, whose reads end at once; `zero`, which reads as zero bytes; and `random`, which reads from `Random::Next`, mixing `RDRAND`/`RNDR` with the cycle counter. All three take and discard writes, report size 0 and file type `Device` (`S_IFCHR`), and accept any seek. Nothing else can be created in `/dev`.
- **`/tmp`** (`tmpfs.cpp`) is a RAM filesystem with nested directories and case-sensitive names, up to 63 characters. It holds at most 128 files and directories and 4 MiB of data, on the kernel heap, and a write past that is short. Its contents last until restart. Open files follow the disk's rules (one writer or many readers, and no removing an open file), and `rmdir /tmp` fails with `SyscallErrorBusy`, like `/`.
- **`/etc`** is the same RAM filesystem's second root, so it shares those limits with `/tmp`, and moving a file between the two copies it. At boot the kernel copies the initramfs's `etc/` files into it (`VFS::LoadEtc`), so `/etc/hosts` and `/etc/resolv.conf` can be changed until the next boot, which starts again from the initramfs (`initramfs/etc/`). This is a stopgap: [ideas.md](ideas.md) ("A persistent `/etc`") lists its limits and the ways to replace it.
- **`/proc`** (`procfs.cpp`) is read-only. It lists `meminfo`, `stat`, and one directory per process, by ascending ID, each holding `status`. A file's text is made when it is opened, so a reader sees one snapshot.
  - `status` gives `Name`, `State` (`R`, `S` or `Z`, as on Linux), `Pid`, `PPid`, `Pgid`, `Pages` mapped, `PageLimit`, `OpenFiles`, `CpuTimeMs` (the timer ticks the process ran for, on any CPU), `LastCpu` and `StartTimeMs` (uptime when it was spawned).
  - `stat` gives `UptimeMs`, `Cpus`, and each CPU's busy time as `Cpu<n>BusyMs`, the ticks it ran a task rather than idling.
  - `meminfo` gives `MemTotal` and `MemFree` from the page allocator, the kernel heap's mapped size (`KernelHeap`) and the memory `/tmp` holds (`Tmp`), in kB.
  - The file system takes its data from `process.cpp` through callbacks (`Procfs::SetSource`), so the host tests can supply their own.
  - `/proc/self` is rewritten to `/proc/<pid>` when a syscall resolves a path (`Path::ReplaceProcSelf`).

### Device registers

`Memory::MapDevice(physical, size)` (`src/kernel/memory/device_memory.cpp`) maps device registers uncached into the kernel half at `0xFFFFF00000000000 + physical`, so drivers reach them whichever address space is active. `PageFlags::Device` selects Device-nGnRnE memory on AArch64 and `PCD`/`PWT` on x86-64. The AArch64 UART, PL031 RTC, GICv2, and virtio-mmio devices, and the x86-64 local APIC, all use it. The AArch64 UART uses Limine's identity map only until virtual memory is initialized, so the earliest panics still print.

### Position-independent programs

User programs are built as static position-independent executables (`-fpie -Wl,-pie -Wl,--no-dynamic-linker -Wl,-z,text`), linked at 0 by `src/user/linker_<arch>.ld`. The ELF loader accepts `ET_DYN` images, adds the load bias to every segment, and applies the `RELATIVE` relocations listed under `PT_DYNAMIC` while the segments are still writable, then sets their final permissions. It rejects relocations that need symbols, a PLT, or a write into a non-writable segment. Spawned programs get a random image base; the kernel's own test programs load at `0x400000` (x86-64) or `0x0000400000000000` (AArch64).

**Dynamic-linking policy:** FeatherOS runs only static PIEs. Every program carries its own copy of the C library, and the kernel never resolves symbols. If shared libraries are added later, a user-space dynamic linker will load and relocate them, the way `ld.so` does on other systems; the kernel will keep applying only `RELATIVE` relocations, to the dynamic linker itself.

### CPU protections

`src/kernel/arch/<arch>/cpu_features.cpp` enables hardware protections on every CPU when the boot CPU reports them, and startup logs `CPU protections: ...`:

- x86-64: SMEP stops the kernel from executing user pages, and SMAP stops it from reading or writing them. `RDRAND` feeds the random source.
- AArch64: every user page is privileged-execute-never anyway; PAN stops kernel access to user pages, and `RNDR` feeds the random source.

The loader copies into a new program through its user addresses inside an `Arch::CpuFeatures::UserAccessWindow` (`stac`/`clac`, or clearing and setting PAN). Interrupt entry closes any open window: x86-64 runs `clac`, and AArch64 clears `SCTLR_EL1.SPAN` so taking an exception sets PAN. QEMU's default `qemu64` and `cortex-a72` CPUs have none of these features. Set `QEMU_CPU=max` to test with them, for example `QEMU_CPU=max SHELL_TEST=ON ./build.sh --arch x86_64 test`; the smoke test then requires the full protections line.

### Security invariants

- User programs never reach kernel memory: user mappings must lie below `0x0000800000000000` on both targets. AArch64 user page tables contain no kernel mappings at all, because the kernel and its devices live in `TTBR1`, and the ELF loader rejects segments outside that range before it copies anything.
- Every syscall pointer is translated through the caller's page tables before use, so kernel, unmapped, or read-only addresses return `SyscallErrorInvalidArgument`.
- No page is both writable and executable: the ELF loader rejects W+X segments, and stacks, heap, and arguments are non-executable. On AArch64 every user page is also privileged-execute-never, so the kernel cannot run user code.
- A CPU exception in user mode terminates only that program.
- Each process has at most 1024 pages and 16 live children.
- Spawned processes get a randomized layout (`Process::RandomUserLayout`): the stack top lands on a random page in a 1 TiB window (`0x7000…` on x86-64, `0x6000…` on AArch64), the arguments page sits just above it past a guard page, and the heap starts up to 256 MiB above the image. `src/kernel/random.cpp` mixes the CPU cycle counter through splitmix64; it is not a cryptographic generator. Programs the kernel spawns also load at a random image base in a 1 TiB window at `0x1000…`.

User memory grows on demand within the per-process page limit. The stack occupies a 64-page region ending at `Process::UserStackTop`: one page is mapped at load, and a not-present user page fault inside the region maps another zeroed page and resumes the program. The region's lowest page is never mapped, so a stack overflow faults there and terminates only that program. The heap starts at the page after the highest ELF segment; `ExtendHeap` maps whole pages eagerly up to the stack region's guard page. A negative increment lowers the break, no further than the heap's start. It unmaps every whole page above the new break and frees its frame, so the pages count against the limit again; the page holding the new break keeps its contents. Only the current CPU's TLB is flushed. That is enough because a process runs on one CPU at a time, and every switch reloads the page-table root, which drops the old entries: CR3 on x86-64, where user pages are not global and PCIDs are unused, and `TTBR0_EL1` with `tlbi vmalle1` on AArch64. Threads sharing an address space will need a TLB shootdown.

At entry, each program receives a pointer to a read-only `FeatherOS::User::ProgramArguments` block containing its process ID, the full command line, and `argument_count`/`argument_values` (the line split at spaces, at most 16 arguments in 63 characters). After a program exits, `Memory::DestroyAddressSpace` frees its user-mapped frames, private page-table frames, and root frame; it refuses to destroy an active address space and preserves shared kernel mappings. QEMU memory tests verify that free-frame accounting returns to its pre-test value on both architectures.

Normal boot first runs `src/user/test_program.cpp` twice as scheduled tasks to verify console output, exit statuses, and that user mode cannot read a mapped kernel address.

## C Library

`src/libc/` is FeatherOS's own C library, written from scratch with no outside code. The headers in `src/libc/include/` are plain C, wrapped in `extern "C"` for C++ through `__BEGIN_DECLS`. The implementation is freestanding C++, built by CMake as `libfeatheros_c.a` with the same flags as the programs, and every program links it. Only the compiler's freestanding headers come from elsewhere (`stdint.h`, `stddef.h`, `stdarg.h`, `stdbool.h`). Our `limits.h` adds the `long long` limits, which GCC's own leaves to the C library in C++. Every program in `src/user/` is written against it, except the kernel self-test `test_program`. [posix.md](posix.md) lists every function, how it differs from POSIX, and what is left out on purpose; this section covers how it works.

A program with a `main` also links `start.cpp`, the C library's `_start`. It copies the arguments to writable memory, since the kernel maps them read-only and C lets a program modify its `argv` strings. It then runs the `.preinit_array` and `.init_array` constructors (C++ static objects and `__attribute__((constructor))` functions) and calls `exit(main(argc, argv))`. `exit` runs `atexit` handlers and static destructors newest first, then the `.fini_array` destructors, and passes the low 8 bits of the status to the kernel, as POSIX does. That also keeps a program's status apart from the kernel's fault statuses. `abort` exits with status 134, what a shell shows for `SIGABRT`, because there are no signals yet. The C++ runtime hooks are `__cxa_atexit`, `__cxa_guard_*` and `__cxa_pure_virtual`; static-local guards take no lock because programs are single-threaded.

Supported so far:
- `string.h`: the `mem*` and `str*` functions, `strtok_r`, `strdup`/`strndup` and `strerror`.
- `ctype.h`: ASCII classification and case mapping.
- `errno.h`: Linux error numbers. `errno` is `*__errno_location()`, so each thread can get its own later.
- `setjmp.h`: written in assembly per architecture in `src/libc/arch/<arch>/setjmp.cpp`.
- `stdlib.h`, integer parts:
  - `exit`, `_Exit`, `abort`, `atexit` (up to 32 handlers)
  - `abs`, `div` and their `long`/`long long` forms
  - `atoi` and the `strtol` family, with base 0, `errno` set to `ERANGE` on overflow and `EINVAL` on a bad base
  - `qsort` (heapsort, `src/libc/heap_sort.h`), `bsearch`
  - `rand`/`srand`
  - `getenv`, `setenv`, `unsetenv`
  - `malloc`, `calloc`, `realloc`, `free`
- `unistd.h`:
  - `read`, `write`, `close` and `lseek` (descriptors 0–2 are the console)
  - `unlink`, `rmdir`, `chdir`, `getcwd`, `access`, `isatty`
  - `sleep`, `usleep`, `getpid`, `getppid`, `_exit`, `environ`
- `fcntl.h`: `open` with `O_RDONLY`/`O_WRONLY`/`O_RDWR`, `O_CREAT`, `O_EXCL`, `O_TRUNC`, `O_APPEND` (every write goes to the end) and an ignored `O_CLOEXEC`; `creat`.
- `dirent.h`: `opendir`, `readdir`, `rewinddir`, `closedir`. Listings have no `.` and `..`. A stream keeps reading the same directory after a `chdir`.
- `time.h`:
  - `time`, `gmtime`/`localtime` and their `_r` forms (UTC only, from 1970 on)
  - `mktime`/`timegm`, which normalize out-of-range fields
  - `strftime` (the C locale, header-only in `src/libc/time_format.h`), `asctime`, `ctime`
  - `clock_gettime` (`CLOCK_REALTIME` to the second, `CLOCK_MONOTONIC` to the millisecond), `nanosleep`
- `spawn.h` and `sys/wait.h`:
  - `posix_spawn`/`posix_spawnp` build the kernel's one-line command from `path` and `argv`, so an argument cannot hold a double quote; `argv[0]` becomes the path, or the bare name for a program in `/system`. `posix_spawnp` searches `PATH` (`/system:/bin` when unset).
  - File actions and attributes can be initialized but hold nothing.
  - `waitpid`/`wait` use the Linux status encoding, with a CPU exception reported as signal 11 and Ctrl+C as signal 2.
  - `waitpid(-1, …)` polls the children `posix_spawn` started every 10 ms.
- `sys/stat.h`: `stat`, `fstat`, and `mkdir`. With no users yet, the mode only says whether a file can be written (`0644` or `0444`, and `0755` or `0555` for directories); the console is a character device, and times are 0.
- `sys/types.h`.
- `stdio.h`:
  - formatting: `printf`, `fprintf`, `dprintf`, `sprintf`, `snprintf` and their `v` forms
  - streams: `fopen` (modes `r`, `w`, `a`, with `+` and an ignored `b`), `fdopen`, `fclose`, `fflush`, `setvbuf`/`setbuf` (mode only)
  - reading and writing: `fread`/`fwrite`, `fgetc`/`getc`/`getchar`, `ungetc` (one character), `fgets`, `getline`, `fputc`/`putc`/`putchar`, `fputs`, `puts`
  - position and state: `fseek`/`ftell`/`rewind`, `feof`/`ferror`/`clearerr`, `fileno`
  - also `remove` and `perror`
  - scanning: `scanf`, `fscanf`, `sscanf` and their `v` forms (`src/libc/scan.h`), with integers and the `printf` length modifiers, `%e`/`%f`/`%g`/`%a` (`float`, with `l` `double`, with `L` `long double`), `%c`, `%s`, `%[...]` sets, `%n`, `%*` and widths.
- `math.h` (`src/libc/math_functions.h`):
  - exact: `fabs`, `copysign`, `floor`, `ceil`, `trunc`, `round`, `fmod`, `frexp`, `ldexp`/`scalbn`, `modf`, `fmin`, `fmax`, and `sqrt` (the hardware instruction)
  - within 1–3 ulps of the host's results: `exp`, `exp2`, `log`, `log2`, `log10`, `pow`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `sinh`, `cosh`, `tanh`, `hypot`
  - `float` versions of each (computed in `double`), the classification macros, `HUGE_VAL`/`INFINITY`/`NAN` and the `M_` constants
  - Each function reduces its argument to a small interval and sums a Taylor series there. `pow` keeps `y ln x` in two parts so large results stay accurate.
  - sin, cos and tan reduce by pi/2 in three exact parts and lose precision above about 10^6.
  - Errors set `errno` (`EDOM`, `ERANGE`). There are no `long double` versions.
- `assert.h`: a failed `assert` prints `file:line: function: Assertion `expression' failed.` to stderr and aborts; `NDEBUG` turns it off.

One `printf` engine (`src/libc/format.h`) serves every formatting function through a sink: a stream, a buffer, or a descriptor. It supports `d i u o x X c s p f F e E g G a A %`, the flags `- + space # 0`, width and precision (including `*`), and the length modifiers `hh h l ll j z t L`. A null string prints `(null)` and a null pointer `(nil)`, as in glibc. `%n` is not supported, since it writes through a pointer the format supplies.

Floating-point output is exact (`src/libc/float_format.h`). A binary float is an integer times a power of two, so a big integer (`src/libc/big_integer.h`) produces every decimal digit, and rounding sees all of them, with ties going to even as in glibc. The host tests compare the output with the host's `printf` digit for digit. Digits past precision 1100 print as zeros, which is exact for every `double`. `%a` rounds half to even too, and a carry may make the leading digit 2, as in glibc. `strtod`, `strtof`, `strtold` and `atof` (`src/libc/float_parse.h`) are correctly rounded the same way. They keep 800 significant digits, plus a sticky bit for later ones that still settles ties, and accept hexadecimal floats, `inf`, `infinity` and `nan(...)`. `long double` is the x87 80-bit format on x86-64 and the 128-bit IEEE format on AArch64. Both print and parse exactly. On AArch64, `long double` arithmetic and comparisons need compiler runtime routines that are not provided, so programs can only move such values, print them and parse them.

Each stream has a 512-byte buffer. stdout is line-buffered, and stderr is unbuffered, though one call's output is still written at once. Files are fully buffered. Reading from the console first flushes stdout, so a prompt without a newline appears. `exit` flushes every stream after the `atexit` handlers and destructors; `_exit` and `abort` do not. Streams in `a` mode write at the end of the file even after an `fseek`. Seeking past the end fails with `EINVAL`, and the console cannot seek (`ESPIPE`). There are 16 file streams besides the three console ones, matching the descriptor limit.

A failed call sets `errno` and returns -1. `src/libc/syscall_result.h` maps each syscall error to an `errno` value, for example `SyscallErrorBadAddress` to `EFAULT`; a background program's console read fails with `EIO`, as on Linux.

`malloc` (`src/libc/heap_allocator.h`) is a first-fit allocator over `ExtendHeap`. Each block has a 16-byte header, so payloads are 16-byte aligned. Free blocks are kept in address order, which lets `free` merge a block with free neighbors on both sides; `realloc` shrinks in place or grows into a free neighbor before it moves the data. The heap grows in 64 KiB steps, and only by what the free block at its end lacks. When a `free` or `realloc` leaves more than 256 KiB free at the end of the heap, the allocator returns all but 64 KiB of it, in whole 64 KiB steps, with a negative `ExtendHeap`; the cushion keeps a loop of large allocations from making a syscall each time. It first checks that the break is still where its memory ends, so it never takes back memory a program got with its own `sbrk`. Free space below blocks still in use stays in the heap, since only the end can move; `mmap` would lift that, as noted in [ideas.md](ideas.md). Each region ends in a marker block that is never freed, so a block never takes memory past its region for a neighbor. A header tag catches frees of pointers that did not come from `malloc`, and double frees: `free` and `realloc` then print `free: invalid pointer` and abort. C++ `new` and `delete`, including the array and sized forms, use `malloc`. With exceptions disabled, a failed `new` prints a message and aborts instead of throwing. One lock (`src/libc/lock.cpp`) keeps threads from using it at once. `ExtendHeap` checks the page limit before it maps anything, so a request that is too large fails cleanly and the heap can still grow afterwards.

The environment comes from Spawn: `_start` loads the block the parent passed into a fixed table (`src/libc/environment_table.h`) before constructors run, and `environ` points at its entries. The table is the size Spawn accepts (1 KiB, 32 variables), so anything a program sets can be passed to its children; `setenv` fails with `ENOMEM` beyond that. Programs should not assign `environ` themselves.

The parser, the sort, the environment table, the allocator, the `printf` and `scanf` engines, `strftime`, the `posix_spawn` request builder, float conversion, and the math functions are header-only, so host unit tests cover them, most against the host's own C library and `libm`. The allocator runs over an in-memory arena, including a randomized run, and the engine's output is compared with the host's `snprintf` for every flag combination. `libctest one "two words"` checks the rest on both architectures: it prints through stdio and reads three typed lines at its `> ` prompts, with `read`, `fgets(stdin)`, and `scanf`. It also covers descriptors, directories, `/dev`, `/tmp` and `/proc`, numeric `getnameinfo` and names from `/etc/hosts`, time, and `posix_spawn`, starting `echo`, `env`, a copy of `echo` in `/tmp` by path, by relative path and through `PATH`, a text file, a device and a directory (which fail), a failing child, a faulting one, and children with `POSIX_SPAWN_SETSID` and `POSIX_SPAWN_SETPGROUP`. It also runs a child whose `assert` fails, and checks `sbrk`, `sched_getcpu`, that `reboot` is refused, and that `longjmp` restores AArch64's callee-saved `d8`–`d15`. Host tests also check that a line split by the shell reaches a program as the same words after `posix_spawn` joins it and the kernel splits it again. `env` prints the environment and uses only the C library.

## Scheduler And Processes

Tasks are heap-allocated, so their number is limited only by memory. Each has a 16 KiB kernel stack from `src/kernel/memory/kernel_stack.cpp`: stacks live at `0xFFFFFC0000000000` with an unmapped guard page below each, so an overflow faults instead of corrupting a neighbour. Reaped stacks return to a pool still mapped, so reuse never unmaps a kernel page and needs no TLB shootdown. On x86-64 every kernel-half PML4 entry is created at boot, so kernel mappings added later appear in every address space. Each task also keeps its own user exception state; context switches also preserve the AArch64 user stack pointer (`SP_EL0`), and x86-64 restores the TSS kernel stack after blocking syscalls. `Scheduler::Initialize` adopts the boot thread as a task and creates an idle task that halts the CPU (`hlt`/`wfi`) whenever no other task is ready. Tasks have a priority (`Low`, `Normal`, or `High`; set with `Scheduler::SetPriority`). Each CPU runs the highest-priority ready task, rotating among tasks of equal priority, and a yielding task keeps running if no ready task outranks it. Lower priorities can starve while higher ones stay ready. Tasks yield cooperatively or are preempted by periodic timer interrupts when preemption is enabled; the kernel can wait for exit statuses and reap completed tasks, which frees them.

Waiting tasks do not run. `Scheduler::Wait` blocks until the task exits, `SleepUntil` sleeps until a timer tick, and `WaitOn`/`WakeAll` block on a `WaitQueue` with an optional deadline tick. `ReadLine` uses this to block until a keyboard or UART event arrives; the timer interrupt moves UART input into the event queue. `Sync::SpinLock` (`src/kernel/sync/spinlock.h`) protects the scheduler, input queue, page allocator, heap, and process table; `LockIrqSave` and `SpinLockGuard` also mask interrupts. The scheduler lock is held across context switches: the switched-in task releases it and then restores its own interrupt state. Code that waits on a condition holds its own lock and passes it to `WaitOn`, which releases it while the task waits; subsystem locks are always taken before the scheduler lock. Process records in `src/kernel/process.cpp` are heap-allocated too; each has a parent, its own address space, and a page limit (1024 pages by default) covering its ELF segments, stack, and arguments block. Console input belongs to a foreground process group (see Ctrl+C below). Run `SCHEDULER_TEST=ON ./build.sh --arch x86_64 test` or `SCHEDULER_TEST=ON ./build.sh --arch aarch64 test` for kernel-task lifecycle checks. Spawned programs are time-sliced: they run in user mode with interrupts unmasked, and every timer tick on their CPU may switch to a higher-priority or other ready task. Kernel tasks are switched only when they block or yield, except in the scheduler test. Run `USER_PREEMPTION_TEST=ON ./build.sh --arch x86_64 test` or `USER_PREEMPTION_TEST=ON ./build.sh --arch aarch64 test` to verify timer preemption while user code is executing. The scheduler test also covers wait-queue blocking and wakeup, timed sleep, wait deadlines, and three rounds of 12 concurrent tasks without leaking page frames, priority ordering; the memory test checks that a kernel stack's guard page faults.

### Threads

A process runs up to 16 threads (`User::MaximumThreads`), the main one included, as scheduler tasks that share its program: the address space, descriptors, working directory and children. Each thread has its own kernel stack, registers and floating-point state, signal mask and ID (`ThreadCreate`, `ThreadExit`, `ThreadJoin`, `ThreadId`; `pthread.h` in the C library). Stacks are kernel-managed slots of 64 pages, stacked below the main stack (`src/kernel/thread_stacks.cpp`): each grows on demand to 63 pages, with its lowest page an unmapped guard, and stays mapped after its thread ends so the next thread in the slot reuses it. A new thread starts at `entry` with its first argument pointing to `{first, second}`, which `ThreadCreate` writes at the top of its stack; the C library's start routine reads its function and argument from there and calls `ThreadExit` with the function's result.

The process ends when `Exit`, a CPU exception or a terminating signal ends any of its threads: the first status wins, and the others get `SIGKILL`. `ThreadExit` ends only its thread, so after `pthread_exit` in the main thread the process lives on until its last thread ends, with status 0 (the C library calls `exit(0)` in the last thread, so atexit handlers and stdio run too). The parent's `Wait` returns only once every thread has ended. Signal actions are shared, and `SignalAction` updates every thread; masks are per thread. A signal sent to the process goes to the main thread while it runs, otherwise to the first live thread, and `SIGKILL` goes to all of them. `/proc/<pid>/status` adds `Threads` and sums CPU time over the threads.

Threads wait for each other through futexes (`src/kernel/futex.cpp`): `FutexWait` checks the word and joins the waiters under one lock that `FutexWake` also takes, so a wake that follows a change of the word is never missed. Waiters are keyed by process and address, so threads of different processes never meet. The C library builds mutexes, condition variables and `pthread_once` on them, and a detached thread's slot goes back on the next `ThreadCreate` after it ends.

Every thread has thread-local storage. The ELF loader records the program's `PT_TLS` template (at most 16 KiB, inside a load segment; the user linker scripts emit it from `.tdata` and `.tbss`), and the kernel builds each thread's block at the top of its stack slot (`src/kernel/thread_local_storage.cpp`): the template's bytes, then zeros, with the thread's stack starting below. On x86-64 the block ends at the thread pointer, the `FS` base, whose first word points to itself; on AArch64 `TPIDR_EL0` points to a 16-byte control block that the block follows. The scheduler saves and loads the pointer on every switch (`src/kernel/arch/thread_pointer.h`), so `__thread` and constant-initialized `thread_local` variables need nothing from the C library. A reused stack slot is cleared first.

A per-process memory lock covers page faults, stack growth and the heap, since threads on different CPUs map pages at once. Pages unmapped from a process (a shrinking heap, a joined thread's stack) are freed only after `Memory::ShootDownUserMappings`, since other CPUs running the process may still hold their translations. On x86-64, where `invlpg` flushes one CPU, it sends an IPI to every other CPU whose active page-table root is the process's and waits for each to reload `CR3`, serving requests aimed at itself meanwhile so two shootdowns never wait on each other; a CPU records its new root before loading it, so one that switches in meanwhile already sees the changed tables. AArch64 needs nothing more: `tlbi vaae1is` is broadcast to every CPU and `dsb ish` waits for them. A detached thread's stack stays mapped for the next thread in its slot. The C library is thread-safe where POSIX requires it (see [posix.md](posix.md)): `errno` is per thread, `malloc` and each stdio stream are locked, and `thread_local` destructors run when their thread ends.

## Multiple CPUs

QEMU runs with four CPUs (`-smp 4`) in tests and interactive runs. Once the boot CPU's timer runs, `src/kernel/smp.cpp` uses Limine's MP response to start each secondary CPU (up to `Smp::MaximumCpus`, 8) and logs `SMP: N CPUs online with IPIs and timers`. Each secondary CPU installs its CPU-local state, loads its own exception state (on x86-64 a GDT, TSS, and IST stacks with the shared IDT; on AArch64 `VBAR_EL1`), enables its local interrupt controller and timer, prints `CPU N online`, and waits for interrupts. Each secondary CPU then enters the scheduler on its own idle task. Before logging the summary, the boot CPU sends each CPU an IPI, waits for it to be handled, and checks that each CPU's timer is ticking. The normal-boot smoke test requires every CPU's online line and the summary.

IPIs and per-CPU timers use `Arch::Interrupts::SetIpiHandler`/`SendIpi` and `Time::StartSecondaryCpuTimer`. On AArch64 the kernel runs on `SP_EL1` (`SPSel=1`) on every CPU, so exception frames land on the current task's kernel stack and `SP_EL0` holds only user stack pointers; Limine enters on `SP_EL0`, and exception setup moves the stack. Each CPU enables its banked GICv2 CPU interface, SGIs, and PPIs; IPIs are SGI 1, addressed by the GIC target mask each CPU reads at startup, and each core runs its own Generic Timer. On x86-64, `src/kernel/arch/x86_64/local_apic.cpp` maps the local APIC through `Memory::MapDevice` and enables it on every CPU. IPIs use vector 48 and the APIC timer vector 49; the boot CPU calibrates the APIC timer against 10 PIT ticks. The legacy PIC and PIT still deliver device interrupts and global time to the boot CPU through LINT0 (virtual-wire mode); the I/O APIC is not used yet. Only the boot CPU advances `Time::TickCount()` and polls the UART; every CPU's tick drives the scheduler (sleeper wakeups, preemption, and leaving its idle task).

### Scheduling on every CPU

All CPUs share one run queue under the scheduler lock, so any CPU runs any ready task: user programs, the shell, and the boot thread may move between CPUs at each switch. Making a task ready sends an IPI to an idle CPU, if there is one, so it leaves `hlt`/`wfi` at once instead of at its next tick. The lock is held across each context switch and released by the task that switches in, so no CPU can resume a task before its registers are saved. The framebuffer console takes a display lock, and page-table edits take a page-table lock (heap, then page tables, then the page allocator). TLB shootdown is not needed yet: kernel mappings are only added after the secondary CPUs start, and switching address spaces flushes user translations (x86-64 `CR3` reload, AArch64 `tlbi vmalle1`). Unmapping a live kernel page or sharing an address space between CPUs will need one.

Run `SMP_TEST=ON ./build.sh --arch x86_64 test` or `--arch aarch64` to check that three tasks run at the same time on three CPUs that a lock-protected counter they share comes out exact, and that the scheduler counts each of those CPUs as busy. `SCHEDULER_TEST=ON` runs now also check the scheduler success line.

`src/kernel/cpu.cpp` gives each CPU an index that `Cpu::CurrentIndex()` reads from a CPU register: the `GS` base on x86-64 and `TPIDR_EL1` on AArch64. On x86-64 the entry stubs run `SWAPGS` when an interrupt or syscall comes from ring 3, and again before `IRETQ` back to ring 3, so user code never sees the kernel's `GS` base. Per-CPU data lives in arrays indexed by `Cpu::CurrentIndex()`: the scheduler's current and idle tasks, each CPU's active page-table root, and the x86-64 TSS. `Serial::Write` takes a lock so lines from different CPUs do not interleave; panic and fatal-exception reports force it open first.

## Networking

Every QEMU run attaches a virtio-net device on QEMU's user-mode network (`-netdev user`). The kernel boots without an IPv4 address, and init's `respawn dhcp` service leases `10.0.2.15/24` via `10.0.2.2` from slirp, with the name server `10.0.2.3`; the gateway also reaches the host's loopback. For IPv6, slirp's router `fe80::2` advertises `fec0::/64` and the name server `fec0::3`, so the guest is `fe80::5054:ff:fe12:3456` and `fec0::5054:ff:fe12:3456`, and `fec0::2` is the host.

- **Discovery:** shared with the other virtio drivers. `src/kernel/arch/x86_64/pci.cpp` scans PCI configuration space for a transitional device (I/O-port BAR 0, the firmware's legacy interrupt line), and `src/kernel/arch/aarch64/virtio_mmio.cpp` walks the device tree for a `virtio,mmio` node with the right device ID and its GIC interrupt. The virtio-blk and keyboard drivers use the same helpers.
- **Driver:** `src/kernel/network/device.cpp` keeps 64 receive and 64 transmit buffers of 2 KiB in two split virtqueues (`src/kernel/virtio/virtqueue.cpp`, in the legacy layout both transports accept, physically contiguous from `Memory::AllocateContiguousPageFrames`). `src/kernel/arch/<arch>/virtio_net.cpp` is the transport: legacy virtio over I/O ports on x86-64 (10-byte header), virtio 1.0 MMIO on AArch64 (12-byte header). Only the receive queue interrupts; it wakes a high-priority kernel task that hands each frame to `src/kernel/network/interface.cpp`. Transmit buffers are reclaimed on the next send, and a send with none free drops the frame. On x86-64, virtio-blk now asks for no interrupts, because the two devices may share a PIC line.
- **Ethernet and ARP:** frames are padded to 60 bytes, and only frames for our MAC, broadcast or IPv6 multicast (`33:33:*`) are taken. ARP (`src/kernel/network/arp.cpp`) answers requests for our address. Both IP versions share a 16-entry neighbor cache (`neighbor_cache.cpp`) whose entries live five minutes. `Network::Resolve` sends up to three ARP requests or neighbor solicitations, a second apart.
- **IPv4 and ICMP:** `src/kernel/network/ip.cpp` takes packets for our address, `255.255.255.255` and the subnet broadcast (and, before DHCP has set an address, any packet from the wire for our MAC, as a DHCP server may send to the address it offers), and drops fragments and packets with a bad header checksum (`ipv4.cpp`, `checksum.cpp`). It answers echo requests to our own address straight back to the sender's MAC, so the receive task never waits on ARP. Outgoing packets go to the destination when it is on the local network and to the gateway otherwise, after resolving the next hop, so a send can wait up to three seconds. Our own address and `127.0.0.0/8` loop back inside the kernel without reaching the device. Addresses above the IP layer are `Network::IpAddress`, which holds either version. `SendIp` takes the offset of a transport checksum and fills it in over the pseudo-header of the source address it picks.
- **IPv6 and neighbor discovery:** `src/kernel/network/neighbor_discovery.cpp` gives the interface a link-local address from the MAC (modified EUI-64), sends a router solicitation, and takes a global address from the first advertised `/64` prefix (SLAAC); boot waits up to a second for the advertisement and logs the result. New addresses are optimistic (RFC 4429): usable at once while duplicate address detection runs for a second, and dropped if another host probes for or claims the address meanwhile. It answers solicitations for our addresses and learns neighbors from advertisements. `ip.cpp` takes packets for our addresses, all-nodes and our solicited-node groups, skips extension headers, drops fragments, and checks each ICMPv6 checksum over its pseudo-header (`ipv6.cpp`, `icmpv6.cpp`). It picks the link-local source for link-local and multicast destinations and the global one otherwise, sends on-link destinations (link-local or in our `/64`) directly and the rest through the advertised router, answers echo requests straight to the sender's MAC, and loops `::1` and our own addresses back. Neighbor discovery messages go out and must arrive with hop limit 255. Router and prefix lifetimes are not tracked beyond the router's. A recursive DNS server option (RFC 8106) in the advertisement becomes a name server for its lifetime.
- **UDP:** `udp.cpp` holds the header format. `ip.cpp` hands datagrams for our addresses (and IPv4 broadcasts) to the socket bound to their port, after checking the checksum over the pseudo-header; IPv4 datagrams may carry none, IPv6 ones must. Outgoing checksums are filled in by `SendIp`, as 0xFFFF when they come out 0. A valid datagram to one of our addresses that no socket takes gets ICMP destination unreachable, port unreachable (type 3, code 3), quoting as much of the packet as fits in 576 bytes, or ICMPv6 type 1, code 4, within 1280 bytes. Like echo replies, errors go straight back to the sender's MAC. None is sent for broadcasts, multicast or a source that is not one host, and a token bucket shared by both versions allows bursts of 10, then one per 100 ms. An incoming port unreachable error for a UDP datagram we sent is matched by the ports and addresses it quotes; a socket connected to that peer fails its next `send` or `recv` with `ECONNREFUSED` and reports `POLLERR` until then. Sockets that are not connected ignore it, as on Linux without `IP_RECVERR`.
- **Settings:** `src/kernel/network/settings.cpp` serves the `NetworkSettings` syscall: the MAC, the IPv4 address, prefix length and gateway (0.0.0.0 until set, changed under a lock in `interface.cpp`, logged as `Network: IPv4 <address>/<prefix> via <gateway>`), the IPv6 addresses and router, and the name servers (`name_servers.cpp`): up to 3 set by DHCP or by hand, then the advertised one unless it is listed already.
- **Link:** `Network::SetLink` in `interface.cpp`, behind `net down` and `net up`, cuts the interface off without touching loopback. Down, it logs `Network: link down`, resets the device (status 0, which stops its DMA and interrupts; `Device::Stop`), clears the IPv4 configuration, the IPv6 addresses, router and advertised name server (`ForgetIpv6`) and the neighbor cache, and closes every TCP connection whose peer is not `127.0.0.0/8` or `::1` with `SyscallErrorNetworkDown`, sending nothing (`Sockets::DropExternalConnections`). From then on `SendIp` refuses every destination that is not local with `SendStatus::NetworkDown`, which sockets report as `ENETDOWN`, a TCP `connect` without a source address fails the same way, `SendFrame` and address resolution refuse at once, and the receive task drops anything still in flight; a mutex the receive task holds around each frame keeps a frame that arrived before the change from being handled after it. Up, `Device::Restart` negotiates again and posts fresh, emptied queues, IPv6 starts over with a router solicitation (boot waits the same way, up to a second, for the advertisement), and it logs `Network: link up`; IPv4 stays unset until DHCP or `net ipv4` sets it, and is refused while the link is down.
- **TCP:** `tcp.cpp` holds the segment format and `tcp_connection.cpp` the state machine (RFC 9293), which knows no addresses, locks or clock: the socket layer feeds it segments and the time in milliseconds and pulls the segments it should send. Each connection has a send ring and a receive ring on the heap, which start empty and double from 4 KiB up to 256 KiB as data needs them; `TcpConnection::Release` frees them with the socket. Both SYNs offer the window scale option (RFC 7323), ours with a shift of 3, and windows are scaled only when both carry it; a SYN's own window never is. The advertised window is the receive ring's free space at its largest size, at most 64 KiB unscaled; its right edge moves on only once the space has grown by a segment, which keeps duplicate ACKs' windows equal, as the peer's count requires, and a scaled window that holds its edge rounds up to the next 8-byte step rather than pulling the edge back. A byte the ring cannot hold, past the largest ring after such rounding or when memory runs out, is dropped for the peer to send again. It announces an MSS of 1460 (IPv4) or 1440 (IPv6). Retransmission follows RFC 6298 (RTT samples per Karn's rule, an RTO from 200 ms to 60 s, doubling per timeout) with go-back-N after a timeout; a SYN gives up after 5 retries and data after 8, the latter sending a reset. Congestion control is RFC 5681's slow start and congestion avoidance from an initial window of 10 segments, with NewReno fast recovery (RFC 6582): three duplicate ACKs send the first unacknowledged segment again and halve the window, each further duplicate lets another segment out, and a partial acknowledgment sends the next missing segment at once, until everything sent before recovery began is acknowledged. Duplicates of data sent before a timeout start no recovery. A closed peer window is probed one byte at a time, for as long as the peer answers. An out-of-order segment within the window is written straight to its place in the receive ring, past the data in order, and up to 4 such ranges are tracked (with no room, the highest goes); when the gap before them fills, the ranges merge and the acknowledgment jumps past them. A FIN ahead of missing data is taken once the data arrives. Every segment with data is acknowledged at once, each out-of-order one with its own duplicate ACK, and there is no Nagle algorithm or delayed ACK. Only a reset at exactly the next sequence number counts, and a SYN or a reset elsewhere in the window gets a challenge ACK (RFC 5961). TIME-WAIT lasts 60 s, and a closed socket's FIN-WAIT-2 gives up after 60 s. `ip.cpp` checks each segment's checksum and hands it to `Sockets::DeliverTcp`, which finds the connection by both endpoints, opens one on a listener for a SYN, or queues a reset (RFC 9293 3.10.7.1).
- **The TCP task:** sending can wait on address resolution, which only the receive task completes, so all TCP output goes through a high-priority task in `socket.cpp`. The receive task and system calls update connections under the socket lock and wake it; it runs the timers, sends whatever every connection has due, and sleeps until the next timer. A closed TCP socket stays behind, without a descriptor, until its connection finishes (FIN, retransmissions and TIME-WAIT); the task then frees it. Closing a socket with unread data resets the connection instead (RFC 2525 2.17), and closing a listener resets the connections nobody accepted.
- **Sockets:** a socket is a descriptor (`Files::Kind::Socket`) over `src/kernel/network/socket.cpp`, holding one IP version. There are TCP sockets (`socket(AF_INET or AF_INET6, SOCK_STREAM, 0)`), UDP sockets (`SOCK_DGRAM`) and ICMP datagram sockets, like Linux's and macOS's unprivileged ping sockets. `read` and `write` work on every socket, as `recv` and `send` without flags. A UDP or TCP socket binds a port on first use, from 49152 up when none was chosen, and one bound to a specific address receives only what is sent to it. A connected UDP socket sends to its peer and receives only from it. TCP binds as if `SO_REUSEADDR` were set: only a socket that is bound but not connected, such as a listener, holds a port against other binds, so a server can restart while its old connections are in TIME-WAIT. Ports are separate per IP version and per protocol, and any process may bind any port, 68 for DHCP included. For a ping socket, a program sends an echo request (`socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP)` or `socket(AF_INET6, SOCK_DGRAM, IPPROTO_ICMPV6)`), the kernel sets its identifier to the socket's port and computes its checksum, and echo replies with that identifier queue on the socket. Each socket queues up to 8 datagrams of up to 1480 bytes, dropping more, and `recvfrom` returns the payload without the IP or UDP header. `SO_RCVTIMEO` is the only option.

`ping [-6] [-c count] <host>` sends a 56-byte echo request every second until `count` replies or Ctrl+C, printing each reply's round-trip time in milliseconds and then the totals. The host is an address, where a colon or `-6` means IPv6, or a name, which takes its first address from `getaddrinfo` (only IPv6 ones with `-6`). It exits with 0 when any reply came, 1 when none did, and 2 on a usage error.

`nc [-4|-6] <host> <port>` connects to a TCP port, and `nc -l [-4|-6] <port>` waits for one connection on a port of every local address (IPv4 unless `-6`). It then copies standard input to the connection and the connection to standard output with `poll`, sends FIN at the end of the input, and exits once the peer has finished and the input has ended, or only the peer when the input is the console. `nc -u [-4|-6] <host> <port>` uses a connected UDP socket instead: each read of the input goes out as one datagram, replies are printed, and after the end of the input it waits until no reply has come for a second. A port unreachable error from the peer ends it with `nc: <host> <port>: Connection refused`.

`fetch [-4|-6] [-o file] <url>` gets an `http://` URL with HTTP/1.1 (`src/user/fetch.cpp`, messages in `src/user/http_message.cpp`) and writes the body to standard output, or to `file`, which is created only once a successful response arrives, and then prints `fetch: saved <n> bytes to <file>`. A URL without a scheme means `http://`, an IPv6 literal goes in brackets (`http://[fec0::2]:8000/`), and the host may be a name. Each request asks the server to close the connection after its response, and the body ends at its `Content-Length`, after its last chunk (`Transfer-Encoding: chunked`; other codings are refused), or when the connection closes. Interim 1xx responses are skipped, redirects (301, 302, 303, 307, 308) are followed up to 5 times with relative `Location`s resolved per RFC 3986, and any other status outside 2xx is printed as `fetch: <status> <reason>` with exit status 1. Receives time out after 30 s. There is no HTTPS, no other method than GET, no keep-alive and no compression. `nc` and `fetch` share `src/user/tcp_client.cpp`, whose errors go to standard error.

`ntp [-4|-6] [-n] [-p port] [server]` (`src/user/ntp.cpp`, packets in `src/user/ntp_message.cpp`) asks an NTP server, `pool.ntp.org` unless one is named, for the time with an SNTP version 4 request (RFC 4330) on UDP port 123 or `port`, and prints `ntp: <address> offset <+s.mmm> s, delay <s.mmm> s, stratum <n>`. It then steps the clock by the offset with `clock_settime` and prints `ntp: clock set to <date> UTC`; with `-n` it only measures. Each of the server's addresses gets 3 requests, 2 s apart, and only a reply that echoes the request's transmit timestamp counts. A kiss-o'-death (stratum 0) prints its code, such as `RATE`, and an unsynchronized server (leap indicator 3 or stratum 16) is skipped, in both cases for the next address. Timestamps after the NTP era wraps in 2036 are read as era 1, so they cover 1970 to 2104. The clock is stepped, never slewed, and init does not run `ntp` at boot, since QEMU's RTC already follows the host.

`httpd [-4|-6] [-p port] [directory]` (`src/user/httpd.cpp`) serves the files under `directory`, the current one by default, with HTTP/1.1 on port 80 or `port`, listening over IPv4 and IPv6 unless `-4` or `-6` picks one. It answers GET and HEAD (other methods get 501) with `Content-Length`, `Content-Type` from the file's extension (`application/octet-stream` otherwise), `Date` and `Server`. A directory named without its trailing `/` redirects (301) to the name with it; with the `/`, its `index.html` is sent, or else an HTML listing sorted by name. Targets are percent-decoded and their dot segments removed before they are joined to the directory, so no request reaches above it; the absolute form (`GET http://host/path`) is accepted too. Connections stay open by the request's version and `Connection` header, pipelined requests are answered in order, and a connection closes after 10 s without a request, after a malformed one (400, 414, 431 or 505, which an HTTP/1.1 request without exactly one `Host` gets too), or after any request with a body, which is not read. Each connection runs on its own thread, at most 8 at once; more wait in the listen backlog. Every request is logged on standard output as `<client> <method> <target> <status> <body bytes>`, so `httpd /tmp/www > /tmp/httpd.log &` keeps the log in a file. Request heads, paths, link encoding and content types are parsed in `src/user/http_message.cpp`. There is no HTTPS, no request bodies, no ranges, no conditional requests and no `Last-Modified`, since files have no modification time.

`echod [-4|-6] [-p port]` (`src/user/echod.cpp`) sends back every byte its clients send, on port 7 (the echo service) or `port`, over IPv4 and IPv6 unless `-4` or `-6` picks one. One thread serves up to 16 clients at once: its listeners and connections are non-blocking, `poll` says which can go on, `accept4` takes connections until `EAGAIN`, and each client's 4 KiB buffer is read into only while it has room and sent from as the connection takes it, so a client that never reads stalls only itself. It logs `<client> connected, <n> open` and `<client> closed after <bytes> bytes, <n> open` on standard output.

`dhcp` (`src/user/dhcp.cpp`, messages in `src/user/dhcp_message.cpp`) broadcasts a discover from port 68, takes the first offer, requests it, and sets the IPv4 address, prefix, gateway and name servers from the acknowledgement. It pads its messages to 548 bytes, since slirp ignores shorter ones, waits a second for each answer and doubles the wait after each failed round, up to 64 s, saying after four rounds that no server answers. It then keeps running to hold the lease (timing in `src/user/dhcp_lease.cpp`, counted from when the request was sent): at T1, half the lease unless the server gives option 58, it unicasts a request naming only its address to the server; at T2, seven eighths unless option 59, it broadcasts it to any server; retries come after half the time left until T2 or the end, at least 60 s apart. Each acknowledgement configures the network again and prints `dhcp: renewed ...`; a NAK, or a lease that runs out, drops the IPv4 address and starts over with a discover. A missing or infinite lease is never renewed. Its waits look at the link and the kernel's IPv4 address each second, and a change counts as a request to renew: once `net down` (or `net ipv4`) removed the address, it prints `dhcp: the address is gone; leasing again` and starts over with a discover, and `net up` restarts discovery without waiting. Sends that fail with `ENETDOWN` are not reported, and discovery keeps its backoff while the link is down. `dhcp -r` sends SIGUSR1 to every other process named `dhcp`, which renews at once, or restarts discovery without waiting; a second client cannot start, since port 68 is taken. slirp's leases last a day. `net` prints the settings (`mac`, `link up` or `link down`, `ipv4`, `ipv6` and `dns` lines); `net dns <address>[#port]...` replaces the configured name servers, `net ipv4 <address>/<prefix> [gateway]` or `net ipv4 none` sets IPv4 by hand, and `net down` and `net up` take the link down and back up (see Link above), after which the running `dhcp` leases IPv4 again at once. `host [-4|-6] <name>` prints a name's addresses as `<name> has [IPv6 ]address <address>`, and `host <address>` its name as `<address> has name <name>`, from `getnameinfo` with `NI_NAMEREQD`.

Names resolve in the C library (`getaddrinfo` and `getnameinfo`, see [posix.md](posix.md)): it asks the name servers in order over UDP for A and AAAA records, with a 2-second timeout and one round of retries, and answers names in `/etc/hosts` and then `localhost` itself. `/etc/hosts` ships in the initramfs (`initramfs/etc/hosts`) with `localhost` over both versions, `ip6-localhost` and `ip6-loopback` for `::1`, and `featheros` for `127.0.1.1`. `nameserver` lines in `/etc/resolv.conf` (`address[#port]`, up to 3) replace the kernel's name servers, and `options timeout:n attempts:n` change the wait and the rounds; the shipped file has only the default options, so the kernel's list is used. Both files can be edited until the next boot, for example `echo nameserver 10.0.2.3 > /etc/resolv.conf`.

`NETWORK_TEST=ON ./build.sh --arch <arch> test` resolves the gateway twice before DHCP, from 0.0.0.0, the second time from the cache, and expects slirp's `52:55:0a:00:02:02`; then it resolves `fec0::2` through neighbor discovery, which slirp answers as `52:56:00:00:00:02`. It then runs a shell session against a DNS server the test harness starts on the host's loopback, on one port for IPv4 and IPv6: `net` must show the DHCP lease and both name servers, `host` resolves `localhost` and `ip6-localhost` and `ping` reaches `FeatherOS.` (`127.0.1.1`) and `ip6-loopback` from `/etc/hosts`, `host` names `127.0.1.1` and `::1` from the same file, `host` resolves a CNAME and a missing name through `nameserver 10.0.2.2#<port>` written to `/etc/resolv.conf`, and `host -4 ip6-localhost`, which `/etc/hosts` lists only for IPv6, goes on to that server and fails, `host` names `10.0.2.2` and `fec0::2` from the server's PTR records and fails for `10.0.2.99`, which has none, and `ping` reaches the gateway by name. `host -4 big.featheros.test` gets 40 A records, too many for a datagram: the server answers over UDP with only the question and the truncation bit, so the resolver asks again over TCP on the same port and `host` prints the first 8. A second file names a closed port first, then `fec0::2#<port>`, with `options timeout:1 attempts:1`, so `host -6` waits out one second before the IPv6 server answers. A last file has only options, so `host -6` and `ping -6` use the kernel's list, set with `net dns fec0::2#<port>`, and `host -6 big.featheros.test` takes its 40 AAAA records over TCP the same way. The session's first line waits for the DHCP client's lease, which init starts beside the shell, and its last ones ask the client to renew with `dhcp -r`, wait for slirp's acknowledgement (`dhcp: renewed`), and check that `net` shows the DHCP name server again. The harness checks that queries arrived over both versions, over UDP and over TCP. For TCP it also starts an echo server on the host's loopback that answers in upper case, and forwards a host port to the guest's port 8080 (`hostfwd`; QEMU cannot forward IPv6). `nc` reaches the echo server at `10.0.2.2` and, by name, at `fec0::2`, gets `Connection refused` from a closed port, sends a datagram over each version with `-u` to the echo server's UDP port, which answers in upper case too, gets `Connection refused` from ICMP and ICMPv6 port unreachable errors for UDP port 9 on `127.0.0.1` and `::1`, serves the harness's client through the forwarded port, talks to a second `nc -l` over `127.0.0.1` and `::1`, and streams `/system/vi` through the echo server, whose byte count must come back unchanged. A second echo server streams it again over each version through a relay in the harness: QEMU never loses or reorders a packet, so `filter-redirector` objects pass every frame of the user-mode network through the relay (`LossyRelay`), which drops the 5th and 7th new data segments each way on that server's connections and swaps the 12th and 13th. The byte counts must match, and the harness checks that each version and direction lost two segments and had one reordered. Then `echod` runs in the background with its log in a file: a first `nc` over `127.0.0.1` holds its connection open for 3 s while a second over `::1` is echoed, and the log must show both open at once. Five copies of `/system/libctest`, appended to `/tmp/b` (about 2 MB), then go through `echod` over `127.0.0.1` and `::1`, where both ends scale their windows, and the byte counts must match. ## Wall Clock

The kernel reads UTC wall-clock time from the platform real-time clock with one-second resolution: the CMOS RTC on x86-64 (`src/kernel/arch/x86_64/rtc.cpp`, BCD or binary and 12- or 24-hour formats, century register `0x32`, with reads serialized by a lock because the index/data port pair is shared by all CPUs) and the PL031 at its fixed QEMU `virt` address on AArch64 (`src/kernel/arch/aarch64/rtc.cpp`). QEMU initializes both from the host clock in UTC. Startup logs the time as `Wall clock: YYYY-MM-DD HH:MM:SS UTC`. Once the timer runs, the kernel's wall clock (`src/kernel/time/wall_clock.cpp`) reads the RTC once and advances by timer ticks in nanoseconds, so it has 10 ms resolution; programs read it with the `ReadClock` syscall and set it with `SetClock`, which `ntp` uses. A set time lasts until the next boot: the RTC itself is never written. `src/user/calendar.h` converts between UNIX seconds and UTC dates for both the kernel and user programs; there is no time-zone support.

## Shell And Console Input

After startup, the kernel spawns `init` (`src/user/init.cpp`), and restarts it if it ever exits. init reads `/system/init.conf` from the initramfs (`initramfs/init.conf`), with one service per line as `<policy> <command line>` and `#` comments. `once` services run to completion in order before the others start. `respawn` services run in the background. A `console` service, at most one, holds the console as a session leader. init starts them with `posix_spawn`: the console service with `POSIX_SPAWN_SETSID`, and respawned services with `POSIX_SPAWN_SETPGROUP`, which FeatherOS treats as starting in the background. init polls its services with `waitpid(..., WNOHANG)`, reports each exit as `init: <command> exited with status N` (or `ended by signal N` after a fault or Ctrl+C), and restarts the service; one that exits five times within ten seconds is disabled instead. An `env NAME=value` line adds a variable to the environment every service starts with; the default configuration sets `HOME=/home` and `PATH=/system:/bin`, and the shell passes its environment on to every program it runs. Malformed lines are reported and skipped, and a missing `/system/init.conf` falls back to `console shell`. The default configuration prints a startup line and runs the shell as the console service, so the shell's `exit` built-in returns to a fresh shell.

`shutdown` and `reboot` are shell built-ins that call `reboot(RB_POWER_OFF)` and `reboot(RB_AUTOBOOT)`, over the `Shutdown` syscall (`src/kernel/power.cpp`). In order, the kernel:

1. Marks every process except the caller and its ancestors for termination, and waits up to two seconds for them to exit.
2. Takes the filesystem lock for good, so no file operation is half done.
3. Sends a virtio-blk flush when the device supports it.
4. Parks the other CPUs with an IPI.
5. Asks the firmware to act.

AArch64 uses PSCI `SYSTEM_OFF` or `SYSTEM_RESET`, through `hvc` or `smc` as the device tree's `/psci` node says (`src/kernel/arch/aarch64/power.cpp`). x86-64 reads ACPI from Limine's RSDP through the device-memory window, checking table checksums. It powers off with the FADT's PM1 control ports and the `\_S5` sleep types, found by scanning the DSDT's AML instead of interpreting it, and enables ACPI mode first if needed. It restarts through the FADT reset register when present, then the keyboard controller, then a triple fault (`src/kernel/arch/x86_64/power.cpp`). If the firmware does nothing, the kernel panics.

The shell shows a prompt with its working directory, such as `/home> `, and edits the line itself in raw mode (`src/user/line_editor.h`, over `RawTerminal` in `src/user/raw_terminal.h`), falling back to `featheros_read_line` when standard input is not the console. The keys are listed in the [readme](../readme.md#keyboard-shortcuts) and in the shell's `help`. History keeps the last 32 lines, skipping blank lines and repeats, and Down returns to the line being typed. The editor redraws a line that wraps with relative cursor moves, using the console width from `ioctl(TIOCGWINSZ)`, so a serial terminal narrower than the screen can show long lines oddly. Its reads set `FEATHEROS_WAKE_ON_OUTPUT` (`TerminalWakeOnOutput`): when a service, a background job or the kernel log prints while the shell waits at its prompt, the read returns empty once the output paused for a tenth of a second (console writes wake it, kernel log lines are noticed within a second), the kernel moves the cursor to a new row if needed, and the shell draws the prompt and line again there, as after the DHCP client's lease message at boot. The console returns to canonical input before each command runs. It splits each line into words by the kernel's rules (`SplitCommandLine` in `src/user/command_line.h`, where double quotes group words), runs the first word with `posix_spawnp`, which looks a name up in the directories of `PATH` (`/system:/bin`) and runs a word with a `/` as that file, waits for it with `waitpid`, and prints `exit status N` for nonzero statuses. A missing name reports `Unknown command: <name>`, and other failures `shell: <word>: <error>`, such as `Exec format error` for a file that is not a program. Programs copied to the disk run like those in `/system`: `cp /system/echo /bin/say` makes `say` a command. A process's name, in `ps` and `/proc`, is the last part of its path. A command's input and output can be redirected with `< file`, `> file`, `>> file`, `2> file` and `2>&1`, as its own word or joined to the file name (`>out.txt`); the shell opens the files and passes them as `posix_spawn` file actions, and a quoted `">"` is an ordinary word. Built-ins cannot be redirected. `a | b` runs up to four commands with each one's output feeding the next one's input, as in other shells, and redirections still apply to each command; the last command's status is reported. Each command line, pipeline or not, runs as one process group led by its first command, so any of them may read the console and Ctrl+C stops them all. A trailing `&` (`sleep 9 &`, or `sleep 9&`) starts it in the background instead: the shell prints `[n] pid` and returns to the prompt, and the job cannot read the console. Before each prompt the shell reaps finished jobs and reports `[n] Done`, `[n] Exit N` or `[n] Signal N` with the command. `jobs` lists running jobs, `fg [n]` gives job `n` (or the newest) the console and waits for it, and `wait` waits for every job. At most 8 jobs run at once. `help` lists the bundled programs:

- `calc [expression]` evaluates an expression such as `4 + 66 - (3 / 4)` with `+ - * /`, parentheses, unary signs, and decimals, using exact fractions (`src/user/calculator.h`) and printing up to six decimal places. Without an expression it reads one per line at a `calc> ` prompt until `exit` or `quit`.
- `date` prints the current UTC time, such as `2026-10-19 03:07:39 UTC`.
- `echo <words...>` prints its arguments.
- `fanout <n>` starts `n` (1–16) `echo` children before waiting for any of them.
- `primes <workers> [limit]` demonstrates multicore scheduling. It counts the primes below `limit` (default 10,000,000) with 1–16 worker processes, each testing every n-th odd number by trial division. Each worker reports its count and the CPUs it ran on in one line through a pipe of its own, and the parent prints one line per worker plus the total time. Compare `primes 1` with `primes 4` and watch the status bar's busy-CPU count.
- `threads <threads> [limit]` counts primes like `primes`, but with 1–15 threads of one process (`pthread_create`, `src/user/prime_count.cpp` shared with `primes`), and shows the CPUs each thread ran on. The shell test runs `threads 4 100000` and `threads 15 20000`, which must find the same counts as `primes`.
- `sleep <seconds>` sleeps, with fractions such as `0.5`, and checks that the wall clock advanced by the whole seconds requested.
- `fptest [workers]` starts 8 workers by default, more than there are CPUs. Each fills every vector register with its own pattern, spins while the others run, and checks the pattern is intact; it fails if context switches lose floating-point state.
- `hardening` runs 67 checks, including `Shutdown` from an ordinary program: syscalls with kernel or invalid pointers (including a `Spawn` environment) and oversized arguments, a kernel-half ELF (`badelf`, generated by `tools/create_bad_elf.py`) from `/system` and from a copy in `/tmp`, `Spawn` of a missing file, a directory, a device, a text file, a truncated program, a file over 1 MiB and a path too long once resolved, children that execute the heap, touch a heap page after shrinking the heap below it (also from a thread spinning on another CPU, which fails without a TLB shootdown), write their code, read kernel memory, or use an invalid syscall (each must be terminated), a thread starting at a kernel address or joining into kernel memory, the per-process child limit, and zero-length reads, writes, `poll` and datagrams from address 0, which must succeed.
- `aslr` prints where its image, stack, arguments page (`featheros_arguments_page`), and heap (`sbrk(0)`) landed; the shell test runs it twice and requires different addresses.
- `memtest [overflow|exhaust]` grows its stack and heap and checks them, recurses into the stack guard page to show that the kernel terminates it, or grows its heap until the page limit refuses more, shrinks it back to its start, and checks that it grows as far again (the shell test runs it twice and requires the same count).
- `upper` reads one line as the foreground process and prints it in upper case; when its input is a file, it converts all of it.
- `cd [dir]` and `pwd` are shell built-ins; `cd` alone returns to `/home`, and the prompt shows the working directory, such as `/home/docs> `.
- `env` prints the environment, one `NAME=value` per line.
- `ls [directory]` lists a directory (the working directory by default) with file sizes, marking subdirectories with `/`. `mkdir <dir>` and `rmdir <dir>` create and remove (empty) directories.
- `cat [file]` prints a file, or its input without one; the console shows tabs as spaces and drops other control characters. `write [-a] <file> <text...>` writes the words and a newline to a file, replacing it or, with `-a`, appending. `rm <file>` deletes a file. Names are relative to the working directory, and `cat` also tries `/system` for a missing relative name, so `cat hello.txt` works anywhere.
- Text tools, which read their files or, without any, their input, so they work in pipelines (shared logic in `src/user/text_tools.cpp`):
  - `cp <source> <target>` copies a file, into a directory under the source's name; `touch <file>...` creates empty files (there are no file times to change).
  - `mv <source> <target>` renames or moves a file or directory the same way, with the `Rename` syscall. On the disk this rewrites only directory entries (a moved directory's `..` follows it), and a new case for the same name works. Between the disk and `/tmp` it copies a file and removes the original; directories cannot move between them.
  - `head [-n lines] [file...]` and `tail [-n lines] [file]` print the first or last 10 (or `-n`) lines.
  - `wc [-lwc] [file...]` counts lines, words and bytes, with a total for several files.
  - `grep [-ivnc] <text> [file...]` prints the lines containing plain text: `-i` ignores case, `-v` inverts, `-n` numbers, `-c` counts. It exits with 0 on a match, 1 without, 2 on an error.
  - `sort [-rnu] [file...]` sorts lines by bytes, or with `-n` by their leading numbers; `-r` reverses and `-u` drops repeats.
- `filetest` runs 33 checks of the file syscalls: creation, multi-cluster writes, reads, seeks, appends, the one-writer and no-removing-open-files rules, bad pointers and flags, the read-only initramfs, the 16-descriptor limit, and a child that exits with a file still open.
- `uptime` prints the time since boot as `H:MM:SS`.
- `ping [-6] [-c count] <host>` sends ICMP echo requests to an IPv4 or IPv6 address or a name (see Networking).
- `dhcp` leases an IPv4 address and holds it (`dhcp -r` renews now), `net` shows or changes the network settings and takes the link down or up, and `host [-4|-6] <name>` or `host <address>` looks up a name or an address (see Networking).
- `kill [-signal] <pid>...` sends `SIGTERM`, or the named or numbered signal, to each process, or to a group as `-group`; `kill -l` lists the signals. In the shell, `kill %n` names job `n`.
- `keys` switches the console to raw input and prints the name of each key pressed (`up`, `ctrl-a`, `page-down`, `escape`, …), Ctrl+C included, until `q`. It decodes keys with `src/user/key_decoder.h`, which also reads the SS3 and `ESC [ 1 ~` forms some terminals send, and waits a tenth of a second to tell a lone Escape from the start of a sequence.
- `vi [file]` is a small vi (`src/user/vi_editor.cpp`). It draws on the alternate screen, so the shell's screen comes back unchanged when it exits; its keys are in the [readme](../readme.md#vi). It keeps the whole file in memory, scrolls long lines sideways instead of wrapping them, shows tabs as 8 columns and other control bytes as `?`, and writes the file with a final newline. Undo keeps up to 100 whole-buffer snapshots or 512 KiB of them, dropping the oldest. Not supported: visual mode, named registers, `.`, macros, `f`/`t`, operators with motions (`dw`, `cw`), regular expressions in searches, and more than one file.
- `clear` clears the screen below the status bar with `ESC [ H ESC [ 2 J`, as Ctrl+L does at the prompt.
- `ps` lists every process from `/proc`: ID, parent, group, state, the CPU it last ran on, its CPU time, and its name.
- `top [-n count] [-d milliseconds]` samples `/proc` every second (or `-d`, at least 100 ms) and prints the processes busiest first, with `%CPU` of one CPU and the whole system's use, On the console, without `-n`, it takes the alternate screen and redraws the table in place, cut to the screen's height, until `q`, Escape or Ctrl+C (raw input, waiting for keys between refreshes); with `-n`, or when its output is not the console, it prints `count` tables one after another.

Every program except the boot self-test prints its usage and purpose for `<name> -h` or `<name> --help` (`HelpRequested` in `src/user/command_line.h`), and the shell's `help` points to this. To add a program, create `src/user/<name>.cpp` with a `main(argc, argv)` and add `<name>:<name>` to `FEATHEROS_PROGRAMS` in `src/user/CMakeLists.txt`. `FEATHEROS_START_PROGRAMS` is for programs that define `_start(const ProgramArguments*)` themselves and skip the C library's startup, which only `test_program` does. `filetest` and `hardening` still call `src/user/syscall.h` directly where they test the kernel's exact errors.

Interactive runs accept keys from the QEMU window on both architectures. x86-64 uses PS/2; AArch64 uses virtio-input on QEMU `virt`. The launching terminal's serial console also remains available. Program output appears on both serial and the framebuffer console.

Input reaches the console as one byte stream (`src/kernel/input/input.cpp`), in the form a VT100 terminal sends it. Serial bytes arrive as typed, with `\r\n` counted once. The keyboard drivers only turn scancodes into key codes (PS/2 set 1, including its `E0` keys, or virtio-input codes, which match for the main keys). `src/kernel/input/keyboard.cpp` then maps them for both architectures, with the US layout, Shift, Caps Lock and Ctrl:

| Key | Bytes |
| --- | --- |
| Enter, Backspace, Tab, Escape | `\r`, `0x7F`, `\t`, `ESC` |
| Ctrl+A to Ctrl+Z, Ctrl+[ \ ] | 1 to 26, 27 to 29 |
| Up, Down, Right, Left | `ESC [ A`, `B`, `C`, `D` |
| Home, End | `ESC [ H`, `ESC [ F` |
| Insert, Delete, Page Up, Page Down | `ESC [ 2 ~`, `3 ~`, `5 ~`, `6 ~` |
| Shift+Tab | `ESC [ Z` |

Ctrl+C (byte 3) goes to the console's interrupt handler first, in order with the bytes around it, and is queued only if the handler declines it. The console has terminal settings (`TerminalMode`, behind `tcgetattr` and `tcsetattr`), which start as canonical input with echo, signals, and Enter as `\n`:
- **Canonical:** `ReadLine` and console reads edit a line: the prompt and the typed line appear inline in the scrolling text with a block cursor, like a normal terminal. Printable ASCII is inserted, Backspace erases (also across a wrapped line), and Enter ends the line. Escape sequences are skipped, so the cursor keys do nothing there; programs that want them, like the shell, use raw input. Input is echoed to serial and the screen unless echo is off.
- **Raw** (canonical off): a read returns bytes as they arrive, without editing, once `minimum` bytes are there. `timeout`, in tenths of a second, limits the wait for the first byte when `minimum` is 0, and the wait between bytes otherwise; with both 0 a read returns at once. Echo, when on, prints what arrives.
- **Signals:** with them off, Ctrl+C arrives as byte 3 instead of sending `SIGINT`.

Only the foreground group may change the settings. The process that changed them owns them: when it exits, even after a fault or `SIGKILL`, the console returns to the defaults and the terminal to the main screen and normal video with the cursor shown, so a crashed full-screen program cannot leave the shell in raw mode.

The framebuffer's top row is a status bar. Its left side names the foreground program (`kernel` before the shell starts). Its right side shows busy CPUs over online CPUs, a network dot, then the UTC date and time as `Mon Oct 19 9:36:05 PM`. The dot is green while the link is up and an address has a way off the local network (IPv4 with a gateway, or a global IPv6 address with a router; `Network::HasRoute`), and red otherwise, including without a network device. Nothing probes whether that path reaches the internet. The status text marks the dot with byte 1 (green) or 2 (red), which `Term` draws as a filled circle. A CPU counts as busy when the scheduler's timer ticks found it running a task other than its idle task for at least half of the last second. A high-priority kernel task redraws the bar once a second and when the foreground program changes. Its clock is the kernel's wall clock, and setting the clock redraws the bar at once.

Below the bar, the console understands a VT100 subset, so programs can draw full screens (`src/kernel/framebuffer/term.cpp`). Row 1 of `CSI row;column H` is the first row below the bar, and moves stop at the screen's edges.

| Sequence | Effect |
| --- | --- |
| `CSI n A`, `B`, `C`, `D` | Cursor up, down, right, left by `n` (default 1) |
| `CSI n G`, `CSI n d` | Cursor to column `n`, to row `n` |
| `CSI row;column H` or `f` | Cursor to a position (default 1;1) |
| `CSI n J` | Erase below the cursor (0), above it (1), or the whole text area (2) |
| `CSI n K` | Erase to the end of the line (0), to its start (1), or the whole line (2) |
| `CSI 7 m`, `CSI 27 m`, `CSI 0 m` | Reverse video on, off, off |
| `CSI s`, `CSI u`, `ESC 7`, `ESC 8` | Save and restore the cursor |
| `CSI ?25 l`, `CSI ?25 h` | Hide and show the cursor |
| `CSI ?1049 h`, `CSI ?1049 l` | Switch to a blank alternate screen, and back to the main screen as it was, with its cursor |
| `\r`, `\b` | Column 0, one column left |

Other sequences are read and ignored. Serial output carries the same bytes, so a terminal emulator on the serial port follows them too. `ioctl(TIOCGWINSZ)` reports the text area's size.

`CALC_TEST=ON` checks a calculator expression, an unknown command, and a blank line; `SHELL_TEST=ON` checks init's startup line and its restart of the shell after `exit`, `filetest`, `cd` and `pwd` from `/home` with relative paths, `/`, and `/system`, `ls /dev`, a file written to `/tmp`, `/proc/self/status` and `/proc/meminfo`, `fptest 8`, `libctest` with a quoted argument and a console read, programs copied to `/bin` and `/tmp` with `cp` and run by `PATH`, by path and relative to the working directory (with `aslr` and `memtest exhaust` checking ASLR and the page limit for them, and `/proc/self/status` their name), a missing file, a text file and a directory run as commands, `env` with the variables from `init.conf`, `--help`/`-h`, Ctrl+C on a CPU-bound `primes`, a `sleep`, `upper` and `calc` waiting for input, and the shell prompt, plus `echo` arguments, foreground input in `upper`, the interactive `calc> ` prompt and its errors, `primes 4 100000` and `primes 16 20000` (the counts and one report per worker, through pipes), a nonzero exit status, the `uptime` format, and that `date` is within two minutes of the host clock. `INPUT_TEST=ON` runs the keyboard test through QEMU's `sendkey`, which exercises PS/2 on x86-64 and virtio-input on AArch64: Ctrl+C at the prompt, typing with Backspace and Enter, Left and Up editing a shell line, and then special keys in `keys` (`up`, `home`, `delete`, `esc`, `ctrl-a`, `shift-tab`). The shell test also edits lines over serial (Home, Right, Up, Ctrl+U, Ctrl+W, Delete, a lone Escape, `history`), runs `clear`, edits a file in `vi` and checks it with `upper`, quits an interactive `top` with `q`, and runs `keys` with every special key and Ctrl+C as a byte. Pass each with `./build.sh test --arch x86_64` or `--arch aarch64`.

To run only one architecture's panic check, use `PANIC_TEST=ON`; this intentionally panics during startup, and the smoke test passes only when it observes the expected panic record:

```sh

```

## AArch64 Target

The cross-toolchain builder installs under `~/.local` by default and does not need `sudo`. It adds `~/.local/bin` to `PATH` when building. Build the AArch64 cross-compiler, then select that target for each build action:

```sh
./toolchains/build_toolchain.sh --binutils --gcc --arch aarch64-elf
ARCH=aarch64 ./build.sh build
ARCH=aarch64 ./build.sh iso
QEMU_EFI=/path/to/AAVMF_CODE.fd ARCH=aarch64 ./build.sh test
```

The AArch64 ISO is UEFI-only and uses Limine's `BOOTAA64.EFI`. QEMU runs with the `virt` machine. Interactive runs let the guest restart and power off, so the shell's `reboot` boots again and `shutdown` closes QEMU; set `QEMU_NO_REBOOT=1` to make a reset exit QEMU instead, which helps catch a triple fault during boot. The window scales the guest's 1024×768 screen with its size (`-display cocoa,zoom-to-fit=on` on macOS, GTK elsewhere), since pixel for pixel it is small on a Retina display; resize the window or use View → Zoom To Fit. Set `QEMU_ZOOM=0` for the default display at its native size, as on a QEMU built without Cocoa or GTK. They copy serial output to the launching terminal and to `build/<arch>/serial.log` as it arrives, removing the screen-clearing control sequences the firmware and Limine send on every boot. The log covers the whole session, including the boots after a `reboot`, and each new run starts a fresh log. Set `QEMU_EFI` to an AArch64 UEFI firmware image if the script cannot find one in a common system location.

On macOS, the toolchain builder automatically selects Apple Clang, the active Xcode SDK, GNU89 host flags, and system zlib for Binutils. Build each stage separately:
