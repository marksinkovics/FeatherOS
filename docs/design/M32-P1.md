# M32 Part 1: `/dev/fb0` and present (design)

**Scope.** A program whose controlling terminal is a virtual console opens `/dev/fb0`, acquires that console's screen, and presents XRGB8888 rectangles from its own memory. While the console is acquired, its `Term` takes text into its cell grid but draws nothing: no text, no status bar. On release the console redraws whole. Release happens on `FB_RELEASE`, on the last close of the open file, and on exit or a kill. Key events (D8–D11) are Part 2. This part leaves a place for their queue and routing (§1.4).

**Done when:**
1. `./build.sh unit-test`;
2. `bash tools/quality.sh check`;
3. `tools/check.sh --arch both --modes "SHELL GRAPHICS"`;
4. the new matrix cases pass.

## 0. What exists and what this builds on

- **`Framebuffer`** (`src/kernel/framebuffer/framebuffer.{h,cpp}`) is one static instance in `kernel_runtime.cpp`, with a 1024x768 back buffer.
  - `packColor` converts `0x00RRGGBB` through the Limine masks. `draw(y, height)` copies rows to the hardware.
  - `kernel_runtime.cpp` only passes `terms` to `Console::Initialize`, so `Console` never sees the `Framebuffer`.
- **`console.cpp`.**
  - `Screen{index, term}` for each of 4 consoles.
  - `display_lock` is a `SpinLock`, and `SpinLockGuard` turns IRQs off. `shown_console` is guarded by it.
  - `Show` runs in IRQ context from `Input::SubmitKey` through `SetConsoleSwitch`.
  - The status task's `DrawStatus` calls `term->SetStatus` under `display_lock`.
- **`Term::Refresh`** returns early when `!m_shown`, and `SetShown(true)` does a `Redraw`.
  - `KLogger` prints to `terms[0]` without the lock, as today.
  - `Panic` writes only to serial, so "a panic draws as now" needs no change.
- **There is no `fork` or `exec`.** `Spawn` is the only way to create a process.
  - `Files::Inherit` copies the descriptors that are not close-on-exec.
  - `RunProcess` calls `Files::CloseAll` after `WaitForThreads` on every way out: exit, fault, terminating signal, SIGKILL.
- **User memory** is read through `UserByte`/`TranslateUserPage` and the direct map, so a bad address can never fault in the kernel.
  - `CopyFromUser` translates one byte at a time, which is far too slow for 3 MiB.
  - `TranslateUserPage` takes no lock.
- **`files.cpp` is host-tested; `console.cpp` and `process.cpp` are not.** `file_system_lock` is a sleeping `Sync::Mutex`.
- **libc `ioctl`** (`src/libc/ioctl.cpp`) only knows `TIOCGWINSZ`=1 and `TIOCSWINSZ`=2.
- **QEMU setup.** `ramfb` on AArch64 and the standard VGA on x86-64, both 1024x768 from `limine.conf` and both XRGB8888. So in QEMU the conversion takes the row-copy path. The BGRX, 24-bit and 565 paths are checked only by host tests.

### 1.3 Kernel

**`src/kernel/framebuffer/framebuffer.{h,cpp}`: conversion that can be tested on the host**

```cpp
struct PixelFormat { uint32_t bytes_per_pixel; uint8_t red_size, red_shift, green_size,
```

**`src/kernel/framebuffer/graphics_mode.{h,cpp}` (new, namespace `FeatherOS::GraphicsMode`)**

```cpp
struct Clipped { uint32_t screen_x, screen_y, width, height; uint64_t source_offset; };  // pixels
// 0 with width/height 0 when nothing is visible; SyscallErrorInvalidArgument per §3.

public:
    uint64_t Acquire(uint32_t console, const void* owner);  // 0 (also if already its own), Busy
```

**`src/kernel/files.{h,cpp}`**

```cpp

using FramebufferRelease = void (*)(const void* owner);
void SetFramebufferRelease(FramebufferRelease release);   // null in host tests unless set
// Takes a reference, so the open file outlives the syscall even if a thread closes the descriptor;
// owner is its identity. SyscallErrorBadDescriptor, or SyscallErrorNotTerminal for another kind.

void DropFramebuffer(const void* owner);                  // ReleaseLocked under file_system_lock
```

- `IsTerminalDevice` becomes `IsSpecialDevice` and includes `Framebuffer`.
- `OpenDeviceLocked` creates a `Kind::Framebuffer` `OpenFile` with `close_on_exec = true`. Any access mode is accepted.
- `Inherit` skips `Kind::Framebuffer` slots even if `F_SETFD` cleared the flag.
- `ReleaseLocked`: on the last reference of a `Framebuffer` file it calls the hook, then `Deallocate`.
- `Read` and `Write` give `EINVAL`, `Seek` gives `SyscallErrorNotSeekable`, `PollEvents` gives 0, and `StatDescriptor` reports a character device.

**`process.cpp` and `syscall.{h,cpp}`**

- `Handlers::device_control` and the dispatch of 73, as `resource_limit` was added for 72.
- `ReadSyscall` sends `Kind::Framebuffer` to `EINVAL`. Part 2 replaces this with event reads, following the Terminal branch.
- A new `CopyFromUserPaged(process, address, destination, size)` translates once per 4 KiB page and copies through the direct map. `UserPagesReadable` is the per-page check.
- `DeviceControlSyscall` keeps a scoped hold, so `DropFramebuffer` runs on every return:
  - **`GET_INFO`:** fills `{w, h, IndexOf(ControllingTerminal) + 1 or 0, 0}` and copies it out (`EFAULT`). Allowed before an acquire.
  - **`ACQUIRE`:**
    1. The argument must be 0.
    2. The controlling terminal must be a console (`ENOTTY`).
    3. `CheckBackgroundAccess(*process, terminal, SignalTerminalOutput)`, as `TerminalModeSyscall` does.
    4. `AcquireDisplay`.
  - **`PRESENT`:**
    1. Copy the request in.
    2. `Clip`.
    3. Check `Owns`.
    4. Check the pages of every visible row (`EFAULT`).
    5. Allocate a bounce row of `Config::Width * 4` B from the heap (`ENOMEM`).
    6. For each row: `CopyFromUserPaged` with no lock held, then `PresentRow`. `false` gives `EINVAL`, and a failed copy gives `EFAULT`.
    7. Free the bounce row on every path.
  - **`RELEASE`:** `ReleaseDisplay`.
- `RunProcess` needs no change: `CloseAll` already releases on exit.

### 1.4 Room for Part 2

- **The queue.** The per-owner event queue (64 × 8 B, the dropped count, a `Scheduler::WaitQueue`) goes next to `owners` in `GraphicsMode::Owners`, guarded by `display_lock`. It is IRQ-safe because the guard turns IRQs off.
- **Routing.** `Input::SubmitKey` calls a new hook, `Input::SetGraphicsKeys(bool (*)(uint16_t code, bool pressed))`, installed by `Console::Initialize` like `SetConsoleSwitch`. The hook returns true when the shown console is acquired.
- **Reads and poll.** These are added in `process.cpp` the way terminals are, so `files.cpp` keeps only the release hook.

## 2. Invariants

- **I1. One owner per console, one console per owner.** `owners` changes only under `display_lock`.
- **I2. Release happens exactly once.** **(mutation)**
  - Ownership ends only through `Owners::Release(owner)`. It is called by `FB_RELEASE` and by the hook on the last reference of a `Kind::Framebuffer` file, which covers the last of any `dup`s, the hold of a racing syscall, `CloseAll` at exit, kill and fault.
  - A second call finds nothing, returns `Count`, and redraws nothing.
  - An acquire runs while a hold keeps the file alive, so a racing close can never leave a dangling owner.
- **I3. Only one process ever refers to a framebuffer open file.** It is close-on-exec and never inherited. So "exec" in D6 means a spawned child never owns the screen, and the owner's exit is always a last close.
- **I4. No `Term` draws while its console is in graphics mode.** **(mutation)** This covers text, scrolling, the cursor and `SetStatus`. Entering graphics mode, and showing a console that is in it, blank the screen once.
- **I5. Leaving graphics mode repaints everything.** It sets `m_redraw_all`, so the next shown refresh repaints all cells, the status bar included.
- **I6. The back buffer is written by a present only under `display_lock`,** in the same critical section that checks that the caller owns the console and that the console is shown.
- **I7. A present never writes outside the back buffer and never reads outside the user rectangle.** **(mutation)**
  - `Clip` uses 64-bit arithmetic and limits; `presentRow` clips again against `m_width`/`m_height`.
  - It reads only `[pixels + 4·source_offset, …)` of the visible rows.
- **I8. User memory is read only through page translation, and never while holding `display_lock` or `file_system_lock`.**
  - Every visible page is checked before any pixel is written.
  - A page that disappears in the middle (another thread shrinking the heap) gives `EFAULT` and never a panic. The rows already drawn stay on screen.
- **I9. Lock order is `file_system_lock` → `display_lock`.**
  - `process_lock` (`CheckBackgroundAccess`) and `status_lock` are never held together with `display_lock` in the new code.
  - The IRQ path (`Show`) only takes `display_lock`.
- **I10. Conversion is correct.** `PackRow(f, p)` equals `PackColor(f, p)` byte for byte for every format `init` accepts. The row copy is used only for exact XRGB8888.
- **I11. The ABI is checked.** Struct sizes are fixed and asserted on both sides. Unknown requests, nonzero `flags`, and nonzero arguments where none is used give `EINVAL`.
- **I12. Switching consoles.**
  - Showing an acquired console blanks it, and only presents draw it.
  - Showing a text console redraws it whole.
  - Presents to a hidden console succeed and draw nothing.

## 3. Edge cases and errno

| Case | Result |
|---|---|
| `/dev/fb0` without a framebuffer | `ENOENT`, not listed |
| request 73 on a non-fb descriptor (tty, file, pipe) | `ENOTTY`; bad descriptor `EBADF` |
| unknown request on fb (e.g. `0x4699`) | `EINVAL` |
| `FB_GET_INFO` before acquire | succeeds; `console` 0 without a virtual console |
| `FB_GET_INFO`/`FB_PRESENT` with a bad struct pointer | `EFAULT` |
| `FB_PRESENT`/`FB_RELEASE` by a file that is not the owner | `EINVAL` |
| `FB_ACQUIRE` from a pty or with no controlling terminal | `ENOTTY` |
| `FB_ACQUIRE` with another open file the owner | `EBUSY` (same process or not) |
| `FB_ACQUIRE` again on the owning file | 0 |
| `FB_ACQUIRE` from a background group | `SIGTTOU`, then `EINTR`; allowed if `SIGTTOU` is ignored or blocked (as `tcsetattr`) |
| `width == 0` or `height == 0` | 0; nothing read, pixels may be null |
| `stride < width` (both sizes > 0) | `EINVAL` |
| stride, width or height > 16384; `flags != 0` | `EINVAL` |
| rectangle fully off the screen (any `int32` x/y) | 0; nothing read |
| partly off the screen, negative x/y included | visible part drawn, 0 |
| `pixels` + extent wraps, or a visible row is unmapped or kernel memory | `EFAULT` |
| console hidden | 0 after the page check; nothing drawn |
| `read`/`write` on fb | `EINVAL` (Part 1); `lseek` `ESPIPE` |
| bounce row allocation fails | `ENOMEM` |
| owner stopped by Ctrl+Z (Part 1 only) | the screen stays acquired until it exits; Part 2 (D11) stops queuing Ctrl+Z as a stop |

## 5. Tests

### Host (`tests/unit/kernel/framebuffer/framebuffer_tests.cpp`, `.../graphics_mode_tests.cpp` (new), `filesystem/virtual_files_tests.cpp`, `syscall/syscall_tests.cpp`)

- **T1. Conversion against hand-computed bytes.**
  - `0x00123456` in XRGB8888 is `56 34 12 00`.
  - In BGRX (red shift 0, blue shift 16) it is `12 34 56 00`.
  - In 24-bit RGB it is `56 34 12`.
  - In 565 it is `0x11AA`, stored as `AA 11`.
  - Then 256 seeded colors per format: `PackRow` equals `PackColor` equals what `drawPixel` leaves in the back buffer.
- **T2. `Clip`, table-driven.**
  - Each row of §3's size table.
  - x/y of ±2^31−1 with width 16384.
  - x = −10 with width 20 gives screen_x 0, width 10, source_offset 10.
  - y = 760 with height 100 gives height 8.
  - Fully off-screen gives 0×0.
  - `stride*(height−1)+width` at the limits does not overflow.
- **T3. `presentRow` clips again.** A back buffer filled with `0xA5` canaries. Rows at x = −5, x = 1020 with count 10, and y = height give no byte changed outside the clipped span (ASan).
- **T4. `Term` graphics mode.**
  - Print 200 lines, `SetStatus`, and the cursor: no pixel changes from the blanked screen.
  - `SetGraphics(false)` gives pixels equal to a reference `Term` that was fed the same input and never entered graphics mode, bar included. This extends "terminals sharing a framebuffer draw only while shown".
  - A hidden graphics `Term` blanks when shown.
- **T5. `Owners`.**
  - Acquire, acquire again with the same token (0), another token (Busy), the same token on another console (Busy).
  - `Release` returns the console once, then `Count`.
  - Four consoles work independently.
- **T6. Files.**
  - Without `SetFramebuffer` the open gives `ENOENT`. With it, `fb0` is listed.
  - Set a counting hook. `Duplicate`, close one: 0 calls. Close the other: 1 call.
  - `HoldFramebuffer`, then `Close`: 0 calls. `DropFramebuffer`: 1 call.
  - `Inherit` gives the child no fb slot even after `DescriptorFlags` clears close-on-exec.
  - `CloseAll` on a table holding two dups: 1 call.
  - `Read`/`Write` give `EINVAL`. `HoldFramebuffer` on a file gives `ENOTTY`. `StatDescriptor` reports a character device.
- **T7. Dispatch.** `DeviceControl(73, a, b, c)` reaches `device_control` with all three arguments.

### QEMU (step 1, the SHELL session on both architectures)

**T8. `fbtest` prints `fbtest: ok`, or the first failing check.** It runs the checks below in order. Its child modes are started through `posix_spawn` of `fbtest <mode>`; a pipe on fd 3 (a file action) reports what the child did.

1. **Open and info.** Open `/dev/fb0`. `F_GETFD` has `FD_CLOEXEC`. `GET_INFO` gives 1024×768, console 1.
2. **Before acquire.** `PRESENT` and `RELEASE` give `EINVAL`, `read` gives `EINVAL`, and `ioctl(0, FB_ACQUIRE)` gives `ENOTTY`.
3. **Two ways to `ENOTTY`.** A `POSIX_SPAWN_SETSID` child's acquire gives `ENOTTY`, and so does `script -q -c "fbtest pty" /tmp/fbpty.txt` (a part line), which prints `fbtest pty: ok`.
4. **Acquire and `EBUSY`.**
   - Acquire, then acquire again: 0.
   - A second open's acquire gives `EBUSY`.
   - A `busy` child's acquire gives `EBUSY`.
5. **Present errors.**
   - `pixels` = `(uint32_t*)8` and a kernel address give `EFAULT`.

   - x = −5000 gives 0.
   - (1000, 760, 100, 100) gives 0.
   - A full screen from `malloc` gives 0.
6. **Release on last close.**
   - `dup`, close the original, present on the dup: 0.
   - Close the dup, and the second open's acquire gives 0.

7. **Release on kill.** A `hold` child acquires and reports `h`; SIGKILL; `waitpid`; the parent's acquire gives 0, then release.
8. **Release on exit.** An `exit` child acquires and exits without releasing; the parent's acquire gives 0.
9. **Background.**
   - A `stop` child spawned with `POSIX_SPAWN_SETPGROUP | POSIX_SPAWN_BACKGROUND` is stopped by `SIGTTOU` (`WUNTRACED`), then killed.

### QEMU (step 2, `GRAPHICS_TEST=ON`, both architectures; the oracle is QEMU's `screendump`)

**T10. The pattern.**
- Eight 128-px bars over y < 384 in `FF0000 00FF00 0000FF FFFFFF FFFF00 00FFFF FF00FF 808080`.
- Below them, `0x00RRGG00` with R = x/4 and G = (y−384)/2, which is exact in 8 bits.
- Then present (−10, −10, 20, 20) in `654321` and (1000, 700, 100, 100) in `123456`.

The harness checks, in order:

1. **Pattern and no status bar.** About 1.5 s after `fbdemo: presented` (so the status task has ticked), screendump A:
   - each bar's center at y = 200;
   - (0,0) and (9,9) are `654321`, and (10,10) is `FF0000`;
   - (1023,767) and (1000,700) are `123456`, and (999,699) is the gradient value;
   - **(1011,24), the bar's last blank cell, is still `808080`, not white.**
2. **Text console shown.** `sendkey alt-f2`, then screendump B: (1011,24) is `FFFFFF` (tty2's bar) and the bar centers are not the pattern.
3. **Blank on return.** `alt-f1`, then screendump C: every sample point is `000000`, since the acquired console was blanked and nothing redrew it.
4. **Re-present.** Type `r` on serial and wait for the second `presented`. Screendump D equals A's samples.
5. **Text console back.** After `fbdemo: done` and the prompt, screendump E: (1011,24) is `FFFFFF`, (4,4) is `000000` (padding), and no bar center keeps its pattern color.

Each screendump is retried for up to 2 s until it matches, to allow for QEMU's display update lag.

## 6. Risks for the implementer

- **The hold/drop discipline (I2).** Every early return in `DeviceControlSyscall` must drop. Use a scoped guard, and make `DropFramebuffer` the only path that can free the file.
- **IRQ-off time.** `PresentRow` holds `display_lock` with IRQs off for one row: about 4 KiB converted and drawn. Do not move the whole-frame loop under the lock.
- **The `/dev` directory listing.** Shifting `ReadDirectory`'s indices for `fb0` is easy to get off by one; `ls /dev` in the SHELL part `files.py` may list it.
- **`screendump` on AArch64.** It reads ramfb's surface. Confirm it works with `-display none` before writing the checks. If it does not, add `-display none` alternatives in `QemuArguments` for this case only.

## Settled by the coordinator

1. **"Release on exec" (D6).** FeatherOS has no `exec`; `Spawn` is fork+exec in one call. `/dev/fb0` descriptors are always close-on-exec and never inherited (I3), so a spawned child never shares the screen and the owner's exit is always a last close.
2. **`FB_GET_INFO` before acquire (D4).** Allowed at any time, so a program can learn the size and its console first; only `FB_PRESENT`, `FB_RELEASE` and `read` give `EINVAL` before an acquire. `console` is the tty number 1–4, 0 for none. D4 in `M32.md` is amended to match.
