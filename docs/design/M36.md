# M36: shared memory and local sockets (design)

**Scope.** Two unrelated processes share memory and exchange bytes and descriptors: what a compositor and its clients need. Checked against the code on `main` at `8b9ba14`:

- **A process's memory** (`process.h`, `process.cpp`) is an image, a heap moved by `ExtendHeap`, thread stack slots that grow on faults, and an arguments page. There is no list of what is mapped: the page tables are the only record, with `mapped_page_count` against `page_limit` (16384 pages).
- **Page tables** (`memory/virtual_memory.h`, both `arch/*/virtual_memory.cpp`): `MapPage`, `UnmapUserPage`, `ProtectPage`, `TranslateUserPage` and `ShootDownUserMappings` exist on both architectures. `DestroyAddressSpace` frees **every** leaf frame it finds.
- **Frames** come from a bitmap (`memory/page_allocator.h`) with no reference counts.
- **Teardown.** `RunProcess` waits for the process's threads, then calls `Files::CloseAll`. The address space is destroyed later, in `Process::Wait`, when the parent reaps the process.
- **Syscalls copy user memory through the direct map:** `UserByte` translates an address with `TranslateUserPage` and returns a kernel pointer to the frame. An address that is not mapped yet fails the syscall; only signal frames map stack pages on demand.
- **Descriptors** (`files.h`, `files.cpp`): an `OpenFile` has a `Kind`, a reference count under `table_lock`, and one pointer per kind. `Spawn` gives a child the parent's descriptors that are not close-on-exec.
- **Sockets** (`network/socket.h`) are IPv4 and IPv6 only. The ABI's `SocketAddress` is a fixed 24-byte IP address, and `SocketMessage` has a buffer and an address, with no control data.
- **Syscalls take at most three arguments.**

This milestone adds, in order:
1. A list of mapped regions per process, and anonymous `mmap` and `munmap`.
2. Memory objects: a descriptor that names a fixed set of zeroed frames, which any number of processes can map.
3. Local (`AF_UNIX`) stream sockets on abstract names, with `socketpair`.
4. Passing descriptors over a local socket (`SCM_RIGHTS`).

Left out: `fork` and copy-on-write, file-backed mappings, `mprotect`, `mremap`, `MAP_FIXED`, executable mappings, growing or shrinking a memory object, sealing, socket files in the filesystems, datagram and sequenced-packet local sockets, credentials beyond the peer's process ID, and `readv`/`writev`. `FB_MAP` (the roadmap's Part D) is designed only if M39's measurements ask for it.

**Done when:**
1. `./build.sh unit-test` and `./build.sh unit-test-tsan` pass.
2. `bash tools/quality.sh check` passes.
3. `tools/check.sh --arch both --modes "IPC MEMORY SHELL NETWORK SMP"` passes.
4. `tools/check.sh --arch both --matrix` passes, including the new cases in Debug and one in Release.

## Decisions

**User, 2026-11-25:** kernel work first; every app is a separate process from the start (the plan's D1). The plan's D5 and D6 chose POSIX-style calls: `mmap`, a memory-object descriptor, `AF_UNIX` stream sockets and `SCM_RIGHTS`.

**Design:**

- **D1. Mappings are populated when they are made,** anonymous ones too. A syscall that is handed a fresh buffer must find its pages, and the kernel's user-copy code does not fault pages in. So `mmap` allocates and zeroes every page, or fails with `ENOMEM` and maps nothing. The fault handler does not change.
- **D2. The region list covers only the mapping window.** The image, heap, stacks and arguments keep their existing code untouched. Mappings live in their own address range, so the two cannot overlap.
- **D3. The kernel chooses every address.** The window starts at `0x0000200000000000` on both architectures, above the image window and below the stack windows. A process's first mapping starts at a random page offset inside it, and later ones take the lowest free range above that. A hint is ignored and `MAP_FIXED` is refused.
- **D4. A memory object is sized once.** `ftruncate` on an object of size 0 allocates and zeroes its frames; a later call with the same size succeeds and any other size is `EINVAL`. So frames never appear or vanish under a mapping, and there is no fault for touching a truncated page.
- **D5. An object's pages count against the process that sized it,** in a count of their own with the same limit as its ordinary pages, and are given back when the object is destroyed. A process that only maps an object is not charged, so the compositor can map every client's buffers. A system-wide cap of half the machine's frames bounds them all.
- **D6. A frame is never freed while a syscall is still copying through it.** This closes a small race that exists today: a thread that shrinks the heap, or ends a thread, frees frames after the TLB shootdown, while another thread's syscall may still hold a kernel pointer into them. `munmap` would make that race ordinary, so this milestone fixes it for all three paths (1.2).
- **D7. Object mappings are removed when the process's last thread has ended,** in `RunProcess` next to `Files::CloseAll`, not when the parent reaps it. A zombie must not keep shared frames alive, and `DestroyAddressSpace` must never see an object's frames.
- **D8. Local sockets are their own module and their own `Files::Kind`.** They share nothing with the IP stack except the syscall numbers, which dispatch on the descriptor's kind.
- **D9. Names are abstract:** a kernel table of byte strings, written from user space as a `sockaddr_un` whose path starts with a zero byte, as on Linux. A path that names a file is `EINVAL`. No filesystem gains socket nodes.
- **D10. `connect` completes at once.** It creates the connected pair and queues the server's end on the listener, so a client may write before the server accepts, as on Linux. A full backlog makes `connect` wait, or fail with `EAGAIN` when non-blocking.
- **D11. Descriptors travel with a byte position.** They are delivered by the read that takes the first byte of the message they were sent with, and a read stops before the next message that carries descriptors. A message that carries descriptors has at least one byte.
- **D12. At most 8 descriptors per message. A local socket or the framebuffer cannot be passed.** Refusing local sockets rules out reference cycles, so no collector is needed.
- **D13. No architecture code is expected.** Everything uses the page-table calls that exist. Step B2 checks two things on both backends before relying on them: a user mapping without `Execute` is not executable, and mapping into an empty entry needs no flush.

## ABI

Syscall numbers 76 to 83 were reserved by `docs/design/M35.md`.

| Number | Syscall | Arguments | Returns |
|---|---|---|---|
| 76 | `MemoryMap` | pointer to a `MemoryMapRequest` | the address |
| 77 | `MemoryUnmap` | address, length | 0 |
| 78 | `MemoryObjectCreate` | flags | a descriptor |
| 79 | `Truncate` | descriptor, length | 0 |
| 80 | `SocketPair` | family, type with flags, pointer to two descriptors | 0 |
| 81 | `SendMessage` | descriptor, pointer to a `SocketMessageHeader`, flags | bytes sent |
| 82 | `ReceiveMessage` | descriptor, pointer to a `SocketMessageHeader`, flags | bytes received |
| 83 | — | reserved | |

```cpp
struct MemoryMapRequest      // 32 bytes
{
    uint64_t length;
    uint32_t protection;     // MemoryProtectRead 1, MemoryProtectWrite 2
    uint32_t flags;          // MemoryMapShared 1, MemoryMapPrivate 2, MemoryMapAnonymous 0x20
    int32_t descriptor;      // -1 for an anonymous mapping
    uint32_t reserved;       // 0
    uint64_t offset;         // a multiple of the page size
};

struct LocalSocketAddress    // 112 bytes; the first two bytes are the family, as in SocketAddress
{
    uint16_t family;         // SocketFamilyLocal = 1
    uint16_t length;         // bytes of name used, 1 to 107
    char name[108];
};

struct SocketMessageHeader   // 32 bytes
{
    uint64_t buffer;
    uint64_t length;
    uint64_t descriptors;    // an array of int32_t, or 0
    uint32_t descriptor_count; // in: how many to send, or the array's capacity; out: how many stored
    uint32_t result_flags;   // out: SocketMessageControlTruncated
};
```

- Flags with Linux's values: `MemoryObjectCloseOnExec` 1, `SocketMessageControlTruncated` 8, `SocketMessageCloseOnExec` `0x40000000`.
- `MaximumPassedDescriptors` 8, `MaximumObjectPages` 65536 (256 MiB), `LocalSocketBufferSize` 65536.
- `SocketOptionPeerProcess` 3: the process ID of the peer, read only.
- `Bind`, `Connect`, `Accept` and `SocketName` read the family first, then the rest of the address by family.

## What makes this harder (existing code)

| Where | Assumption | Plan |
|---|---|---|
| `DestroyAddressSpace` | Every mapped user frame belongs to the process | Object regions are unmapped before it can run (D7, I3) |
| `FreeUnmappedFrames` | A shootdown is enough before freeing | A drain of in-flight user copies is added (D6, 1.2) |
| `UserByte` and the copy helpers | A translated pointer stays valid for the copy | The same drain |
| `process.cpp` | Already 4100 lines | New logic goes in `memory/` and `ipc/`; `process.cpp` gets only thin syscall handlers |
| `Files::OpenFile` | One raw pointer per kind | Two more kinds; pinning and installing an open file become part of the interface for descriptor passing |
| Socket syscalls | Every socket descriptor is an IP socket | Each handler looks at the kind first |
| `SocketAddress` | 24 bytes, IP only | A second address struct, chosen by the family field both start with |
| A zombie keeps its address space | Harmless, since all its frames are its own | Object mappings go at exit (D7) |

## 1. Design

### 1.1 Regions (`memory/regions.{h,cpp}`)

Pure code with no kernel services, so the host tests run it.

- `enum class RegionKind : uint8_t { Anonymous, Object }`.
- `struct Region { uint64_t start; uint64_t pages; PageFlags protection; RegionKind kind; Object* object; uint64_t object_page; }`.
- `class RegionList`: regions sorted by address, never overlapping, in an array that the caller grows (`Reserve(count)` allocates outside any spinlock; the list never allocates on its own). At most 256 regions per process.
  - `const Region* Find(uint64_t address) const`
  - `uint64_t FindFree(uint64_t base, uint64_t limit, uint64_t pages) const`: the lowest gap at or above `base`.
  - `bool Insert(const Region&)`: refuses an overlap or a full list.
  - `uint32_t Remove(uint64_t start, uint64_t pages, Region* removed, uint32_t capacity)`: takes the range out, splitting regions it cuts, and reports each removed piece. A split object region gives both remaining halves the right `object_page`.
  - `uint32_t Count() const`, `const Region& At(uint32_t) const`.
- `UserLayout` gains `map_base`: `MapWindowBase` plus a random page offset below `2^24` pages when the layout is random, `MapWindowBase` otherwise. The window ends at `MapWindowBase + 2^37`.
- `UserProgram` gains `Memory::RegionList regions GUARDED_BY(memory_lock)`.
- `/proc/<pid>/maps`: one line per range, `<start>-<end> <rw-> <kind>`, for the image, the heap, each used stack slot and each region. An object region ends with `object <pages>`.

### 1.2 The user-copy drain (D6)

- `UserProgram` gains `std::atomic<uint32_t> user_copies`.
- Every helper that turns a user address into a kernel pointer and then reads or writes through it brackets that use with `++user_copies` and `--user_copies`: `CopyFromUser`, `CopyToUser`, `CopyFromUserPaged`, `WriteProgramBytes`, `CopyToCurrentUser`, `CopyFromCurrentUser`, the futex word read, and any other caller of `UserByte` that step A2's first act finds by reading the file. A bracket spans at most one page's copy and never sleeps.
- `FreeUnmappedFrames`, after its shootdown, waits until `user_copies` is 0 before it frees anything, yielding between checks. The pages are already unmapped, so no new copy can find them; it only waits out copies that had started.
- The same function serves `ShrinkHeap`, `ReleaseStackSlot` and `munmap`, so all three are fixed together.

### 1.3 Anonymous mappings (`memory/user_mappings.{h,cpp}`)

Functions on a `UserProgram&`, returning syscall values.

- `uint64_t MapAnonymous(UserProgram&, uint64_t pages, PageFlags protection)`:
  1. Reserve list space and allocate the frames, zeroed, before taking `memory_lock`. Any failure frees them and returns `NoMemory`.
  2. Under the lock: check the page limit, find a free range, insert the region, map every page, add to `mapped_page_count`.
  3. A failed `MapPage` unmaps what was mapped, removes the region, frees the frames, and returns `NoMemory`.
- `uint64_t Unmap(UserProgram&, uint64_t address, uint64_t length)`:
  1. The address must be page-aligned and the whole range inside the window; else `InvalidArgument`. Length 0 is `InvalidArgument`. Pages in the range that are not mapped are skipped, as POSIX allows.
  2. Work goes in chunks of at most 4096 pages, so the frame array allocated before the lock is bounded.
  3. Under the lock: `Remove` the range; for each removed piece unmap its pages; collect anonymous frames; take the anonymous pages off `mapped_page_count`.
  4. After the lock: shootdown, drain (1.2), free the anonymous frames, and release one object reference per removed object piece.
- Protection must include `Read`; `Write` is optional; anything else is `InvalidArgument`. Mappings are never executable.
- `MemoryMap` validates the request: flags exactly `Private | Anonymous` with descriptor -1 and offset 0, or exactly `Shared` with an object descriptor; length 1 byte to the page limit, rounded up to pages.

### 1.4 Memory objects (`memory/memory_object.{h,cpp}`)

- `struct Object` (opaque): a reference count, a size in pages, an array of frame addresses from the kernel heap, the process that was charged, and a `sized` flag. One global spinlock guards the counts and the system total.
- `Object* CreateObject()`: one reference, size 0.
- `uint64_t SizeObject(Object*, uint64_t pages, ProcessId owner)` (D4, D5): allocates the frame array and the zeroed frames outside the lock; then, under it, checks the system cap, charges the owner through a hook `Process` registers, and publishes the frames with `sized`. Any failure frees everything and leaves the object at size 0.
- `void RetainObject(Object*)`, `void ReleaseObject(Object*)`: the last release frees the frames and the array and gives the charge back, if the owner still exists.
- `uint64_t ObjectPages(const Object*)`, `uint64_t ObjectFrame(const Object*, uint64_t page)`: valid for any holder of a reference once `sized` is set; the frames never change after that.
- `Files`: `Kind::Memory`; `CreateMemoryObject(table, flags)`, `FindMemoryObject(table, descriptor, Object**)` (which retains for the caller), `Truncate(table, descriptor, length)`. The last close releases the descriptor's reference. `StatDescriptor` reports a regular file's type with the size in bytes. `Read`, `Write` and `Seek` on it are `InvalidArgument`.
- `MapObject(UserProgram&, Object*, uint64_t first_page, uint64_t pages, PageFlags)` in `user_mappings`: the object must be sized and the range inside it. It retains the object, then, under the lock, inserts the region and maps its frames; a failure unmaps, removes and releases.
- `ReleaseMappings(UserProgram&)` (D7): called from `RunProcess` after `WaitForThreads`. It removes every object region as `Unmap` does. Anonymous frames stay for `DestroyAddressSpace`, as the heap's do.
- `/proc/<pid>/status` gains `ObjectPages`; `/proc/meminfo` gains `Shared`.

### 1.5 Local sockets (`ipc/local_socket.{h,cpp}`, namespace `FeatherOS::LocalSockets`)

- **Pure parts, host-tested:**
  - `ByteQueue`: a 64 KiB ring of bytes plus up to 32 attachment records, each a byte position and up to 8 opaque file pointers. `Write`, `Read` (which applies D11) and `TakeAttachments`.
  - `NameTable`: abstract names to listeners; a name is taken at `Bind` and freed when its socket closes.
- **Endpoints.** A connection is two endpoints, each with a receive queue; either may close first. A listener has a backlog of at most 16 endpoints.
- **Calls,** each returning a syscall value and taking the `InterruptCheck` and non-blocking flag that pipes take:
  - `Create`, `CreatePair`, `Close`
  - `Bind(Endpoint*, name, length)`: `AddressInUse` for a taken name.
  - `Listen`, `Accept`, `Connect` (D10): `ConnectionRefused` when nothing listens on the name.
  - `Send(Endpoint*, buffer, length, files, file_count, ...)`: waits for room as a pipe does; `BrokenPipe` once the peer has closed or shut down reading.
  - `Receive(Endpoint*, buffer, capacity, files, file_capacity, *file_count, ...)`: waits for data; 0 at the end of the stream.
  - `Shutdown`, `Name`, `PeerProcess`, `PollEvents`.
- **Waiting and waking** follow `pipe.cpp`: a spinlock, the scheduler's wait lists and `Poll::Notify`.
- **Lock order:** the local-socket lock is a leaf. Pinned files are released, and `Poll::Notify` is called, only after it is dropped.
- **Hang-up:** when one end closes, the other reads what is queued, then 0; its writes fail with `BrokenPipe` and raise `SIGPIPE` unless asked not to; `poll` reports `PollHangUp`. Closing a listener closes the endpoints still in its backlog.
- **`Files`:** `Kind::LocalSocket`; `CreateLocalSocket`, `AddLocalSocket`, `FindLocalSocket`. `Read` and `Write` on the descriptor are `Receive` and `Send` without files. The socket syscalls in `process.cpp` look at the descriptor's kind and call one module or the other.

### 1.6 Descriptor passing

- `Files` exports three calls for it:
  - `uint64_t Pin(Table*, uint64_t descriptor, OpenFile** file)`: adds a reference; refuses `Kind::LocalSocket` and `Kind::Framebuffer` (D12).
  - `void Unpin(OpenFile*)`: drops it, closing the file if it was the last.
  - `uint64_t Install(Table*, OpenFile*, uint64_t flags)`: a new descriptor for a pinned file, taking over the reference.
- **Send:** validate the header; pin every descriptor (unpinning all on any failure); hand them to `Send` with the bytes. If the bytes go in several pieces because the buffer is full, the files travel with the first piece.
- **Receive:** `Receive` returns bytes and files together. Each file is installed in the receiver's table. If the caller's array is too small or the table is full, the files that do not fit are unpinned and `result_flags` gets `SocketMessageControlTruncated`.
- A queue that is destroyed with attachments still in it unpins them.

### 1.7 libc

- `<sys/mman.h>`: `mmap`, `munmap`, `memfd_create`, `PROT_READ`, `PROT_WRITE`, `MAP_SHARED`, `MAP_PRIVATE`, `MAP_ANONYMOUS`, `MAP_FAILED`, `MFD_CLOEXEC`. `mmap` ignores its address hint.
- `<unistd.h>`: `ftruncate`, for memory objects only; other descriptors give `EINVAL`.
- `<sys/un.h>`: `struct sockaddr_un`. libc turns it into a `LocalSocketAddress` and back.
- `<sys/socket.h>`: `AF_UNIX`, `AF_LOCAL`, `socketpair`, `sendmsg`, `recvmsg`, `struct msghdr`, `struct cmsghdr` with the `CMSG_*` macros, `SCM_RIGHTS`, `MSG_CTRUNC`, `MSG_CMSG_CLOEXEC`, `SO_PEERCRED` with `struct ucred` (user and group 0).
- `<sys/uio.h>`: `struct iovec`. `sendmsg` sends several buffers in order, with the descriptors on the first that is not empty; `recvmsg` fills the first buffer.
- Step A3, optional: `malloc` takes blocks of 128 KiB and more from `mmap` and gives them back with `munmap`.

## 3. Invariants

**Frames**
- **I1.** A frame has exactly one owner: a process's page tables, or one memory object. `DestroyAddressSpace` frees only the first kind. **Riskiest.**
- **I2.** An object's frames are freed only when its reference count reaches 0, and that happens only after every mapping of it has been unmapped and shot down.
- **I3.** By the time a process's address space is destroyed, it holds no object mapping. `ReleaseMappings` runs when the last thread has ended; a process that never ran has none.
- **I4.** No frame is freed while a syscall copy that translated its address is still in flight (D6).
- **I5.** A frame is zero when it first becomes visible to a process, through an anonymous mapping or a newly sized object.

**Regions**
- **I6.** The region list and the page tables agree inside the window: a page is mapped there if and only if a region covers it. They change together under `memory_lock`.
- **I7.** Regions never overlap each other, and the window never overlaps the image, the heap or a stack slot.
- **I8.** A failed `mmap` leaves no mapping, no region, no charge and no reference behind.

**Objects**
- **I9.** An object's size and frames never change once it is sized.
- **I10.** Each object region holds exactly one reference; splitting a region adds one, removing a piece drops one.
- **I11.** The charge for an object is taken once, from one process, and given back exactly once or not at all (if that process is gone).

**Local sockets**
- **I12.** Bytes arrive in the order sent, none lost or repeated, and a reader never receives bytes from both sides of a descriptor-carrying message's start in one call (D11).
- **I13.** A pinned file is installed in a table or unpinned, exactly once, whatever happens: delivery, truncation, a full table, a closed endpoint, or the receiver's exit. **Riskiest** of the socket work.
- **I14.** No file can reach a queue it holds open: local sockets are refused by `Pin`.
- **I15.** The local-socket lock is never held across a call into `Files`, the scheduler's blocking waits, or `Poll::Notify`.
- **I16.** A name maps to at most one listener, and is free again once that socket is closed.

## 4. Edge cases

| Case | Result |
|---|---|
| `mmap` length 0, or above the page limit | `EINVAL`; `ENOMEM` |
| `mmap` with `PROT_EXEC`, `PROT_NONE`, `MAP_FIXED`, or both or neither of `MAP_SHARED` and `MAP_PRIVATE` | `EINVAL` |
| `mmap` of a file, terminal, pipe or socket descriptor | `ENODEV` |
| `mmap(MAP_SHARED)` of an object not yet sized, or with offset plus length past its end | `EINVAL` |
| `mmap` with a hint address | The hint is ignored |
| The window or the region list is full | `ENOMEM` |
| `munmap` with an unaligned address, length 0, or a range outside the window | `EINVAL` |
| `munmap` over a hole, or over nothing mapped | 0; mapped pages in the range go, the rest is skipped |
| `munmap` of the middle of a region | The region splits in two |
| `ftruncate` to 0 on a new object | 0; it stays unsized |
| `ftruncate` a second time with a different size | `EINVAL` |
| `ftruncate` above 256 MiB, above the owner's limit, or above the system cap | `EFBIG`; `ENOMEM`; `ENOMEM` |
| `ftruncate` on anything but a memory object | `EINVAL` |
| `read`, `write` or `lseek` on a memory object | `EINVAL` |
| The sizing process exits while others map the object | The object lives on; its charge went with the process |
| A process is killed while it maps an object | Its mappings go when its last thread ends; other mappers are unaffected |
| A thread unmaps a buffer while another thread's `read` is filling it | The `read` finishes or fails with `EFAULT`; no freed frame is written (I4) |
| `bind` to a name in use | `EADDRINUSE` |
| `bind` or `connect` with a filesystem path, an empty name, or a name over 107 bytes | `EINVAL` |
| `connect` with no listener on the name | `ECONNREFUSED` |
| `connect` with the backlog full | Waits; `EAGAIN` when non-blocking |
| `write` after the peer closed | `EPIPE` and `SIGPIPE`, or only `EPIPE` with `MSG_NOSIGNAL` |
| `read` after the peer closed | The queued bytes, then 0 |
| Listener closed with connections in its backlog | Those clients see a hang-up |
| `sendmsg` with descriptors and no bytes | `EINVAL` |
| `sendmsg` with more than 8 descriptors, a bad one, a local socket or the framebuffer | `EINVAL`; `EBADF`; `EINVAL`; nothing is sent and nothing stays pinned |
| `recvmsg` with too small an array, or a full descriptor table | The ones that fit are installed, the rest are closed, `MSG_CTRUNC` is set |
| `recvmsg` with no room for descriptors at all (`read`) | The attached files are closed; the bytes are delivered |
| Receiver exits with descriptors still queued | They are closed with the queue |
| `sendmsg` or `recvmsg` on an IP socket | Works as `sendto` and `recvfrom`; descriptors are `EINVAL` |
| `socketpair` for a family other than local | `EOPNOTSUPP` |

## 6. Tests

**Unit (host),** under `tests/unit/kernel/`.

- **T1** `memory/regions_tests.cpp`: 30 000 random inserts, finds, removals and free-range searches against a per-page model; a removal that cuts a region in the middle, at each end, across several regions and across holes; the reported pieces and the `object_page` of each remaining half; a full list refuses (I7).
- **T2** procfs tests: the `maps` text for a program with a heap, two stacks, an anonymous and an object region.
- **T3** `memory/user_mappings_tests.cpp`, over a fake address space that records `MapPage` and `UnmapUserPage`: `MapAnonymous` maps exactly the region's pages, zeroed (I5, I6); the page limit; a `MapPage` failure at each page index leaves nothing behind (I8); `Unmap` whole, partial, over holes, in 4096-page chunks.
- **T4** `user_mappings_tests.cpp`: the drain: frames are not freed while `user_copies` is above 0, and are freed once it returns to 0 (I4).
- **T5** `user_mappings_tests.cpp`, `[concurrency]`, also under ThreadSanitizer: threads that map, touch and unmap while others run bracketed copies; the model and the fake page table agree at the end, and no freed frame is written.
- **T6** `memory/memory_object_tests.cpp`: create, size, retain, release; frames are zero; sizing twice with the same and a different size (I9); every limit; an allocation failure at each frame leaves size 0 and no charge (I11).
- **T7** `memory_object_tests.cpp`, `[concurrency]`: threads retain and release one object; it is freed exactly once, after the last release (I2).
- **T8** `user_mappings_tests.cpp`: `MapObject` in two fake address spaces maps the same frames; an offset mapping; a range past the end; `Unmap` of half an object region keeps one reference per remaining piece (I10); the object is freed only after both spaces unmap and the descriptor closes.
- **T9** `user_mappings_tests.cpp`: `ReleaseMappings` removes every object page, so a following destroy sees none (I1, I3); anonymous pages stay.
- **T10** `ipc/local_socket_tests.cpp`: `ByteQueue`: fill, wrap, partial reads, 200 000 random writes and reads against a model (I12).
- **T11** `local_socket_tests.cpp`: `NameTable`: bind, duplicate, release on close, the longest and an over-long name (I16).
- **T12** `local_socket_tests.cpp`: endpoints with fake waits: connect and accept; write before accept; the backlog limit; close on each side with data queued; shutdown each way; a closed listener's backlog; `PollEvents` in every state; the peer process.
- **T13** `local_socket_tests.cpp`: attachments: delivered with their first byte; a read stops before the next carrying message (I12); two carrying messages are never merged; a message split by a full buffer carries its files once.
- **T14** `local_socket_tests.cpp`: every way a pinned file ends: installed, truncated, table full, endpoint closed with it queued, queue destroyed. A counting fake proves one unpin or one install each (I13).
- **T15** files tests: `Pin` refuses local sockets and the framebuffer (I14); `Install` gives the lowest free descriptor with the flags asked for; a pinned file survives its sender's close.
- **T16** libc tests: `CMSG_*` arithmetic and the control buffer conversion both ways, including a short buffer.

**QEMU (both architectures).**

- **T17** `MEMORY` and SHELL, `memtest`: map 1 page, 1 MiB and 32 MiB; contents are zero; write and read back; unmap and map again; the limit gives `ENOMEM`; a touch after `munmap` ends the child with `SIGSEGV`; four threads map, fill, check and unmap 1000 times while four others `read` into buffers that are being unmapped; `MemFree` afterwards equals the value before.
- **T18** `IPC`, `shmtest share`: a parent sizes an 8 MiB object, maps it, starts a child that inherits the descriptor and maps it; both write patterns to their halves and each checks the other's; `/proc/<pid>/maps` and `ObjectPages` show it.
- **T19** `IPC`, `shmtest kill` and `shmtest cycle`: the child is killed while writing and the parent's mapping is intact; 100 rounds of create, size, map in two processes, unmap and close leave `MemFree` and `Shared` as before.
- **T20** `IPC`, `unixtest`: a server binds, listens and accepts four clients; each exchanges 1 MiB both ways with a checksum; a second bind to the name fails; connect with no listener is refused; `poll` wakes on data, on room and on hang-up; `SIGPIPE` and `MSG_NOSIGNAL`; `socketpair` between a parent and a child.
- **T21** `IPC`, `unixtest pass`: one process sizes an object, fills it, and passes it to an **unrelated** process (started by the shell, not by the sender) over a named socket; the receiver maps it and prints the checksum; then the sender exits and the receiver still reads the data. A pipe end and a disk file are passed and used the same way.
- **T22** `IPC`, `unixtest leak`: a sender passes 8 objects to a receiver that exits without receiving; another receives with an array of 2 and gets `MSG_CTRUNC`; `MemFree`, `Shared` and the open-file count return to their starting values.
- **T23** The `ipc` matrix cases, both architectures in Debug and x86-64 in Release, run T18 to T22 in one boot.

**Mutation checks** (each must fail the named test, then be reverted): `Remove` not adjusting `object_page` on a split (T1); `MapAnonymous` without zeroing (T3); freeing without the drain (T4); `SizeObject` charging after a failure (T6); `ReleaseObject` freeing at count 1 (T7); `ReleaseMappings` skipped (T9, T19); a read crossing a carrying message (T13); a truncated file not unpinned (T14, T22); `Pin` accepting a local socket (T15).
