# M30 Part 2: atomic rename onto an existing file (design)

**Scope.** Today a replacing rename is not atomic.

- `Files::Rename` (`src/kernel/files.cpp`) deletes an existing target with `VFS::Remove(to)`, a separate core call that may commit on its own, and only then calls `VFS::Rename`.
- `CoreDriver::Rename` refuses any existing target with `Exists`.
- So a crash between the two calls loses the target.

The core already replaces correctly. `Ext2Filesystem::RenameNode` (`src/fs/core/ext/namespace.cpp`) rewrites the target's directory record in place and releases the replaced inode last, all in one `Journalled` step. When that step is too big, `Rename` splits off only the inode's release through the orphan list. The kernel never reaches that path today.

This part:

- routes a replacing rename into one core `Rename` call;
- makes tmpfs replace in memory;
- lets a directory replace an empty directory (POSIX);
- keeps FAT16's order (not atomic) and documents it;
- adds crash tests that cut every write of a replacing rename on ext2, ext3 and ext4.

After it, on ext2, ext3 and ext4 the target name always exists after a crash and names either the old file or the new one. On ext3/ext4 that holds with no repair at all.

**Done when:** `./build.sh unit-test`, `bash tools/quality.sh check`, `tools/check.sh --arch both --modes "SHELL STORAGE"`, then `tools/check.sh --arch both --matrix`.

## Decisions (confirmed by the user, 2026-11-20)

- **D1. One core call.**
  - `Files::Rename` no longer calls `VFS::Remove` or `VFS::RemoveDirectory` on the target.
  - Every kind check is made in the kernel before anything changes (I6).
  - Then a single `VFS::Rename` → `Driver::Rename` → `Filesystem::Rename` does the whole replacement.
  - `CoreDriver::Rename` drops its `target && *target != *source → Exists` refusal.
- **D2. The ext core stays as it is,** checked by tests only. It already:
  - rewrites the record in place (`RewriteRecord`);
  - skips `ClearIndex` when replacing;
  - drops the source record;
  - fixes `..` and the link counts;
  - releases the replaced inode last (`DropLink`);
  - on ext3/ext4, does all of this in one `Journalled` step, or splits the release through the orphan list when it overflows (`ReleaseSplit`).

  A test that finds a fault fixes `namespace.cpp`.
- **D3. tmpfs replaces in memory.** `Tmpfs::Rename` accepts an existing `to` when:
  - it is the same node (nothing changes);
  - or both are non-directories;
  - or both are directories and the target is empty.

  Every check comes first. Only then does it free the target's data, mark the node unused, and rename the source. Nothing after the first change can fail.
- **D4. FAT16 keeps today's order, documented.** `Fat16Filesystem::Rename` removes the target's entry and chain, creates the new entry, then marks the old one deleted. A crash after the removal leaves the source and no target, never the reverse. The alternative order (new entry first) would leave two entries sharing one chain, which is worse for `fsck.fat`.
- **D5. A directory can replace an empty directory** (POSIX). A non-empty target gives `ENOTEMPTY`. Today this case gives `EEXIST`; `posix.md` changes.
- **D6. An open target stays `EBUSY`**, as `unlink` of an open file does, so no inode is released while a handle uses it. An open source also stays `EBUSY` on every filesystem. POSIX open-unlinked inodes are left for a later part, together with POSIX `unlink`.
- **D7. Errno after the checks.** A `VFS::Rename` failure returns `VFS::LastError()`, except that a missing parent of `to` gives `ENOENT`. The old fallback (`ExistsLocked(to)` → `EEXIST`/`EISDIR`) goes.
- **D8. ext2 without a journal:** after a crash the target is always old or new, possibly with a leaked inode or bitmap bits that `e2fsck -fy` repairs. Accepted, and documented beside FAT16's window.

## 0. Where "remove first" happens today

| Place | What it does |
|---|---|
| `src/kernel/files.cpp` `Rename` | a link target: `VFS::Remove(to)`. A tracked target with a different key: `FindUse` → `EBUSY`, then `VFS::Remove(to)`, then `VFS::Rename`. A directory onto a directory reaches the core, which answers `EEXIST`. |
| `src/kernel/filesystem/core_driver.cpp` `Rename` | an existing target → `Fail(Error::Exists)` |
| `src/kernel/filesystem/tmpfs.cpp` `Rename` | an existing `to` → false |
| `src/fs/core/fat/fat16.cpp` `Rename` | `RemoveEntry(existing)` before `CreateEntry` (stays, D4) |
| `src/fs/core/ext/namespace.cpp` `RenameNode` | already replaces in place (D2) |

`src/kernel/kernel_test.cpp` also calls `VFS::Rename`, and never depends on a refusal.

## 1. Files and signatures

**Kernel**

- **`src/kernel/files.cpp` `Rename(from, to)`.** In order:
  1. Walk both names, then the checks that exist today:
     - `.`/`..` → `EBUSY`;
     - `EROFS`;
     - a mount point → `EBUSY`;
     - `EXDEV`;
     - `IsWithin(to, from)` → `EINVAL` (0 when the paths are equal);
     - an open source → `EBUSY`.
  2. If `to` exists, the kind checks:
     - a directory onto a non-directory or link → `ENOTDIR`;
     - a non-directory onto a directory → `EISDIR`;
     - a directory onto a non-empty directory → `ENOTEMPTY` (`VFS::ReadDirectory(to, 0, …)` in a `HeapObject<DirectoryEntry>`);
     - a tracked target whose key differs from the source's → `EBUSY` (`FindUse`).
  3. `VFS::Rename(from, to)`.
  4. On failure: `ParentExistsLocked(to) ? VFS::LastError() : ENOENT`.
- **`core_driver.{h,cpp}` `CoreDriver::Rename`:** the `Exists` refusal goes.
- **`filesystem.h` `Driver::Rename` and `vfs.h` `VFS::Rename`:** the comment says they replace an existing `to` of the same kind (a directory only if empty) as one change.
- **`tmpfs.{h,cpp}` `Tmpfs::Rename`:** D3.

**Core (step 1: tests, plus fixes only where a test fails)**

## 2. Invariants

- **I1.** A replacing rename on any filesystem is exactly one `Driver::Rename` call; the kernel never removes the target itself. **Riskiest (kernel).**
- **I2. ext2 write order (no journal).**
  - The target's record is rewritten in place, one block write, before the source record is dropped.
  - The replaced inode's link count, deletion time, blocks and bitmap bit are written only after both.
  - So every prefix of the writes has the target name pointing to the old or the new inode, and that inode is still allocated.

  **Riskiest (core).**
- **I3. ext3/ext4: one transaction.**
  - Rewriting the target, dropping the source, `..` and the link counts all run in one `Journalled` step, with no commit between them.
  - Only the replaced inode's release may move to later transactions, and only after a commit that put it on the orphan list with 0 links.

  **Riskiest (core).**
- **I4.** A replacing rename never calls `ClearIndex`, so a hashed directory stays indexed.
- **I5. Counts after success:**
  - the replaced file has one link fewer, and is freed at 0;
  - a replaced directory is freed, and its parent loses one link;
  - a moved directory's `..` names its new parent, with the parents' counts adjusted;
  - the free inode count rises by one exactly when the last link went.
- **I6. A refused rename changes nothing.** Every refusal (`EISDIR`, `ENOTDIR`, `ENOTEMPTY`, `EINVAL`, `EBUSY`, `EXDEV`, `EROFS`, `ENOENT`) is decided before the first change. tmpfs frees the target only after every check. **Riskiest (tmpfs).**
- **I7.** An error after the checks is the driver's own (`EIO`, `ENOSPC`, …), never `EEXIST`.
- **I8.** A target with a tracked open handle → `EBUSY`. No inode or tmpfs node in use is ever released by a rename.
- **I9.** A name onto itself, or onto another hard link of the same inode, returns 0 and writes nothing.
- **I10.** FAT16: the target's entry is removed before the new entry is written. A crash leaves the source's name and data intact.
- **I11.** A tmpfs replacement returns the target's node and bytes: `UsedBytes` drops by its capacity, and the node can be created again.

## 3. Write order, and what a crash at each point leaves

**ext2 (write-through, `RenameNode`)**, for a file replacing a file. Every `e2fsck -fn` report below is on the `OnlyRoutineRepairs(…, renames=true)` list.

| # | Write | A crash after it leaves |
|---|---|---|
| 0 | (none) | target = old |
| 1 | only a directory moving to a new parent: the new parent's inode, links +1 | target = old; parent "ref count" |
| 2 | the target directory's block, with the record rewritten | target = **new**; the moving inode has two names with a count of 1; the old inode is unattached |
| 3 | the target directory's inode (times) | as 2 |
| 4 | the source directory's block (`DropRecord`), then its inode | target = new; the old inode is unattached |
| 5 | only a moving directory: its `..` block, then the old parent's links −1 | target = new |
| 6 | the moving inode's ctime | target = new |
| 7 | `DropLink`: the old inode's links −1; at 0, deletion time, `ReleaseContents`, `FreeInode` | target = new; bitmap differences between writes (leaked; `e2fsck -fy` frees them) |

**ext3/ext4.** Steps 1–7 go into the running transaction. On the device they are written in this order:

1. the journal blocks;
2. a flush, then the commit block;
3. a flush, then the checkpoint.

Before the commit block is durable, a replay gives the old state; from then on, the new one. In the split case, transaction A holds steps 2–6 and puts the old inode on the orphan list with 0 links, and later transactions free its blocks. A crash after A gives the new target, and recovery finishes the orphan.

**tmpfs.** Memory only, under `file_system_lock`: checks, then free the target, then repoint the source.

**FAT16 (unchanged).** In order:

1. Mark the target's entry `0xE5`: the source is present, the target missing.
2. `FreeChain`.
3. `CreateEntry`: both names exist, and the target has the new data.
4. `SetParent`.
5. `MarkDeleted` on the source.

## 4. Edge cases and errno (`Files::Rename`)

| Case | Result |
|---|---|
| A file onto an existing file, same or another directory | 0; the target holds the source's data; the source name is gone |
| A file onto a symbolic link | 0; `lstat(to)` is a regular file |
| A link onto a file | 0 |
| A file or link onto a directory | `EISDIR` |
| A directory onto a file or link | `ENOTDIR` |
| A directory onto an empty directory, across directories too | 0; `..` names the new parent |
| A directory onto a non-empty directory | `ENOTEMPTY` |
| `rename("a/b", "a")` | `ENOTEMPTY` |
| A directory into its own subtree | `EINVAL` |
| A name onto itself, or onto its own hard link | 0, nothing written |
| The target is open | `EBUSY`, target unchanged |
| The source is open | `EBUSY` |
| The target is a mount point, or `.`/`..` | `EBUSY` |
| A replaced empty directory is a working directory | 0 (working directories are paths, as with `rmdir`) |
| Writes fail while replacing | `EIO`. On ext3/4 the journal aborts and the target is the old one. On ext2, as in §3. |
| A big target overflows the transaction | the release is split off; 0 |
| Across filesystems / onto a read-only one | `EXDEV` / `EROFS` |

## 6. Tests

### Core (`src/fs/core/tests/`, `FEATHERDISK_EXT_IMAGES`)

The fixture is a base image prepared with the core, then unmounted cleanly:

- `/d/old.txt` (6000 B) and `/src.txt` (3000 B, another pattern);
- `/d/x.txt` and `/d/y.txt`;
- `/h1` with a hard link `/h2`;
- `/f.txt` and a symbolic link `/ln`;
- `/e2/` holding `child`, and an empty `/x/empty/`;
- `/big.bin` (about 400 KiB).

The scenario runs one change per `Sync`:

1. `Move("/src.txt", "/d/old.txt")`
2. `Move("/d/x.txt", "/d/y.txt")`
3. `Move("/f.txt", "/ln")`
4. `Move("/e2", "/x/empty")`
5. `Move("/h1", "/h2")` (no-op)
6. `Make("/n.txt", "n")` then `Move("/n.txt", "/big.bin")`

Old and new inode numbers come from `InodeOfPath` (debugfs) on the base image.

- **T1. Journalled, every write cut.** `ext3` and `ext4` at stride 1, `ext4-64bit` at stride 3, one `TEST_CASE` each. For each cut:
  1. `RunCrashed`, then `ReplayBothWays`.
  2. `RequireCommittedState` and `RequireLossyRecovery`.
  3. Every target's inode on the replayed image is old or new, never `nullopt`.

  Across all cuts, every target must be seen both old and new.
- **T2. ext2 without a journal, every write cut.** Variants `1k`, `ext4-nojournal` and `ext4-csum`, with `FailWritesAfter` and a snapshot (the pattern of `ext2_tree_tests.cpp`). For each cut:
  1. `RunE2fsck` passes `OnlyRoutineRepairs(report, true)`.
  2. On the unrepaired snapshot, every target's inode is old or new, and `debugfs cat` of a file target is the old or the new contents.
  3. `FixWithE2fsck` and `CheckClean` pass, and the target is still present.

  At some cut, a replaced inode must be left unattached (proof the window is reached).
- **T3. Hashed directory.** On `ext4-htree`, `Move("/r.txt", "/large/" + HashedName(1))`, cut at every write, then `ReplayBothWays`. Afterwards:
  - the index flag stays set;
  - `htree /large` shows "Indirect levels: 1";
  - the target is old or new.
- **T4. Split.** In the existing "rename onto" case of "a split change stopped after any write…", also require that `InodeOfPath("/big.bin")` is never `nullopt`, and that the old inode, once no longer named, is free after recovery both ways.
- **T5. Counts** (`ext2_tree_tests.cpp` `RenameAll`, all variants). Each case is followed by `CheckClean`:
  - replacing a single-link file: free inodes +1, and the old inode has a deletion time;
  - replacing `/h2`: free inodes unchanged, `nlink` 2;
  - a directory onto an empty directory across directories: both parents' `links_count` and `..` per debugfs.

### Kernel host (`tests/unit/kernel/filesystem/`)

- **T6. One call, ext2 prefix replay.**
  1. `/mnt` is ext2. Write `dst.txt` "old" and `src.txt` "new", then `SyncPeriodic`.
  2. Copy the partition, and record every `(sector, data)` through `on_write` during `Files::Rename` and `SyncPeriodic`.
  3. For each prefix k, apply k writes to a copy and mount it. `dst.txt` is "old" or "new", never missing.
  4. Both outcomes must occur.

  The same on ext4 (`vda4`), with a journal replay.
- **T7. Errno matrix through `Files::Rename`,** over ext2 `/mnt`, ext4 `/mnt`, `/tmp` and FAT16. Every row of §4 that the filesystem supports. Plus:
  - an open target gives `EBUSY` and stays unchanged;
  - `writes_fail` while replacing on ext2 gives `EIO`, not `EEXIST`;
  - `ENOTEMPTY`, `EISDIR`, `ENOTDIR` and a rename onto its own hard link leave `on_write` uncalled.
- **T8. tmpfs.**
  - It replaces a file, a link and an empty directory.
  - It refuses a non-empty directory, mismatched kinds and an ancestor, and both nodes are unchanged after each refusal.
  - After a replacement, `UsedBytes` = before − the target's capacity.
  - With all 128 entries used, a replacement followed by a `Create` succeeds.
- **T8b. FAT16 window.** A prefix replay as in T6 on FAT16: every prefix shows the target old, new or missing, and when it is missing the source holds "new".

### QEMU (both architectures)

- **T9. `libctest` `CheckRename`,** on `/home` (the ext4 root) and `/tmp`:
  - file onto file: the contents are new and the source gives `ENOENT`;
  - onto a symbolic link: `lstat` is `S_ISREG`;
  - onto its own hard link: 0, `st_nlink` 2;
  - `EISDIR`, `ENOTDIR`, `ENOTEMPTY`, `EINVAL`;
  - a directory onto an empty directory: `..` is the parent, and the parent's `st_nlink` drops by one;
  - an open target: `EBUSY`, unchanged.
- **T10. Shell** (`ext4.py`).
  1. Write `/samples/t.txt` "old target" and `/samples/s.txt` "new target".
  2. `mv /samples/s.txt /samples/t.txt`.
  3. `cat` prints "new target", and `ls` does not show `s.txt`.
  4. Clean up. The session's `e2fsck -fn` passes.

## 7. Risks for the implementer

- **The old errno fallback** in `Files::Rename` turns any failure on an existing target into `EEXIST`/`EISDIR`. It must go together with moving the checks ahead of the call.
- **T1–T3 run debugfs and e2fsck at every cut.** Keep one `TEST_CASE` per variant so CTest runs them in parallel, and use a stride on the slower layouts.
- **tmpfs has no hard links**, and **`mv` moves into an existing directory**, so the shell cannot replace a directory; T9 covers that case.
