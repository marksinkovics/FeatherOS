# M14: USB host and HID input (design)

**Scope.** Today, keyboard input reaches programs as terminal bytes:
- x86-64 uses PS/2 on IRQ 1 through the legacy PIC (`src/kernel/arch/x86_64/keyboard.cpp`).
- AArch64 uses virtio-keyboard over MMIO (`arch/aarch64/keyboard.cpp`).
- Both call `Input::SubmitKey(Keyboard&, code, pressed)` (`src/kernel/input/input.cpp`). It turns key codes into VT100 bytes for the shown console's `Terminal`.
- Key codes are Linux evdev numbers (`input/keyboard.h`). Only the US layout exists. Repeat comes from the device: PS/2 typematic or virtio.

What the code lacks:
- **x86-64:**
  - PCI is a port-I/O scan that finds legacy I/O BARs only (`arch/x86_64/pci.cpp`).
  - Device interrupts go through the 8259 PIC. There is no IOAPIC and no MSI.
  - The local APIC is used only for IPIs and the timer (vectors 48 and 49). IRQ stubs cover vectors 32–49.
- **AArch64:**
  - There is no PCI code.
  - The GIC is a GICv2 found through the device tree (`arch/aarch64/interrupts.cpp`). SPIs are never set to edge-triggered.
- **Both:**
  - `Memory::MapDevice` tracks at most 128 pages.
  - DMA memory is `AllocateContiguousPageFrames` plus the HHDM. It has no address limit.
  - There is no kernel log ring.
  - Without virtio-blk the kernel panics: "Virtio block device initialization failed".

This milestone has five parts:
1. A shared PCI layer, DMA buffers and MSI on both architectures.
2. An xHCI driver and a USB core with root-port hot-plug.
3. HID keyboard and mouse, software key repeat, LEDs, and a pointer-event queue behind `/dev/mouse`.
4. USB 2.0 and 3.x hubs with transaction translators.
5. Real-hardware readiness for an x86-64 UEFI laptop: i8042 hardening, Intel port routing, booting without a disk, fallbacks, a USB-stick image and a checklist.

The design leaves room for M19 Part 2:
- Transfers do not depend on the endpoint type, so bulk transfers fit.
- `HostController::Submit` can be called from any task.
- The core binds drivers by interface class, so mass storage (class 8) is a new driver, not a core change.

**Done when:**
1. `./build.sh unit-test` and `unit-test-tsan` pass.
2. `bash tools/quality.sh check` passes.
3. `tools/check.sh --arch both --modes "PCI USB INPUT"` passes.
4. `tools/check.sh --arch both --matrix` passes.
5. The laptop checklist (section 7) has been run once and its log saved. A failure there does not block the milestone.

## Decisions (user, 2026-11-21)

- The first real machine is an x86-64 UEFI laptop.
- Hubs are in scope: USB 2.0 and 3.x, with transaction translators.
- Keyboard and mouse are in scope. The mouse feeds a new pointer-event queue.
- Done means QEMU tests on both architectures. The laptop boot is a checklist item, not a blocker.

## How the laptop's keyboard is reached

- **PS/2 behind the embedded controller (i8042).** This is the usual case. The EC emulates ports 0x60/0x64 even when the firmware runs in pure UEFI mode.
  - Today's driver only waits for the input buffer and sends `0xAE`. That works under SeaBIOS.
  - On real firmware it also needs:
    - flushing the output buffer;
    - reading the configuration byte (`0x20`) and writing it back (`0x60`) with IRQ 1 on (bit 0), translation on (bit 6) and the keyboard clock enabled (bit 4 clear);
    - logging the FADT `IAPC_BOOT_ARCH` 8042 flag (bit 1) without trusting it, because firmware often reports it wrong;
    - running *after* the xHCI handoff.
  - Before the handoff, the firmware's SMM "USB legacy emulation" can feed a USB keyboard into ports 0x60/0x64. It stops at the handoff, and leftover bytes must be flushed.
  - IRQ 1 reaches CPU 0 through the PIC in virtual-wire mode (LINT0 is ExtINT, `local_apic.cpp:80`). PCH chipsets still have the 8259.
  - With no controller, the status port reads `0xFF`, so `WaitForControllerWrite` fails and the kernel goes on.
- **Internal USB keyboard** (some laptops): handled by this milestone's xHCI and HID drivers.
- **I2C-HID** (some 2-in-1s, and most touchpads since about 2015): **out of scope.** It needs ACPI AML interpretation (`PNP0C50`, `_DSM`, `_CRS` GPIO interrupts), an Intel LPSS DesignWare I2C driver and a GPIO driver. If the laptop's keyboard is I2C-HID, use an external USB keyboard.
- **PS/2 touchpad** (aux port, IRQ 12): not in M14. See open question 14.

## 1. Design

### 1.1 PCI (shared) and its architecture backends

- `src/kernel/pci/` holds the architecture-neutral layer over a `ConfigSpace` interface:
  - enumeration: header type, multifunction bit, recursion through PCI-to-PCI bridges along the secondary bus numbers the firmware set;
  - BAR decoding and sizing: 32- and 64-bit, original value restored;
  - the capability walk, at most 48 steps;
  - MSI and MSI-X programming.
- **x86-64:**
  - The `0xCF8` mechanism moves into a `ConfigSpace`. The first 256 bytes are enough, since xHCI's extended capabilities are in MMIO.
  - `FindIoDevice` stays for virtio.
  - INTx is not supported. The PIC lines from config 0x3C mean nothing on UEFI, routing needs ACPI `_PRT`, and PIC handlers cannot be shared.
- **AArch64:**
  - New: `arch/aarch64/pci_ecam.cpp`. It reads the `pci-host-ecam-generic` node's `reg` (ECAM), `bus-range`, `ranges`, `interrupt-map` (INTx with the standard swizzle) and `msi-parent` (GICv2m).
  - BARs: use what the firmware assigned (edk2 ArmVirtQemu assigns every BAR). If a BAR is 0, assign it from the 32-bit `ranges` window with a simple bump allocator.
  - QEMU virt sets `dma-coherent` on the node. A node without it is refused with a log line until a non-coherent DMA path exists (Raspberry Pi, later).
- `Memory::MapDevice` keeps a table of up to 64 *ranges* instead of 128 pages. An ECAM bus is one 1 MiB range, and an Intel xHCI register block is 64 KiB.

### 1.2 DMA and MSI

- `Dma::Allocate(bytes, below, Buffer*)` returns zeroed, physically contiguous pages through the HHDM. `below` limits the physical address: 4 GiB when xHCI's `HCCPARAMS1.AC64` is 0, 256 MiB for the `edu` test device.
- `AllocateContiguousPageFrames` gains a `limit` argument.
- Barriers:
  - `Dma::ProducerBarrier()`: `dmb oshst` on AArch64, a compiler barrier on x86-64. Used before a cycle-bit handover and before a doorbell.
  - `Dma::ConsumerBarrier()`: `dmb oshld` on AArch64. Used after seeing an owned TRB.
- `Arch::Msi::Allocate(handler, context, MsiMessage*)`:
  - **x86-64:** vectors 50–57. IRQ stubs are extended to vector 57 (`exceptions.asm` `%rep 26`), dispatched in `exceptions.cpp`, and end with a local APIC EOI. Address `0xFEE00000 | (boot CPU APIC ID << 12)`, data = vector (fixed delivery, edge). Everything goes to CPU 0.
  - **AArch64:** GICv2m. `TYPER` at frame + 0x008 gives the first SPI and the count. Address = frame + 0x040 (`MSI_SETSPI_NS`), data = SPI ID. The SPI is set edge-triggered in `GICD_ICFGR` (new `ConfigureEdge`). Without edge configuration, QEMU's pulse can be lost.
- `Arch::Msi::RegisterIntx(irq, handler, context)`: AArch64 only, level-triggered.
- Order of preference: **MSI-X, then MSI, then INTx (AArch64 only), then polling.** `usb=poll` forces polling.

### 1.3 xHCI (`src/kernel/usb/xhci/`)

**Bring-up, in order:**
1. Find the controller by PCI class 0C/03/30. Map BAR 0 and enable memory space and bus mastering.
   - Log any EHCI (prog-if 20), OHCI (10) or UHCI (00) controller as unsupported.
2. **Intel PCH port routing** (vendor 8086, 7-, 8- and 9-series): write `USB3_PSSEN` (0xD8) from `USB3PRM` (0xDC), and `XUSB2PR` (0xD0) from `USB2PRM` (0xD4). This moves the USB 2.0 ports from EHCI to xHCI. 100-series chips (2015) and later have no EHCI, and the registers are harmless.
3. **BIOS/OS handoff.** Walk the extended capabilities (`HCCPARAMS1.xECP`) to ID 1, USB Legacy Support.
   - Set *OS Owned*.
   - Wait up to 1 s for *BIOS Owned* to clear. If it does not, clear it yourself and log `forced`.
   - In `USBLEGCTLSTS`, clear the SMI enables (bits 0, 4, 13–15) and write 1 to clear the status bits (29–31).
4. Stop (`USBCMD.RS`=0) and wait for `HCH`, up to 32 ms.
5. Set `HCRST`. Wait for `HCRST` and `CNR` to clear, up to 1 s; give Intel controllers up to 10 s. Wait 1 ms before the first access after reset (Intel).
6. Read `HCSPARAMS1` (MaxSlots, MaxPorts), `HCSPARAMS2` (scratchpad count), `HCCPARAMS1` (AC64, CSZ, PPC, xECP), `PAGESIZE` (must include 4 KiB) and `DBOFF`/`RTSOFF`.
7. Set `CONFIG.MaxSlotsEn` = min(MaxSlots, 64).
8. Allocate the DCBAA: (slots + 1) × 8 bytes, 64-byte aligned, one page.
   - If scratchpads > 0: allocate a scratchpad array of N page pointers plus N zeroed pages, and set DCBAA[0] to the array.
9. Command ring: one page, 256 TRBs, the last one a Link TRB with Toggle Cycle. Set `CRCR` = address | RCS.
10. Event ring on interrupter 0: one segment of 256 TRBs and a one-entry ERST. Set `ERSTSZ`, then `ERDP`, then `ERSTBA`.
    - `IMOD` = 4000 (1 ms).
    - `IMAN.IE` = 1, and `USBCMD.INTE` = 1 except in polling mode.
11. Set up MSI-X, MSI, INTx or polling (1.2). Set `RS`=1. If `PPC` is set, power the ports (`PORTSC.PP`).
12. Scan the root ports. The Supported Protocol capabilities (ID 2) say which port numbers are USB 2 and which are USB 3, and give the PSI speed IDs.

**Contexts.** Context size is 32 or 64 bytes (`CSZ`), and every offset goes through `ContextLayout`.
- Input context: an input control context, then slot, then EP0 to EP30. One page per slot.
- Device context: one page per slot.

**Enumerating a port** (root port or hub port, done by the manager task):
1. Reset the port. USB 2 ports get `PR` and a wait for `PRC`, 50 ms then `PED`. A USB 3 port that is already enabled in U0 needs no reset; otherwise use a warm reset (`WPR`).
2. Read the speed from `PORTSC`.
3. `Enable Slot`.
4. Fill the input context:
   - slot context: route string, speed, root port, context entries = 1, TT hub slot/port/MTT;
   - EP0: control, CErr 3, MPS 8 for low and full speed, 64 for high speed, 512 for SuperSpeed.
5. `Address Device` (BSR=0).
6. `GET_DESCRIPTOR(device, 8)`. If `bMaxPacketSize0` differs, send `Evaluate Context`.
7. `GET_DESCRIPTOR(device, 18)`, then the configuration (first 9 bytes, then `wTotalLength`, at most 4 KiB).
8. Choose configuration 1 and match drivers. Send `Configure Endpoint` with the drivers' endpoints, then `SET_CONFIGURATION`.

**Rings.**
- Producer rings (command and transfer) are one segment of 256 TRBs each.
- A TRB is written with dwords 0–2 first, then a barrier, then dword 3 with the cycle bit.
- At the Link TRB, the producer writes the link with its current cycle and the chain bit set if the TD continues, then toggles its cycle state.
- A TD that does not fit before the link is padded with No-Op TRBs first. This sidesteps the chain-bit quirk of AMD 0.96 controllers.
- Free space = capacity − 1 − in flight. In-flight TRBs are retired by their completion events.
- Event ring: consume while the cycle bit equals CCS, toggle CCS at the segment end, and write `ERDP` = last consumed | EHB once per batch.

**Interval** (xHCI exponent in 125 µs units):
- Low and full speed interrupt endpoints: `clamp(floor(log2(bInterval × 8)), 3, 10)`.
- High speed and SuperSpeed: `bInterval − 1`, clamped to 0–15.

**Errors.**

| Completion code | Action |
|---|---|
| Success, Short Packet (IN) | Done; `actual` = length − residue |
| Stall on EP0 | `Reset Endpoint` (TSP=0). The transfer fails with `Stall`; the next control transfer works |
| Stall on other endpoints | `Reset Endpoint`, `Set TR Dequeue Pointer` past the TD, `CLEAR_FEATURE(ENDPOINT_HALT)` to the device, then resubmit (HID) or fail (callers) |
| USB Transaction Error | Retry up to 3 times, then handle as a stall. After 3 recoveries in 1 s, unbind the interface |
| Babble, Split Transaction Error | Handle as a stall |
| Command not complete within 5 s | `CRCR.CA` (abort), then wait for Command Ring Stopped. The command fails with `Timeout` and its slot is disabled |
| `USBSTS.HCE` or `HSE` (checked on every wake and by a 1 s watchdog) | Log, detach every device, reset the controller once and enumerate again. A second failure disables the controller |
| Event pointer matches no pending TRB | Log once per controller and ignore. Never dereference it |

**Root-port hot-plug.**
- A Port Status Change Event posts work to the manager. The manager reads `PORTSC` and clears the change bits it saw.
- Writes to `PORTSC` keep only the RW bits (PP, PIC, LWS, the wake bits) plus the one change bit being cleared. They never write 1 to `PED`, because that disables the port.
- Connect: 100 ms debounce, then enumerate. Disconnect: detach.

### 1.4 USB core (`src/kernel/usb/`)

- `HostController` is an interface implemented by `Xhci::Controller` and by the host-test fake.
- `Device` holds:
  - its number (lowest free 1–127 per bus; the root hub is 1);
  - its path name in Linux style, such as `1-1.2`;
  - the slot, the `Location` (speed, root port, route, depth, TT), the parent and its port;
  - the descriptors, the bound drivers per interface, and a `generation`.
- Drivers come from a static table and match on interface class/subclass/protocol: hub (09), HID (03), and later mass storage (08). One driver per interface; the first interface that matches wins.
- The configuration is always the first one. Alternate settings other than 0 are ignored.
- Detach:
  - Children are detached first.
  - `Stop Endpoint` on every endpoint, so each pending transfer completes with `Cancelled`.
  - The manager waits until the device's in-flight callbacks reach 0.
  - Then `Detach` on each driver, `Disable Slot`, and the rings and contexts are freed.
- `/proc/usb` has one line per device: `1-1.2 dev 3 full 0627:0001 class 03/01/01 hid-keyboard`. New program `lsusb` prints it.

**Log lines (the tests depend on them):**
- `USB: xHCI 1b36:000d at 00:04.0, 8 ports, 64 slots, 32-byte contexts, MSI-X`
- `USB 1-1: high-speed 0627:0001 "QEMU USB Keyboard" hid-keyboard`
- `USB 1-1: disconnected`
- `USB: handoff from firmware forced`
- `USB: interrupts by polling`

### 1.5 Hubs (`usb/hub.cpp`, logic in `usb/hub_state.cpp`)

- Attaching a hub:
  1. Read the hub descriptor: 0x29 for USB 2, 0x2A for USB 3.
  2. For a USB 3 hub, send `SET_HUB_DEPTH` (depth − 1).
  3. Update the slot context: Hub=1, port count, TT think time (`wHubCharacteristics` bits 5–6), MTT if `bDeviceProtocol` = 2 and alternate setting 1 is chosen. This goes in the same `Configure Endpoint` that adds the hub's interrupt IN endpoint.
  4. `SET_FEATURE(PORT_POWER)` on every port, then wait `bPwrOn2PwrGood` × 2 ms.
  5. Submit the status-change interrupt transfer: a bitmap, bit 0 for the hub, bit *n* for port *n*.
- On a change, the event task posts `{hub number, generation}` to the manager. The manager:
  1. Runs `GET_STATUS(port)` and clears each `C_PORT_*` it sees (connection, enable, suspend, over-current, reset; for USB 3 also `C_BH_PORT_RESET` and `C_PORT_LINK_STATE`).
  2. Debounces for 100 ms and sends `SET_FEATURE(PORT_RESET)`.
  3. Waits for `C_PORT_RESET`, up to 500 ms.
  4. Reads the speed: low or high from the USB 2 status bits; always SuperSpeed on a USB 3 hub.
  5. Enumerates the child.
  6. Resubmits the interrupt transfer.
- Child location:
  - route = parent route | (port << 4 × parent depth); depth at most 5; ports above 15 are refused;
  - the root port is inherited;
  - for a low- or full-speed device with a high-speed ancestor hub, the TT hub slot is the *nearest* high-speed hub, and the TT port is the port on that hub the path leaves by (1 if it is a single-TT hub).
- Only the manager task enumerates, so one device at a time is in the default state.

### 1.6 HID (`usb/hid/`)

- Attach:
  - Read the report descriptor (`GET_DESCRIPTOR(0x22)`, at most 1 KiB).
  - Boot keyboards (subclass 1, protocol 1) use `SET_PROTOCOL(boot)` and the fixed boot layout, unless `usbhid=report`. Mice (protocol 2) and other interfaces use report protocol with the parsed layout (`SET_PROTOCOL(report)`, a stall ignored); a mouse whose descriptor is refused or has no mouse fields falls back to `SET_PROTOCOL(boot)` and the boot layout.
  - `SET_IDLE(0)`. A stall here is ignored.
  - Keep two interrupt IN transfers queued, so the endpoint never waits for a resubmit.
- **Report-descriptor parser:**
  - Main items: Input, Output, Feature, Collection, End Collection.
  - Global items: Usage Page, Logical Minimum/Maximum, Report Size, Report Count, Report ID, Push/Pop (depth 4). Local items: Usage, Usage Minimum/Maximum.
  - The application collection's usage gives the kind: Generic Desktop Keyboard (01:06), Mouse (01:02) or Pointer (01:01).
  - Keyboard fields: modifiers (07:E0–E7, variable bits), keys as an array or as a bitmap (NKRO), LEDs (08:01–05, Output).
  - Mouse fields: buttons (page 09), X and Y (01:30, 01:31, relative, 8–16 bit signed), wheel (01:38), AC Pan (0C:0238).
  - At most 8 report IDs per interface, fields of at most 32 bits, reports of at most 64 bytes.
  - Long items, unbalanced collections and fields past the report length are refused. A refused interface falls back to the boot protocol if it has one.
- **Keyboard:**
  - Each report is compared with the previous one and gives releases first, then presses, as evdev codes through `UsageToKeyCode`. The table is written from HID Usage Tables §10 and the evdev values: 04→30 (A), 1E–27→2–11, 28→28, 39→58, 3A–45→F1–F12, 4F–52→arrows, 53→69, 54–63→keypad, 64→86, E0–E7→29/42/56/125/97/54/100/126.
  - A rollover report (every slot is 01) is ignored.
  - Detach and endpoint errors release every key that is down.
  - Events go to `Input::SubmitKey(keyboard, code, pressed)` with one `Input::Keyboard` per USB keyboard.
- **Repeat** (software; USB does not repeat): the most recent non-modifier, non-lock key repeats after 500 ms, then every 33 ms. A release, a new press or a detach stops it. The event task submits repeated presses, which `Keyboard::Press` already handles.
- **Locks and LEDs:**
  - Caps Lock and Num Lock become *global* lock states in `Input` (atomic). Modifiers stay per keyboard.
  - `Keyboard` gains Num Lock and keypad digits (71–83) when it is on.
  - A change in lock state is posted to the manager. The manager sends `SET_REPORT(Output, LED byte)` to every keyboard that has an LED field: boot bit 0 = Num, bit 1 = Caps.
  - PS/2 LEDs (`0xED`) are left out (open question 12).

### 1.7 Pointer events and their ABI

- `Input::Pointer` is a ring of 256 `User::InputEvent` records with a global sequence number. Each reader keeps its own cursor.
- A producer submits one report at a time, ending in `SYN_REPORT`, so readers see whole reports.
- A reader that fell more than 256 events behind gets one `SYN_DROPPED`, then continues at the oldest report start still in the ring.
- ABI, identical to Linux `struct input_event` on 64-bit:
  `struct InputEvent { int64_t seconds; int64_t microseconds; uint16_t type; uint16_t code; int32_t value; }` (24 bytes).
  - The time is monotonic uptime.
  - Event types and codes use the Linux names and values: `EV_SYN`/`EV_KEY`/`EV_REL`, `REL_X`/`REL_Y`/`REL_WHEEL`/`REL_HWHEEL`, `BTN_LEFT` 0x110, `BTN_RIGHT`, `BTN_MIDDLE`, `SYN_DROPPED` 3.
- `/dev/mouse` merges every pointer device.
  - `read` returns only whole events. A length below 24 gives `EINVAL`.
  - It blocks, or gives `EAGAIN` with `O_NONBLOCK`.
  - `poll` reports readable when the cursor is behind the ring.
  - Writes are discarded, like the other devices.
- Files gets a new `Kind::PointerEvents` with a per-file cursor. Each `Submit` calls `Poll::Notify()`.
- libc: `<featheros/input.h>`, documented in `docs/posix.md`. New program `mousetest [n]` prints events such as `mouse: rel x 10` and `mouse: key 272 1`.

### 1.8 Tasks and locking

- **`UsbEvents`** (kernel task, High priority, one for every controller):
  - Sleeps on `event_wait` until whichever comes first: an interrupt, the next tick (polling), the next repeat deadline, or a 1 s watchdog.
  - Drains the event rings and completes commands and transfers, waking their waiters.
  - Runs the interrupt-endpoint callbacks: HID parsing, `SubmitKey`, `Pointer::Submit`, resubmits; hub changes are posted to the manager.
  - **It never blocks on a transfer and never takes `topology_lock`.**
- **`UsbManager`** (kernel task, Normal priority): handles port work and LED work in order. It enumerates, configures and detaches, and blocks in `Wait(transfer)` and `WaitCommand`.
- **Interrupt top half:** clear `IMAN.IP` (write 1 to clear, keep IE), clear `USBSTS.EINT`, set `pending`, then `WakeAll(event_wait)`. It touches no ring.

Lock order, for `docs/development.md` as "USB locking"; nothing takes an earlier lock while holding a later one:

1. The `/proc` volume lock, held only by readers of `/proc/usb`.
2. `Usb::topology_lock` (`Sync::Mutex`): the device tree, bindings and numbering. Held by the manager during attach and detach, and by `/proc/usb`. Never held by the event task.
3. `Controller::ring_lock` (spinlock, saves interrupt state): ring enqueue state, the pending tables and doorbells. Held by submitters from any task and by the event task when it retires TRBs. No allocation, logging, waiting or `Input` call under it.
4. `Usb::completion_lock` with `completion_wait`, and `Usb::event_lock` with `event_wait`, and the manager's `work_lock` (all spinlocks).
5. Leaves: `Input::Pointer`'s `pointer_lock` (spinlock, saves interrupt state) and the heap. Terminal locks are reached from the event task with no USB lock held.

Callbacks check the device's `generation` under `ring_lock`, and the in-flight count keeps a device's driver state alive until detach has waited for it.

## 3. Invariants

**PCI and DMA (steps 1–2)**
- **I1.** BAR sizing restores the original BAR and command register. A 64-bit BAR consumes two indexes. **Riskiest.**
- **I2.** The capability walk ends: at most 48 steps, and offsets are 4-aligned and ≥ 0x40.
- **I3.** MSI and MSI-X are programmed (address, data, entry unmasked) *before* the enable bit, and INTx is disabled while they are on. **Riskiest.**
- **I4.** `Dma::Allocate(below)` returns only frames whose whole range lies below `below`, zeroed and contiguous. **Riskiest.**
- **I5.** An MSI on x86-64 ends with a local APIC EOI, never a PIC EOI. An MSI SPI on AArch64 is edge-triggered.

**Rings and controller (steps 3–4)**
- **I6.** A TRB's dword 3 (cycle) is written last, after a producer barrier. **Riskiest.**
- **I7.** The Link TRB carries the producer's old cycle and TC=1. The producer toggles after writing it. A TD never straddles the link without the chain bit. **Riskiest.**
- **I8.** Enqueue never overruns in-flight TRBs (free = capacity − 1 − in flight).
- **I9.** The event consumer stops at the first cycle mismatch, toggles CCS at the segment end, and writes `ERDP` only up to a consumed TRB, with EHB set.
- **I10.** Every completion maps to at most one pending command or transfer. Unknown pointers are ignored. **Riskiest.**
- **I11.** Handoff: OS Owned is set, BIOS Owned is clear (or forced) and the SMI enables are off before `HCRST`. `HCRST` only after `HCH`. No register access while `CNR` is set.
- **I12.** Scratchpads: DCBAA[0] points to N zeroed, page-aligned buffers when N > 0, and is 0 when N = 0.
- **I13.** Every context offset uses the controller's context size (32 or 64 bytes).
- **I14.** `PORTSC` writes keep the RW bits and never write 1 to `PED` or to change bits other than the one being cleared. **Riskiest.**
- **I15.** Every wait (command, reset, handoff, port) has a deadline. A timeout aborts and frees.

**Core (step 5)**
- **I16.** Descriptor parsing never reads past `wTotalLength` or the buffer, and refuses `bLength` < 2. **Riskiest.**
- **I17.** A full-speed EP0 MPS is fixed with `Evaluate Context` before any transfer longer than 8 bytes.
- **I18.** Interval exponents follow 1.3 for each speed.
- **I19.** A stalled endpoint is reset (`Reset Endpoint`, `Set TR Dequeue`, `CLEAR_FEATURE(HALT)` when not EP0) before reuse.
- **I20.** Detach order: children first; stop endpoints; no callback runs for a detached device's generation; driver state is freed after in-flight reaches 0; then the slot is disabled. Slots and frames return to their counts before attach. **Riskiest.**
- **I21.** The event task never blocks on a transfer or takes `topology_lock`. No USB lock is held across `Input` calls, logging or allocation. The interrupt handler touches only `IMAN`, `USBSTS` and the wake flag.

**HID (steps 6–7)**
- **I22.** Report fields lie inside the report. Unknown report IDs are ignored. Malformed descriptors are refused.
- **I23.** Every press has exactly one release, including on detach and on endpoint errors. Rollover reports change nothing. **Riskiest.**
- **I24.** Only the latest non-modifier, non-lock key repeats. A release, a new press or a detach stops it.
- **I25.** The LED reports follow the global lock state, and Caps Lock toggles once per physical press.
- **I26.** The usage-to-code map matches the HID Usage Tables and evdev values for every mapped usage. Unmapped usages give 0 and are dropped.

**Pointer ABI (step 8)**
- **I27.** Readers get whole 24-byte events in report order. Each reader has its own cursor. Overflow gives exactly one `SYN_DROPPED`, then the next report start. **Riskiest.**
- **I28.** A read shorter than 24 bytes gives `EINVAL`. An empty queue gives `EAGAIN` with `O_NONBLOCK`, else blocks (and a signal ends the wait). `poll` reports readable exactly when the cursor is behind.

**Hubs (step 9)**
- **I29.** A child is enumerated only after its port reset completes and `C_PORT_RESET` is cleared. Every change bit seen is cleared. **Riskiest.**
- **I30.** Route = parent route | port << 4 × depth, with depth ≤ 5. The TT hub is the nearest high-speed hub and is used only for low- and full-speed devices below one. A USB 3 hub gets `SET_HUB_DEPTH` = depth − 1. **Riskiest.**

**Real hardware (step 10)**
- **I31.** With no xHCI, or `usb=off`, boot and PS/2 behave as before.
- **I32.** The i8042 is set up after the USB handoff, with translation and IRQ 1 on.
- **I33.** Booting without a disk reaches a shell.

## 4. Edge cases

| Case | Result |
|---|---|
| No xHCI / `usb=off` | No USB line; PS/2 or virtio as today |
| EHCI, OHCI or UHCI only | `USB: EHCI at bb:dd.f not supported`; PS/2 only |
| AC64=0 and no frame below 4 GiB | Controller refused, `ENOMEM` in the log |
| `PAGESIZE` without 4 KiB | Controller refused |
| BIOS never releases ownership | Forced after 1 s, logged |
| `HCRST` or `CNR` never clears | Controller refused after 10 s |
| No MSI-X or MSI | INTx on AArch64, polling on x86-64 (`USB: interrupts by polling`) |
| More than 64 devices | `Enable Slot` fails (`No Slots Available`); port left disabled, logged |
| Configuration longer than 4 KiB | Refused with a log line |
| Device without a matching driver | Enumerated, listed in `/proc/usb` as `unbound` |
| A seventh hub tier, or a port above 15 | Refused, port disabled |
| Unplugged during enumeration | Commands fail `NoDevice` or `Timeout`; slot freed; no log storm |
| Hub unplugged with devices behind it | Children detached first (I20) |
| Over-current on a hub port | Port powered off, logged |
| Keyboard unplugged with Shift held | Releases submitted; the next keyboard types lowercase |
| Second reader of `/dev/mouse` | Gets events from the moment it opens |
| `read(fd, buf, 10)` on `/dev/mouse` | `EINVAL` |
| Interrupt storm or Event Ring Full | Events drained each wake; Event Ring Full logged once |
| `HCE`/`HSE` | One controller restart, then the controller is disabled |

## 7. Laptop checklist (manual, not blocking)

1. **Firmware setup:**
   - Secure Boot off.
   - Note the "USB legacy support" and "xHCI mode" options; test with legacy support on, then off.
   - Fast Boot off.
   - No CSM is needed.
2. **Build:**
   - `LIMINE_TIMEOUT=5 ./build.sh --arch x86_64 iso`. Without the timeout, Limine's `timeout: 0` hides the menu where the command line is edited.
   - `build/x86_64/featheros.iso` is a hybrid image with Limine's BIOS install and an EFI partition. Write it to a stick: `sudo dd if=build/x86_64/featheros.iso of=/dev/rdiskN bs=4m` on macOS (find N with `diskutil list` and unmount first).
   - Or `tools/make_usb_stick.sh`: a FAT32 image with `EFI/BOOT/BOOTX64.EFI`, `limine.conf`, `kernel.elf` and `initramfs.tar`.
3. **Boot** from the stick through the firmware's one-time boot menu. Tries, in order:
   - default;
   - `usb=poll`;
   - `ps2=off` (USB keyboard only);
   - `usb=off` (PS/2 only).
4. **Log** (every line has a fixed prefix):
   - `Limine transferred control`, timer and CPU count;
   - the ACPI FADT 8042 flag;
   - `PCI:` lines (look for class `0c0330` and any `0c0320` EHCI);
   - the xHCI line (ports, slots, context size, interrupt mode, handoff forced or not, scratchpad count);
   - each `USB 1-x` line;
   - `Keyboard: i8042 config 0xNN`;
   - `Storage: no disk`.
   - Then type on the internal keyboard and on a USB keyboard. Run `lsusb`, `mousetest 20` (move a USB mouse) and `dmesg`.
5. **Without a serial port** (most laptops):
   - The framebuffer shows the log as it happens. Photograph each screen.
   - `dmesg | head -60` and `dmesg | tail -60` page through the 64 KiB ring.
   - A log cannot be saved to the ESP or a FAT stick in M14. The kernel's only disk driver is virtio-blk, so writing needs USB mass storage (M19 Part 2) or an NVMe/AHCI driver. Note the photos in `docs/hardware.md`.
   - The xHCI Debug Capability (a USB 3 A-to-A debug cable) is a possible later serial console.
6. **Known blockers this milestone does not fix.** Record which one appears:
   - firmware-enabled x2APIC: the xAPIC MMIO accesses in `local_apic.cpp` fail;
   - a gated 8254 PIT (timer calibration hangs);
   - no 1024x768 GOP mode.

## 8. Decisions taken (2026-11-21)

The user accepted every recommendation below, and noted for question 17: x2APIC is fixed in a small separate step only if it blocks the first laptop boot.


1. **Pointer ABI.** Recommended: `/dev/mouse` with Linux-layout `struct input_event` records and Linux code values, in `<featheros/input.h>`. Alternatives: PS/2 3-byte packets (lossy) or a FeatherOS-only struct.
2. **Per-device event nodes** (`/dev/input/eventN`, including raw keyboard events). Recommended: later, with a GUI.
3. **PS/2 stays the default?** Recommended: initialize both PS/2 and USB always; `ps2=off` and `usb=off` exist for diagnosis.
4. **Keyboard layouts.** Recommended: US only in M14 (add code 86 for the ISO key). A layout table (`/etc/keymap`) goes to `docs/ideas.md`.
5. **USB naming.** Recommended: Linux-style paths (`1-1.2`) in logs and `/proc/usb`, device numbers lowest-free 1–127, no `/dev/bus/usb` nodes.
6. **Polling vs MSI first.** Recommended: polling in step 4 for bring-up, MSI-X in the same step as the default.
7. **AArch64 without MSI.** QEMU virt has GICv2m by default (`msi=gicv2m`). Recommended fallbacks: INTx through `interrupt-map`, then polling. GICv3/ITS is out of scope.
8. **x86-64 INTx.** Recommended: not implemented (it needs PIC sharing and ACPI `_PRT`); fall back to polling.
9. **USB devices in every QEMU run?** Recommended: only in the USB cases, plus `QEMU_USB=1` for interactive runs. Otherwise `sendkey` in the `INPUT` case could reach `usb-kbd` instead of PS/2.
10. **An x86-64 UEFI (OVMF) matrix case**, closer to the laptop. Recommended: yes, for `usb` only, when edk2 x86 firmware is found (Homebrew QEMU ships it).
11. **Repeat rates.** Recommended: fixed 500 ms / 30 Hz; configuration later.
12. **Lock state.** Recommended: Caps and Num Lock global across keyboards; PS/2 LEDs (`0xED`) as a small follow-up.
13. **`usb-tablet` and absolute pointers** (`EV_ABS`). Recommended: parse absolute X/Y in step 6 at little cost; add a QEMU check only if wanted.
14. **PS/2 aux mouse or touchpad into the pointer queue.** Recommended: an optional item in Part 5 if the laptop's touchpad turns out to be PS/2.
15. **Root without a disk.** Recommended: tmpfs `/` with `/home`, init from `/system`, `/etc` as today's RAM copy.
16. **`dmesg` ring now?** Recommended: yes, in step 10 (it is in `docs/ideas.md` already), since a laptop without serial needs it.
17. **x2APIC.** Recommended: check on the first laptop boot; if it is the blocker, a separate small step outside M14.
18. **EHCI-only machines.** Recommended: unsupported, logged.
19. **High-speed and USB 3 hubs have no QEMU device.** Recommended: accept host-only coverage (T26–T28) and the laptop check.
20. **USB power management** (selective suspend, U1/U2). Recommended: off in M14.

**Decision taken 2026-11-22.** 21. **Mice use report protocol.** A boot-protocol mouse gets the 3-byte boot layout and never reports its wheel, so mice follow Linux: the parsed report descriptor by default, the boot protocol only as a fallback. Keyboards keep the boot protocol unless `usbhid=report`.
