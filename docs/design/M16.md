# M16: physical storage drivers, NVMe then AHCI (design)

**Scope.** The kernel today has:
- **Disks.** One block-device layer from M19 Part 2 (`storage/disk_driver.h`, `storage/disk.{h,cpp}`). Two transports implement `Storage::DiskDriver`:
  - virtio-blk (`vda`): polled, one sector at a time, under a spinlock (`arch/*/block_device.cpp`, wrapped by `storage/virtio_disk.cpp`).
  - USB BOT/SCSI (`sda`…): `usb/storage/drive.{h,cpp}`. It waits through `Usb::Storage::Environment` and bounces every transfer through a 64 KiB DMA buffer.
- **PCI and interrupts.** The PCI layer (`pci/pci.{h,cpp}`) does config space and BARs. MSI/MSI-X comes from M14: `pci/msi.{h,cpp}` and `Arch::Msi::Allocate` (x86-64 local APIC, 8 vectors; AArch64 GICv2m, 16 messages). AArch64 uses ECAM (`arch/aarch64/pci_ecam.cpp`) and refuses a host bridge that is not `dma-coherent`.
- **DMA.** `Memory::Dma` gives contiguous zeroed pages below a limit, plus barriers.
- **Volumes and root.** The storage worker probes a registered disk's volumes into the 16 "other" slots (`filesystem/drivers.cpp`). `/proc/partitions` lists them. `Storage::FlushAll()` runs at shutdown. The root is always a partition of `vda`, mounted before the timer starts.

This milestone adds, in order:
1. Groundwork in the shared storage layer: disk kinds and names, the read-only policy, a storage start that does not depend on USB, a controller hardware interface and host-test support.
2. NVMe: one controller driver, one `DiskDriver` per active namespace (`nvme0n1`).
3. AHCI: one controller driver, one `DiskDriver` per SATA disk port (`sda`…, sharing letters with USB).
4. Root on any disk: `root=nvme0n1p2` and `root=sda2` next to `root=vdaN`, with the controllers probed before the root mount.
5. QEMU tests on both architectures: every filesystem (FAT16, ext2, ext3, ext4) is written through each controller and checked on the host with mtools and `e2fsck -fn`; the system boots with its root on NVMe and on AHCI.

Left out: NCQ, several I/O queues, SGLs, direct (zero-copy) DMA, hot-plug, TRIM/DSM, SD/eMMC, root on USB, and any real-hardware step.

**Done when:**
1. `./build.sh unit-test` and `unit-test-tsan` pass.
2. `bash tools/quality.sh check` passes.
3. `tools/check.sh --arch both --modes "NVME NVME_NAMESPACES AHCI STORAGE_POLICY ROOT_DISK ROOT STORAGE USB_STORAGE"` passes.
4. `tools/check.sh --arch both --matrix` passes, including the new root cases.

## Decisions (user, 2026-11-23)

- Each controller implements M19 Part 2's `Storage::DiskDriver` and registers with the disk registry, so its volumes are probed and opened like any other disk's.
- FAT16, ext2, ext3 and ext4 are all read and written through NVMe and through AHCI in QEMU. They are checked on the host with mtools (byte comparison, `fsck.fat -n`) and `e2fsck -fn`.
- On real hardware, NVMe and AHCI disks are read-only by default. Writes happen only in QEMU or with an explicit boot option. USB drives keep read-write on request.
- **The boot option is `storage=ro|rw`.** Absent means auto: a controller with QEMU's PCI subsystem ID 1AF4:1100 is writable, everything else is read-only (1.6). It is one global option, not per disk.
- **Root on NVMe and AHCI is in M16.**
  - `root=nvme0n1p2` and `root=sda2` (AHCI) work on both architectures, next to `root=vdaN`. That makes it Part D, after AHCI, with the full matrix after it.
  - With `root=` absent the default root stays on `vda` (1.9).
- **NCQ and several I/O queues come later.** M16 keeps one command in flight per NVMe controller and per AHCI port.
- **QEMU only.** M16 has no real-hardware step and no laptop item in "Done when". The read-only policy still ships, so a later laptop run is safe.
- **Bounce buffers** are 128 KiB per NVMe controller and per AHCI port, capped by MDTS.
- Order:
  - 0: this design.
  - Part A: groundwork.
  - Part B: NVMe.
  - Part C: AHCI.
  - Part D: root on any disk.
  - Part E: docs.

## 1. Design

### 1.1 Shared groundwork (`storage/`)

**`DiskInfo` additions** (`storage/disk_driver.h`):

```cpp
enum class DiskKind : uint8_t { Virtio, Usb, Nvme, Ahci };
enum class ReadOnlyReason : uint8_t { None, Medium, Policy };
struct DiskInfo { /* existing fields */ ReadOnlyReason read_only_reason;
                  uint16_t controller_index; uint32_t namespace_id; };  // the last two: Nvme only
```

**Names.**
- `Ahci` takes the lowest free letter of the `sd` pool, which it shares with `Usb`. AHCI disks are probed before `Usb::Initialize`, so they come first.
- `Nvme` is `nvme<controller_index>n<namespace_id>`. `controller_index` is the probe order, counted from 0 and never reused within a boot. Partitions get `p`: `nvme0n1p2`. Duplicate names are refused.
- `KindName` gives `nvme` and `ahci`.

**Read-only.**
- `Disk::Transfer` refuses writes when `info.read_only` is set (`disk.cpp:135`).
- `Disk::Flush` on a read-only disk returns `{}` without calling the driver.
- The NVMe and AHCI drivers check again before building any command (I1).
- `CoreDriver::MediaAllowsWrites` logs by `read_only_reason`.

**Storage start.** New `storage/controllers.{h,cpp}`:
- `bool StartControllers(const void* platform_data)`, in order:
  1. sets the kernel `Environment`;
  2. starts the worker (moved from `usb.cpp`);
  3. walks PCI once;
  4. for class 01/08/02 calls `Nvme::Probe`;
  5. for class 01/06/01 calls `Ahci::Probe`;
  6. for class 01/04 logs the RAID-mode hint.
- Each probe creates the controller object and posts its bring-up to the worker.
- `bool WaitForControllers(uint64_t deadline_ms)` blocks the caller until every posted probe job has finished, or the deadline passes. It counts pending probes and waits through `Environment::WaitUntil`. It returns false on timeout and names the controllers still probing.
- Where it runs:
  - In Parts B and C, `StartControllers` runs in `RunConsole` after `Writeback::Start()` and before `Usb::Initialize`. Nothing waits for it.
  - From step D2 on, it runs in `MountAndVerifyDisk`, after the timer starts and the registry and page cache are initialized. It is followed by `WaitForControllers(now + 60 s)`, so the root can be on any disk (1.9).
- `void ShutdownControllers(Power::Action action)` calls each controller's `Shutdown`.

**Controller hardware interface** (`storage/controller_hardware.h`):

```cpp
enum class InterruptKind : uint8_t { Polling, MsiX, Msi };
class ControllerHardware {
public:
    virtual uint32_t Read32(uint32_t offset) = 0;
    virtual void Write32(uint32_t offset, uint32_t value) = 0;
    virtual uint64_t Read64(uint32_t offset) = 0;           // two dword reads, low first
    virtual void Write64(uint32_t offset, uint64_t value) = 0;  // low dword first
    virtual uint32_t ReadConfig32(uint16_t offset) = 0;
    virtual bool AllocateDma(uint64_t bytes, uint64_t below, Memory::Dma::Buffer* buffer) = 0;
    virtual void FreeDma(const Memory::Dma::Buffer& buffer) = 0;
    virtual InterruptKind SetUpInterrupts(void (*handler)(void*), void* context) = 0;
};
```

- The kernel implementation is `storage/pci_hardware.{h,cpp}`. It maps the register BAR, enables memory space and bus mastering with INTx disabled, and tries MSI-X entry 0, then MSI, then polling.
- INTx is not used: a level-triggered line needs the handler to quiet the device before the waiter has reaped. Both QEMU devices have MSI/MSI-X on both arches.
- Time and waits go through `Storage::Environment` (`NowMilliseconds`, `WaitUntil`, `Wake`, `Sleep`). This is the USB interface moved unchanged. Host tests have a single-thread pumping implementation and a threaded one.

**Waiting model, both controllers.**
- A waiter loops on `environment.WaitUntil(channel, min(now + 10 ms, deadline), Ready, this)`.
- `Ready` reads the completion under `completion_lock_`.
- The MSI handler only calls `Wake(channel)`. Interrupts make completion fast, and the tick step guarantees progress when an interrupt is lost and in polling mode.

### 1.2 NVMe (`storage/nvme/`)

**Bring-up** (`Controller::Start`, on the worker):
1. Read `CAP` (64-bit at 0x00) and `VS` (0x08).
   - Fields used: `MQES` (15:0), `CQR` (16), `TO` (31:24, in 500 ms units), `DSTRD` (35:32), `CSS` (44:37, NVM is bit 37), `MPSMIN` (51:48), `MPSMAX` (55:52).
   - Refuse when `CSS` lacks NVM or `MPSMIN` > 0 (no 4 KiB pages).
   - Doorbell stride = `4 << DSTRD`. SQ *y* tail = `0x1000 + (2y) × stride`; CQ *y* head = `0x1000 + (2y+1) × stride`.
2. **Disable first** (I6). Firmware such as SeaBIOS, OVMF or a laptop's UEFI leaves the controller enabled with its own queues.
   - If `CC.EN`=1 and `CSTS.RDY`=0, first wait for `RDY`=1.
   - Then clear `CC.EN` and wait for `CSTS.RDY`=0, within `CAP.TO` × 500 ms. On timeout, refuse: `Storage: nvme0: controller did not disable`.
3. Allocate one 4 KiB page each for the admin SQ (32 × 64 B) and admin CQ (32 × 16 B), with no physical limit (NVMe is 64-bit).
   - Write `AQA` = (31 << 16) | 31, then `ASQ`, then `ACQ`.
4. `SetUpInterrupts(OnInterrupt, this)`: MSI-X entry 0. The admin CQ and the I/O CQ both use interrupt vector 0, so one vector per controller.
5. Write `CC` = `EN` | `CSS`=0 | `MPS`=0 (4 KiB) | `AMS`=0 | `IOSQES`=6 | `IOCQES`=4. Wait for `CSTS.RDY`=1 within `CAP.TO`.
   - `CSTS.CFS`=1, or a read of `0xFFFFFFFF`, means refuse.
6. **Identify Controller** (admin 06h, CNS 01h, into a 4 KiB DMA page).
   - Keep: `VID`, `SSVID`, `SN`, `MN`, `FR`, `MDTS` (byte 77), `SQES`/`CQES` (512/513; their minimums must allow 6 and 4), `NN` (516), `VWC` (525 bit 0), `RTD3E` (88).
7. **Set Features, Number of Queues** (FID 07h) with NSQR = NCQR = 0, asking for one pair. A completion granting at least one pair is required.
8. **Create the I/O CQ** (05h): QID 1, depth `D` = min(`MQES`+1, 32), PC=1, IEN=1 unless polling, IV=0.
   - Then **create the I/O SQ** (01h): QID 1, CQID 1, PC=1.
9. **Namespaces.**
   - `VS` ≥ 1.1: Identify CNS 02h (the active namespace list from NSID 0).
   - NVMe 1.0: try NSIDs 1..min(`NN`, 8).
   - Each NSID gets Identify Namespace (CNS 00h) and is accepted only if (I11):
     - `NSZE` > 0;
     - the chosen format (`FLBAS` bits 3:0, plus 6:5 when `NLBAF` > 16) has `LBADS` 9 or 12 and `MS` = 0;
     - `DPS` & 7 = 0 (no protection information).
   - Otherwise it is logged, for example `Storage: nvme0 namespace 3: LBA format with 8 bytes of metadata not supported`.
   - `NSATTR` bit 0 (write-protected) gives `ReadOnlyReason::Medium`.
   - At most 8 namespaces per controller.
10. Decide the write policy (1.6). Register each accepted namespace, then `Storage::Scan` it (the worker is the caller).
    - Log: `Storage: nvme0: 00:04.0 "QEMU NVMe Ctrl" fw 1.0, MSI-X, 1 I/O queue of 32, max transfer 128 KiB, volatile write cache`
    - Log: `Storage: nvme0n1: 131072 KiB, 512-byte sectors, rw`

**Why one queue pair.**
- `DiskDriver` is synchronous, and M19's volume locks already serialize each volume.
- With the bounce buffer below, one command in flight per controller costs nothing in QEMU or in the read-mostly laptop case.
- Several queues need per-CPU vectors (only 8 on x86-64), per-queue buffers and a slot table.
- CIDs and the queue code are written so that depth > 1 and per-slot buffers can come later without changing invariants I3 and I4.

**Transfers.**
- Read (02h) and Write (01h): `CDW10-11` = SLBA, `CDW12` = NLB−1. No FUA, no SGL (`PSDT`=0).
- PRPs point at the controller's **bounce buffer** of `B` = min(128 KiB, MDTS bytes) bytes, contiguous and page-aligned. MDTS bytes = 2^MDTS × 4 KiB; MDTS = 0 means 128 KiB.
  - `PRP1` = buffer physical address.
  - `PRP2` = 0 for one page, buffer + 4096 for two pages, else the physical address of a **PRP list page**.
  - The PRP list page is filled once at probe with buffer + 4096 × k (31 entries for 128 KiB; one page holds 512, so it never chains).
- `BuildPrps(std::span<const uint64_t> pages, uint32_t first_offset, uint32_t length, ...)` is a pure, host-tested function, so direct DMA can come later.
- `max_transfer_bytes` = `B`. `Disk::Transfer` already splits, in order.
- **Flush** (00h, NSID) is sent only when `VWC`=1. Without a volatile cache, `Flush` returns success at once (I8).

**Bounce, not direct.**
- Callers pass kernel virtual buffers: page-cache pages, heap and stack. Nothing guarantees they are in the HHDM, physically contiguous or page-aligned, and the core does not give physical addresses.
- One copy per 128 KiB is cheap next to a command round trip.
- It keeps one fixed PRP list, which removes the riskiest NVMe bug class (a wrong PRP list, I13).
- It is what the USB drive does (`drive.cpp:283`).
- Direct DMA from page-cache frames is a later optimisation.

**Command IDs and completions.**
- CID is a 16-bit counter per queue that skips `0xFFFF`.
- The waiter's `Ready` reaps the CQ under `completion_lock_`. It checks the phase tag, then `ConsumerBarrier()`, then reads `DW3`.
  - If the CID matches the one in flight, it records the status.
  - Otherwise it drops the entry and logs `stale completion cid N` once (I4).
  - It then advances the head, flips the phase on wrap, and writes the CQ head doorbell.
- Submission copies the SQE into `tail`, calls `ProducerBarrier()`, then writes the SQ tail doorbell (I5).
- Status mapping, from `SF`: `SCT`/`SC`.
  - 0/0 → ok.
  - 0/0x80 (LBA out of range) → `InvalidArgument`, a core bug.
  - 0/0x20 (namespace write-protected) → `ReadOnly`.
  - Anything else → `Io`.
- No retries: a command that failed or timed out returns `Io` once, as on `vda`.

**Timeouts and recovery** (I3, I10).
- Budgets: I/O 30 s, admin 10 s, enable/disable `CAP.TO`.
- On an I/O timeout, under `io_lock_`:
  1. **Check `CSTS`.** `0xFFFFFFFF` means the device is gone and `CFS`=1 means a fatal error; both jump to step 3.
  2. **Abort** (admin 08h, `CDW10` = CID << 16 | SQID 1). Wait for the Abort's completion within the admin budget, then up to 1 s for the original CQE ("aborted", SC 07h).
     - If the original completed in any way, the bounce buffer is free and the command returns `Io`.
  3. **Controller reset.**
     - Clear `CC.EN` and wait for `RDY`=0. After this the controller does no more DMA, so the buffer is free.
     - Zero the queues and reset the phases. Redo steps 3-8 of bring-up.
     - Re-identify each registered namespace and check that `NSZE` and the LBA format are unchanged.
     - The failed command returns `Io`, and later commands work.
     - Log `Storage: nvme0: command timed out; controller reset`.
  4. **Dead.** A failed reset, or a second reset within 60 s, makes the controller dead.
     - `dead_` is set, `CC.EN` is cleared, and `Storage::Remove(disk)` runs for each registered namespace, so volumes go dead and give EIO as on unplug.
     - `Gone()` returns true afterwards.
     - Log `Storage: nvme0: controller failed; its disks are gone`.

**Shutdown.**
- `ShutdownControllers` runs after `FlushAll` on power-off and on reboot.
- It sets `shutting_down_` under `io_lock_`; later commands fail `Io`.
- It writes `CC.SHN`=01, then waits for `CSTS.SHST`=10 within max(5 s, `RTD3E`), capped at 60 s.
- Log `Storage: nvme0: shutdown complete`, or a warning on timeout. This is what keeps the drive's "unsafe shutdowns" counter still (I16).

### 1.3 AHCI (`storage/ahci/`, `storage/ata/`)

**HBA bring-up** (`Hba::Start`, on the worker):
1. Map ABAR (BAR5). Read `CAP`: `NP`+1, `NCS`+1, `SSS` (27), `SAM` (18), `SNCQ` (30, ignored), `S64A` (31). Also read `CAP2`, `PI` and `VS`.
2. **BIOS/OS handoff** if `CAP2.BOH`:
   - Set `BOHC.OOS` and wait up to 25 ms for `BOHC.BOS`=0.
   - If `BOHC.BB` is set, wait up to 2 s more.
   - On timeout, log and continue (as Linux does).
3. Set `GHC.AE`. **Stop every implemented port** (I6):
   - Clear `PxCMD.ST` and wait for `CR`=0 (500 ms).
   - Clear `FRE` and wait for `FR`=0 (500 ms).
4. **HBA reset:** set `GHC.HR`, wait for `HR`=0 (1 s), then set `GHC.AE` again. A timeout refuses the HBA.
5. Per implemented port, allocate one 4 KiB command page: command list at 0 (32 × 32 B; only slot 0 is used), FIS area at 0x400, command table at 0x500 (0x80 header + 8 PRDT entries).
   - The limit is 4 GiB when `S64A`=0, otherwise none (I17).
   - Write `PxCLB`/`PxCLBU` and `PxFB`/`PxFBU` while the port is stopped.
   - Clear `PxSERR` (write all ones) and `PxIS`. Set `PxCMD.FRE`.
6. **Spin-up and link.**
   - If `CAP.SSS`, set `PxCMD.SUD` on one port at a time, and only after the previous port's link is settled (staggered).
   - Wait up to 1 s for `PxSSTS.DET`=3. `DET`=1 gets one COMRESET.
   - No link means no device (silently skipped).
7. Wait up to 10 s for `PxTFD.STS` with `BSY` and `DRQ` clear (HDD spin-up), then read `PxSIG`:
   - `0x00000101`: an ATA disk, accepted.
   - `0xEB140101` (ATAPI), `0x96690101` (port multiplier) or `0xC33C0101` (SEMB) are refused with a log line, such as `Storage: AHCI 00:05.0 port 2: ATAPI device not supported`.
8. If not polling, set `PxIE` = DHRS | PSS | TFES | HBFS | HBDS | IFS | OFS | PRCS. After all ports are set up, set `GHC.IE`. Then set `PxCMD.ST`.
9. **IDENTIFY DEVICE** (ECh, PIO-in, one 512-byte PRD into the bounce buffer). Parsed by `Ata::ParseIdentify`:
   - Requires LBA48: word 83 bit 10, and word 86 bit 10 if set. A disk without it is refused.
   - Sector count from words 100-103.
   - Logical sector size: if word 106 bits 14 and 12 are set, words 117-118 give it in words. Only 512 and 4096 are accepted.
   - Model (27-46) and serial (10-19), byte-swapped.
   - Write cache: word 82 bit 5 is support, word 85 bit 5 is enabled.
   - Flush: FLUSH CACHE EXT is word 83 bit 13, plain FLUSH CACHE is bit 12.
   - Integrity: when word 255's low byte is `A5h`, the checksum must hold; otherwise refused.
10. Policy (1.6), register as `DiskKind::Ahci`, then scan.
    - Log: `Storage: sda: AHCI 00:05.0 port 0, "QEMU HARDDISK" "feather-sata0", 163840 KiB, 512-byte sectors, write cache, rw`

**Commands** (slot 0, one PRD over the bounce buffer).
- The bounce buffer is 128 KiB per disk port: 256 sectors of 512 bytes, or 32 of 4096. That is far below the 65536-sector count limit and the 4 MiB DBC limit.
- The H2D Register FIS is type 27h with C=1, command, LBA 47:0, device 40h, count 15:0.
- The command header has `CFL`=5, `W` for writes, `PRDTL`=1 and `PRDBC`=0. The PRD has `DBA`, and `DBC` = bytes − 1 (bit 0 always set, I13).
- Commands used: READ DMA EXT (25h), WRITE DMA EXT (35h), FLUSH CACHE EXT (EAh, or E7h when only that is supported).
  - Flush is sent only when the write cache is enabled; otherwise it succeeds at once (I8).
- Issue: `ProducerBarrier()`, then `PxCI` = 1.
- Done: `PxCI` bit 0 is clear and no error bit is set in `PxIS`. After `ConsumerBarrier()`, a read is good only if `PRDBC` = bytes (I7).
- `PxIS` and `IS.IPS[port]` are cleared by the waiter.

**NCQ: not in M16.**
- `DiskDriver` is synchronous and `io_lock_` keeps one command per port, so NCQ (READ/WRITE FPDMA QUEUED, `PxSACT`) gives no gain.
- NCQ error recovery is the hardest part of AHCI: READ LOG EXT page 10h, then aborting every outstanding tag.
- Open question 3.

**Error recovery** (AHCI 6.2.2.1, non-queued). On TFES, HBFS, HBDS or IFS, or on a timeout (30 s; FLUSH 60 s):
1. Clear `PxCMD.ST` and wait for `CR`=0. Once `CR`=0 the HBA does no more DMA into the port's buffers (I3).
2. Clear `PxSERR` and `PxIS`.
3. If `PxTFD` still has `BSY` or `DRQ`, do a **COMRESET**: `PxSCTL.DET`=1 for ≥ 1 ms (use 10 ms), then `DET`=0, wait for `PxSSTS.DET`=3 (1 s), then wait for `BSY` clear (10 s).
4. Set `ST` again. The command returns `Io` and is not retried. Log `Storage: sda: <command> failed (status 51h error 04h); port recovered`.
5. The port is dead after any of:
   - three recoveries within 60 s;
   - a COMRESET with no link;
   - a changed signature;
   - `PxIS.PRCS` (PhyRdy change: hot-unplug is not supported).
   A dead port gets `Storage::Remove(disk)`; its volumes give EIO.

**Interrupts.** One MSI per HBA. The handler reads `IS` and calls `Wake(&port[i])` for each set bit. It writes nothing.

**Shutdown.** At power-off only (not reboot), each live port with a disk gets STANDBY IMMEDIATE (E0h, 30 s), after `FlushAll`. This parks the heads instead of an emergency unload. `shutting_down_` then refuses further commands.

### 1.4 Concurrency, waiting and lock order

**Who runs what:**
- Filesystem threads (syscalls), `Writeback`, `eject` (refused: these disks are not removable) and the **storage worker** (probe, then register, then scan) call `Read`/`Write`/`Flush` and hold the controller's or port's `io_lock_`.
- The MSI handler (boot CPU, interrupt context) only calls `Environment::Wake`.
- Recovery (abort, reset, COMRESET) runs on the task that timed out, still holding `io_lock_`. No manager task is needed, because nothing else must run for recovery to finish.

**Lock order.** Extends "Storage locking" in `docs/development.md`. The new locks slot in at the existing levels:
1. `Files` locks and the `/proc` volume lock (existing).
2. Volume locks (existing).
3. `Usb::topology_lock` (existing; never nested with the locks below).
4. `Drive::io_lock_` (USB), `Nvme::Controller::io_lock_`, `Ahci::Port::io_lock_` (all `Sync::Mutex`, held across a command, its waits and its recovery). A task holds at most one of them.
   - 4a. `Nvme::Controller::admin_lock_` (`Sync::Mutex`), taken after `io_lock_` (Abort, reset) or alone (probe).
5. `Storage::registry_lock`, `Drivers::volumes_lock`, `mount_lock` (spinlocks, existing). `Storage::Remove` on a dead controller is called with `io_lock_` held: 4 before 5, as allowed.
6. Environment `wait_lock`, then the controller's `completion_lock_` (an interrupt-saving spinlock that guards the CQ head, phase and in-flight record, or the port's completion record). `Ready` takes it inside `WaitUntil`, which is the same nesting as USB's `state_lock_`.
7. Leaves: worker `queue_lock`, `Arch::Msi` slot lock, the page cache's host lock (never held across a device call), the heap.

**Why no deadlock.**
- The handler takes only `wait_lock`.
- A waiter holding `io_lock_` waits only for the device and its own deadlines, never for another task.
- The worker can block on `io_lock_` behind a filesystem thread's recovery. That recovery is bounded (I10).
- `Files::Quiesce` at shutdown holds every volume lock and flushes through `io_lock_`; nothing it waits for needs a volume lock.

**Lifetimes.**
- NVMe controllers, namespaces, AHCI HBAs and ports are allocated once and never freed: no hot-plug.
- `DiskDriver::Release` is a no-op counter. A dead controller keeps its objects; `Gone()` is true.

### 1.5 DMA and memory

| Object | Size | Limit | Lifetime |
|---|---|---|---|
| NVMe admin SQ / CQ | 4 KiB each | none | per controller; zeroed again on reset |
| NVMe I/O SQ / CQ | 4 KiB each (depth ≤ 32 × 64 B / 16 B) | none | per controller |
| NVMe identify page | 4 KiB | none | per controller |
| NVMe PRP list | 4 KiB, filled once | none | per controller |
| NVMe bounce | `B` ≤ 128 KiB | none | per controller (shared by its namespaces under `io_lock_`) |
| AHCI command page | 4 KiB per implemented port | 4 GiB if `S64A`=0 | per port |
| AHCI bounce | 128 KiB per port with a disk | 4 GiB if `S64A`=0 | per port |

**Coherency.**
- QEMU `virt` is coherent. M14 refuses a non-coherent host bridge, so no cache maintenance is written.
- AArch64 ordering:
  - BARs are mapped Device-nGnRE by `MapDevice`.
  - `ProducerBarrier()` (`dmb oshst`) comes before every doorbell, `PxCI` write and `CC` write that follows memory writes.
  - `ConsumerBarrier()` (`dmb oshld`) comes after a phase tag or `PxCI` shows completion, before the CQE body or bounce data is read.
- x86-64 MMIO is uncached and strongly ordered; compiler barriers suffice.
- Real non-coherent AArch64 PCIe (some Raspberry Pi configurations) stays unsupported (M14's rule).

### 1.6 Real hardware vs QEMU: the write policy

**Boot option `storage=`** (`BootOptions::ParseStorage`; the last one wins; any other value counts as absent):
- `storage=rw`: every NVMe/AHCI disk is writable.
- `storage=ro`: every NVMe/AHCI disk is read-only, even in QEMU. This is how QEMU tests the real-hardware path.
- Absent: auto.

**Auto.**
- A controller is QEMU's when its PCI config dword 0x2C has subsystem vendor `0x1AF4` and subsystem `0x1100`.
  - QEMU stamps these on every emulated PCI device (`nvme` 1B36:0010, `ich9-ahci` 8086:2922).
  - No physical controller carries Red Hat/Qumranet's subsystem ID.
  - A passed-through real controller (vfio) keeps its own IDs and stays read-only, which is the safe answer.
- QEMU's controllers are writable; everything else is read-only.

**Pure function** (`storage/write_policy.{h,cpp}`, host-tested):

```cpp
enum class WritePolicy : uint8_t { Allowed, ReadOnlyHardware, ReadOnlyOption, AllowedByOption };
WritePolicy DecideWrites(BootOptions::StorageMode mode, uint16_t subsystem_vendor, uint16_t subsystem);
```

**Enforcement** (I1). The policy is decided once per controller at probe, before any disk registers. It ends up as `DiskInfo::read_only` = true with `read_only_reason = Policy`, so it is in place before the first `Register`. Then:
- `Disk::Transfer` refuses writes with `ReadOnly` (`disk.cpp:135`).
- `Disk::Flush` skips the driver.
- The driver's own `Write`/`Flush` refuse before touching a queue.
- The filesystem layer mounts read-only (`MediaAllowsWrites`): `mount -o remount,rw` gives EROFS. A dirty ext3/ext4 mounts read-only without replay (`ext2.cpp:1048-1065`).
- Nothing else that writes exists: no TRIM, no Set Features for the write cache, no SMART writes.

**Log lines:**
- `KERN/I: Storage: nvme0: QEMU controller, writes allowed`
- `KERN/I: Storage: nvme0: real hardware, read-only (boot with storage=rw to write)`
- `KERN/I: Storage: nvme0: storage=ro, read-only`
- `KERN/W: Storage: nvme0: storage=rw, writes allowed on real hardware`

`/proc/partitions` ends the disk line with `ro`.

### 1.7 Naming and the boot disk

- **Names:** `nvme0n1` and `nvme0n1p1` for NVMe; `sda` and `sda1` for AHCI (shared letters, 1.1).
- `mount -t ext4 nvme0n1p4 /mnt` works for any disk that is not the boot disk.
- The boot disk is whichever disk `root=` names, or `vda` by default. Its volumes are in boot slots 1-16 and are registered under its own names (`nvme0n1p1`…). The worker scans every other disk into slots 17-32, `vda` included when it is not the boot disk.
- **Root:**
  - `root=vdaN`, `root=sd<letter>N` (AHCI) and `root=nvme<c>n<ns>pN` are accepted. 1.9 has the grammar, the probe order, the default root and the read-only interplay.
  - USB disks enumerate after the root mount, so `root=sdbN` naming a USB stick finds no disk and falls back (edge cases).

### 1.8 Write order and durability

- Each `Disk::Write` becomes commands of at most 128 KiB, in LBA order, one at a time.
- It returns only after each completed successfully (I7, I9). Commands are never merged or reordered.

**Durability points:** as in M19 Part 2 1.6 (`sync`, `umount`, shutdown). `Disk::Flush` maps to NVMe Flush (when `VWC`) or FLUSH CACHE EXT (when the write cache is enabled). At shutdown, `FlushAll` comes first, then `ShutdownControllers`.

**What a crash or power loss leaves:**

| Point | NVMe | AHCI (SATA) |
|---|---|---|
| before the SQ doorbell / `PxCI` write | nothing of the command | nothing |
| after the doorbell, before completion | any subset of the command's LBAs; each LBA is old or new (`AWUPF` ≥ 0 means one LBA is atomic) | any subset; an HDD may tear a sector on power loss |
| after completion, with a volatile cache (`VWC`=1 / WCE) | in the drive's cache: lost on power loss until a Flush | same, until FLUSH CACHE EXT |
| after completion, no volatile cache | durable | durable |
| after Flush / FLUSH CACHE EXT completed | durable (the drive's promise) | durable |
| after `CC.SHN` completed / STANDBY IMMEDIATE | durable, a clean shutdown | durable, heads parked |
| timeout, then abort or reset | unknown subset; the command returned EIO | unknown subset; EIO |

At the filesystem level this is the same as on `vda`: FAT16 has no journal (`fsck.fat` repairs), and ext3/ext4 replay at the next read-write mount.

### 1.9 Root on any disk (Part D)

**Probe before the root: the timer moves earlier, not a counter clock.** `kernel_runtime.cpp` runs, in order:
1. `Run`: `Process::Initialize`, `Arch::Power::Initialize`, `InitializeDisplay`, `MountInitramfs`;
2. `LoadTestExecutable`, which calls `Scheduler::Initialize` at `:194`;
3. `LogPciDevices`;
4. `MountAndVerifyDisk`;
5. `RunConsole`, which starts the timer at `:490` and then the CPUs, the network, `Writeback`, USB and init.

Step D2 moves `Time::InitializeTimer(100)`, `WaitForNextTick()` and the `Timer started at 100 Hz` line to the start of `MountAndVerifyDisk`, and removes them from `RunConsole`. Reasons:
- The scheduler already exists at that point. The user-preemption test already runs the timer there (`:198`), so a timer before the disk is a path that already boots.
- Every wait in the drivers (`Environment::WaitUntil` with deadline ticks, `Scheduler::SleepUntil`, the worker the boot task waits for) is written against the tick. The same goes for M19's USB drive and xHCI. A TSC/CNTVCT counter clock could only busy-wait. It would need a second `Environment` with no sleeping, a calibrated frequency on x86-64, and a second code path for every timeout that the matrix would test only at boot.
- MSI delivery works as soon as interrupts are enabled, which the timer needs anyway.
- Secondary CPUs still start in `RunConsole` (`StartSecondaryCpus`), at the boot CPU's rate. Their order relative to the timer is unchanged.
- The smoke harness only checks that the timer line is present (`tools/smoke/cases/normal_boot.py:49`), not where it is.

**`MountAndVerifyDisk` from D2 on:**
1. Start the timer.
2. `InitializeCache`, `Storage::Initialize`, `AttachStorage`. Then `Storage::DeferScans(true)`: from here on, `Scan(disk)` only marks the disk pending.
3. virtio-blk: `BlockDevice::Initialize` and `RegisterVirtioDisk`, now optional (no virtio disk no longer means a RAM root). `RegisterVirtioDisk` also calls `Scan`, which is deferred.
4. `Storage::StartControllers(platform_data)`, then `WaitForControllers(now + 60 s)`. On timeout: `Storage: nvme0 still probing; the root is chosen without it`. A late disk registers afterwards and is scanned as an "other" disk.
5. Choose the boot disk (below), then `Storage::SetBootDisk(disk)`, which takes a reference that is never dropped.
6. `VFS::MountBlockDevice(requested.partition, &honored)` on the boot disk, exactly as today: boot slots, `ChooseRoot`, read-only fallback.
7. `Storage::DeferScans(false)` posts a scan job for every pending disk other than the boot disk.
8. With no boot disk at all: `MountRamRoot` (today's no-disk path).

**`root=` grammar** (`BootOptions::ParseRoot`; the last one wins):
- `root=` followed by a disk name and a partition number from 1 to 9999 with no leading zero. The disk name is one of:
  - `vd[a-z]`
  - `sd[a-z]`
  - `nvme<c>n<ns>` followed by `p`
- `<c>` and `<ns>` are decimal with no leading zero; `<ns>` ≥ 1.
- Anything else is `Malformed`. That includes a whole disk (`root=sda`, `root=nvme0n1`), `nvme0n1p0`, `nvme0n1-2`, `sda2x` and a name of 16 characters or more.
- `root=vda3` parses to the same `{Partition, 3}` as today, plus `disk = "vda"`.

**Choosing the boot disk:**
- `root=` names a disk that is registered after step 4: that disk.
  - If none of its partitions is usable, today's rule applies inside the disk: "is not a usable partition, using the default root" mounts the disk's lowest-numbered supported partition.
  - If the disk has no supported volume at all, it panics with today's message, naming the disk: `No FAT16, ext2, ext3 or ext4 root filesystem on nvme0n1`. This is today's behaviour for `vda`.
- `root=` names a disk that does not exist (controller missing, failed at probe, a USB name):
  - `KERN/W: VFS: root=nvme0n1p2: no disk nvme0n1, using the default root`;
  - then the default.
- `root=` absent or malformed: the default. Malformed keeps today's warning, now reading "such as vda1 or nvme0n1p2".
- **Default root:** `vda`'s lowest-numbered partition holding a supported filesystem (`ChooseRoot(…, 0)`), unchanged. With no `vda`, the RAM root. An NVMe or AHCI disk is never chosen without `root=`, for two reasons:
  - Every existing case stays exactly as it is.
  - A disk FeatherOS did not make (a Linux ext4 partition) has a `/sbin/init` that `RootInit` would try to run. Picking a foreign root must be an explicit choice.

**Write policy and the root.**
- A root on a read-only disk (`storage=ro`, or real hardware under auto) takes today's read-only root path. `PrepareMount(ReadWrite)` falls back to read-only through `MediaAllowsWrites`, and `/etc` is the initramfs's RAM copy.
- The message gives the reason, taken from `BootDisk()->Info().read_only_reason`:
  - `VFS: / is nvme0n1p1 ext4, read-only: storage=ro`
  - `VFS: / is nvme0n1p1 ext4, read-only: real hardware (storage=rw to write)`
  - `VFS: / is vda1 ext4, read-only: the volume refused writes` (unchanged otherwise)
- A dirty ext3/ext4 root on a read-only disk mounts without journal replay (existing warning).

**Boot-disk lifetime.**
- `SetBootDisk` retains the disk for the kernel's life.
- If the boot disk's controller dies (`Storage::Remove`), the removal handler marks boot slots 1-16 dead, as it does other slots. `/` then fails EIO and turns read-only in `/proc/mounts`. Slots 1-16 are never released.
- Log `VFS: the root disk nvme0n1 is gone; / gives EIO`.
- Shutdown still runs `Quiesce`, `FlushAll` (which reports the failure) and `ShutdownControllers`.

**Slot sources.**
- `Drivers::SetBootDisk(Storage::Disk&)` fills `boot_sources[17][MaximumSourceLength]` with `PartitionName(disk.Name(), n)`. Index 0 is the disk itself.
- `PartitionSource(number)` returns these. It falls back to the `vda` list before `SetBootDisk`, so host tests and the no-controller path keep today's names.

## 3. Invariants

**Policy and read-only**
- **I1.** No write command reaches a controller whose disk is read-only. That covers NVMe Write, Flush, Write Zeroes and DSM, and ATA WRITE DMA EXT and FLUSH CACHE EXT. `Disk::Transfer` refuses, `Disk::Flush` skips, and the driver refuses again. **Riskiest.**
- **I2.** The policy is `DecideWrites(mode, subsystem)`, decided once per controller before its first `Register`, and never changed for a registered disk.

**DMA and queues**
- **I3.** A bounce buffer, PRP list, command table or queue page is reused or freed only after its completion was reaped, or after the device was stopped (NVMe `CSTS.RDY`=0, AHCI `PxCMD.CR`=0). **Riskiest.**
- **I4.** A completion finishes only the command with its CID. Stale CQEs are consumed and dropped. The CQ head, phase and head doorbell always advance.
- **I5.** Doorbell, `PxCI` and `CC.EN` writes come after the memory they publish (`ProducerBarrier`). Completion data is read after the completion signal (`ConsumerBarrier`).
- **I6.** `AQA`/`ASQ`/`ACQ` are written only while `CC.EN`=0 and `RDY`=0. `PxCLB`/`PxFB` are written only while ST, CR, FRE and FR are all 0. A controller left running by firmware is disabled first.

**Results and order**
- **I7.** `Read`/`Write` succeed only when every command of the request reported success. For AHCI reads, `PRDBC` must equal the bytes.
- **I8.** `Flush` success means a Flush (when `VWC`) or FLUSH CACHE EXT (when WCE) completed after every earlier write completed. Without a volatile cache, no command is sent.
- **I9.** One command at a time per NVMe controller and per AHCI port, in the caller's order.

**Recovery and lifetime**
- **I10.** Every call returns within the bounded recovery ladder. A dead controller or port removes its disks; later calls give `Io`.

**Acceptance and limits**
- **I11.** NVMe registers only active namespaces with `NSZE` > 0, `LBADS` ∈ {9, 12}, `MS` = 0 and no PI.
- **I12.** AHCI registers only signature `0x00000101` with LBA48 and a 512 or 4096-byte logical sector.
- **I13.** A command moves at most `max_transfer_bytes`. PRP entries after the first are page-aligned and the list fits one page. A PRD's `DBC` is bytes − 1 with bit 0 set.

**Concurrency, naming and shutdown**
- **I14.** Lock order is 1.4. The interrupt handler takes only `wait_lock`.
- **I15.** Names are unique: `nvme<c>n<nsid>`; `sd` letters are lowest-free across USB and AHCI.
- **I16.** After `ShutdownControllers` starts, no command is issued. NVMe gets `CC.SHN`=01 and a bounded wait for `SHST`=10.
- **I17.** With `S64A`=0 every AHCI DMA address is below 4 GiB.

**Root on any disk**
- **I18.** `ParseRoot` accepts exactly the 1.9 grammar. `root=vdaN` parses as before.
- **I19.** The boot disk is the disk `root=` names, if it is registered when `WaitForControllers` returns; otherwise `vda`; otherwise none (RAM root). Without `root=`, an NVMe or AHCI disk is never the boot disk.
- **I20.** The boot disk's volumes live only in slots 1-16 and carry its names. Every other disk's volumes live only in slots 17-32. No disk has volumes in both, because scans stay deferred until the boot disk is set.
- **I21.** The root is chosen only after every controller probe finished or the 60 s deadline passed. A late disk is scanned as an other disk and never becomes the root.
- **I22.** A root on a read-only disk mounts read-only and `/etc` is the RAM copy. No write reaches its controller (I1). The log line gives the reason.
- **I23.** No controller wait happens before the timer runs: `StartControllers` checks `TimerRunning()`.
- **I24.** The boot disk is retained for the kernel's life. Its removal makes boot slots dead (EIO) and never frees them.

## 4. Edge cases

| Case | Behaviour |
|---|---|
| NVMe `CSTS` reads `0xFFFFFFFF` | dead now; disks removed; `Storage: nvme0: controller is gone` |
| `CAP.MPSMIN` > 0, no NVM command set | refused at probe |
| `CC.EN` never clears or `RDY` never sets | refused, `controller did not disable` / `did not become ready` |
| Admin command timeout during probe | `CC.EN` cleared, refused |
| `NN` = 0 or no active namespace | `Storage: nvme0: no namespaces`; controller disabled |
| Namespace with metadata, PI, `LBADS` not 9 or 12, or `NSZE` 0 | logged and skipped |
| 4096-byte namespace holding FAT16 | `no supported filesystem` (existing core rule) |
| `MDTS` = 1 (8 KiB) | `max_transfer_bytes` = 8 KiB; `Disk::Transfer` splits |
| No MSI vector left | polling, logged |
| Controller already enabled by SeaBIOS/OVMF | I6 disable path |
| Two NVMe controllers | `nvme0`, `nvme1` in PCI order |
| Registry full (16) | `Storage: nvme0n3: disk registry full` |
| AHCI BOHC never released | logged, continue |
| `GHC.HR` never clears | HBA refused |
| Port link up, `BSY` for 10 s | `device not ready`, skipped |
| ATAPI, port multiplier, SEMB | logged, refused |
| IDENTIFY without LBA48, or a bad checksum | refused |
| TFES on a read | port recovered, `Io`, EIO |
| `PxIS.PRCS` | port dead, disk removed |
| Intel RST RAID mode (class 01/04) | logged with a hint |
| `storage=rw` on real hardware | writable; warning per controller |
| `storage=bogus` | auto |
| `eject nvme0n1` / `eject sda` (AHCI) | ENOTSUP |
| Write to a policy-read-only volume | EROFS; `remount,rw` gives EROFS |
| Dirty ext3/ext4 on a read-only disk | mounts read-only without replay |
| `usb=off` | NVMe and AHCI still work |
| Shutdown with a dead controller | skipped |
| `root=nvme0n1p2`, no NVMe controller, or it failed at probe | `VFS: root=nvme0n1p2: no disk nvme0n1, using the default root`; `vda`'s default, else RAM root |
| `root=sdb2` naming a USB stick | no disk at root time (USB starts later): same fallback |
| `root=nvme0n1p9`, partition missing or unsupported | `root=nvme0n1p9 is not a usable partition, using the default root`; the lowest supported partition of `nvme0n1` (today's rule, on the named disk) |
| Named disk has no supported volume at all | panic `No FAT16, ext2, ext3 or ext4 root filesystem on nvme0n1` (today's `vda` behaviour) |
| `root=nvme0n1`, `root=sda`, `root=nvme0n1p0`, `root=nvme01n1p1` | malformed: warning, default root |
| Root on a 4096-byte namespace | ext2/3/4 work; FAT16 there is "not a usable partition" |
| Root disk read-only (`storage=ro`, or real hardware under auto) | `/ is … read-only: storage=ro` (or the real-hardware reason); `/etc` is the RAM copy |
| A controller still probing at the 60 s deadline | root chosen without it; its disks register and are scanned later as other disks |
| Root controller dies after boot | boot slots dead, `/` gives EIO, `VFS: the root disk nvme0n1 is gone`; shutdown reports the flush failure |
| No `root=`, NVMe present, no `vda` | RAM root; NVMe volumes listed and mountable |
| `root=vda1` with NVMe and AHCI present | unchanged root; NVMe/AHCI volumes in slots 17-32 |

## 7. Open questions (answered by the user, 2026-11-23)

1. **Root on NVMe or AHCI:** yes, in M16. `root=nvme0n1p2` and `root=sda2` work on both architectures, next to `root=vdaN`. This is Part D, with 1.9, I18-I24 and T31-T42. Without `root=` the default root stays on `vda`.
2. **Boot option:** `storage=ro|rw`, absent = auto (QEMU subsystem 1AF4:1100 writable, everything else read-only), global.
3. **NCQ and several I/O queues:** later.
4. **Real hardware:** QEMU only. No real-hardware step and no laptop item in "Done when". The read-only default protects a later laptop run.
5. **Bounce buffers:** 128 KiB per NVMe controller and per AHCI port, capped by MDTS.
