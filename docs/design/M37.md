# M37: pixels, design tokens and artwork (design)

**Scope.** Everything needed to draw the prototype's look into memory, and a first picture of it on a real screen. User space and host tools only: nothing here needs M35 or M36. Checked against the code on `main` at `8b9ba14` and the prototype in `docs/design/gui/`:

- **Graphics library** (`src/user/graphics/`, namespace `FeatherOS::Graphics`, in `featheros_user_support` and the host tests):
  - `Surface`: owned XRGB8888 pixels, opaque fill, rectangle outline, blit, colour-keyed blit, text.
  - `Font`: FFNT files; glyph coverage is 0 to 15, blended over the pixel beneath with `Text::Blend`.
  - `DirtyRegion`: at most 8 rectangles. `Display`: one program owns the screen. `TileSheet`: tiles drawn as text.
- **Fonts and their tooling** are the model for this milestone's files: `tools/fonts/` generates, the outputs in `initramfs/fonts/` are committed with `SHA256SUMS`, CTest `fonts.files` checks them and `fonts.reproducible` regenerates and compares, and `build.sh` copies the folder into `/system`.
- **The prototype** holds 45 glyph icons (its `P` table also has an empty `feather` entry; the feather is its own drawing) as SVG path strings (commands `M L H V C S A Z` in both cases) on a 24-unit grid with a 1.75-unit round stroke, the feather on a 64-unit grid, the wallpaper on a 1600x1000 grid, 8 theme blocks, the accent table, and 8 distinct shadows. It draws the glyphs at about 20 sizes between 12 and 64 px. The 13 pointers are SVG files in `docs/design/gui/cursors/svg/`, with PNG renders at 24, 32 and 48 px and hotspots in `cursors.json`.

This milestone adds, in order:
1. The design tokens as one JSON file and a generated C++ table.
2. The pixel library: regions, alpha, a canvas with clipping, rounded shapes, and a renderer for outlines (fills and round strokes) with a cache.
3. The artwork as outlines in one small file, and the drawing of icons, app tiles, pointers, shadows and the wallpaper from it at any size.
4. `uicard`, a test card on `/dev/fb0`, checked byte for byte against a host render of the same code.

Left out: widgets and layout (M41), the compositor (M39), UI scales above 100% (the drawing code takes any size already; the metrics come in M45), image files, gradients, text shaping, a Swift module for the new headers, and the boot animation's frames (M38, which reuses this renderer on the host).

**Done when:**
1. `./build.sh unit-test` passes, with the new `gui.*` CTests.
2. `bash tools/quality.sh check` passes.
3. `tools/check.sh --arch both --modes "PIXELS GRAPHICS FONTS DUNGEON SHELL"` passes.
4. `tools/check.sh --arch both --matrix` passes, including the new cases.
5. The measurement table in section 7 is filled in.

## Decisions

**User:**
- **2026-11-25:** the toolkit and everything under it is C++.
- **2026-11-26: artwork is drawn live.** FeatherOS ships outlines and draws icons, app tiles, pointers and shadows itself, at any size, with a cache. No bitmaps of them are pre-rendered. This replaces the bitmap atlas that `HANDOFF.md` planned, because the prototype uses about 20 icon sizes before any UI scaling. Only the boot animation's frames stay pre-rendered (M38), since the kernel draws them.

**Design:**

- **D1. One renderer, in C++, used everywhere.** The same code draws on FeatherOS and on the host, so a host tool can produce the picture a test expects, and M38 can produce its boot frames. Python only prepares data: tokens and outlines.
- **D2. Integer arithmetic only in every pixel path.** No floating point, so x86-64, AArch64 and the host produce the same bytes. Products that need more than 64 bits use 128-bit multiplication and comparison, never 128-bit division (AArch64 has no compiler runtime).
- **D3. Two surface formats in one class.** `Surface` gains a format: opaque XRGB8888 (today's, the default) or premultiplied ARGB8888. An 8-bit coverage `Mask` is its own small class. Existing programs are untouched.
- **D4. One blend rule.** Every blend rounds with `Div255(x) = (x + 127) / 255`, the rule `Text::Blend` already uses, so text drawn through the canvas equals text drawn today.
- **D5. Outlines are flattened on the host.** `tools/gui/outlines.py` turns curves and arcs into polylines of integer points and writes them to one file. FeatherOS never parses SVG and never evaluates a curve. The script uses only `+ - * /` and `sqrt` on doubles, so every host writes the same bytes.
- **D6. Coverage comes from an 8x8 sample grid per pixel.** A sample is inside a fill by the non-zero winding rule, and inside a stroke when it is within half the stroke's width of the polyline, which gives round caps and joins. All strokes in the artwork are round, so nothing else is implemented.
- **D7. Shadows are computed at load,** as a rounded rectangle blurred by three box passes, kept as a 9-slice mask and tinted with the theme's shadow colour.
- **D8. The graphics library knows nothing about themes.** Tokens, and the helpers that draw a named icon, an app tile, a pointer or the wallpaper, live in a new `src/user/ui/` (namespace `FeatherOS::UI`), which the toolkit joins in M41.
- **D9. Host tools need only Python's standard library.** No rasterizer, no image library, no Chrome. The pointer check decodes the design's PNGs with `zlib`.

A failure is reported; the script never changes a colour.

### 1.2 Regions (step B1)

`Graphics::Region` (`region.{h,cpp}`): a set of pixels as y-x banded rectangles in a `std::vector`.

- Operations: `Add(Rectangle)`, `Add(const Region&)`, `Subtract`, `Intersect`, `Translate`, `Clear`, `Empty`, `Bounds`, `Contains(x, y)`, `RectangleCount`, `RectangleAt`.
- **Canonical form:** bands are sorted by y and do not overlap; within a band, rectangles are sorted by x and neither overlap nor touch; two adjacent bands with the same spans are one band. So two regions covering the same pixels are equal member by member.
- `DirtyRegion` stays as it is for the existing programs.

### 1.3 Colour, formats and the canvas (step B2)

- `Graphics::Color`: a `uint32_t` `0xAARRGGBB` with straight alpha, with `Rgb(r, g, b)`, `WithAlpha(color, alpha)` and `Premultiply`.
- `Surface(width, height, PixelFormat format = PixelFormat::Xrgb)`; `Format()`. On an XRGB surface the top byte stays 0.
- `Graphics::Mask` (`mask.{h,cpp}`): width, height, one byte of coverage per pixel.
- `Graphics::Canvas` (`canvas.{h,cpp}`) draws into one `Surface`:
  - State: an origin and a clip rectangle, with `Save()` and `Restore()` (depth 16). `ClipTo(Rectangle)` intersects; `Translate(dx, dy)` moves the origin.
  - `FillRectangle(Rectangle, Color)`: a copy when the colour is opaque, a blend otherwise.
  - `DrawSurface(const Surface&, x, y)` and `DrawSurfacePart(...)`: a copy for an XRGB source, source-over for a premultiplied one.
  - `DrawSurfaceFaded(const Surface&, x, y, uint8_t opacity)`.
  - `DrawMask(const Mask&, x, y, Color)`: the colour through the coverage.
  - `DrawText(const Font&, x, y, const char* utf8, Color)` and `DrawTextEllipsis(const Font&, Rectangle, const char* utf8, Color)`, which ends a text that does not fit with U+2026.
- **Blend rules** (D4), per channel, with `a` the source alpha after coverage and opacity:
  - straight colour over XRGB: `d = Div255(s * a + d * (255 - a))`;
  - premultiplied over XRGB: `d = s + Div255(d * (255 - a))`;
  - onto a premultiplied target, the same rule is applied to the alpha channel too;
  - coverage and opacity scale the source alpha first: `a = Div255(color_alpha * coverage)`.

### 1.4 Rounded shapes (step B3)

- `Canvas::FillRoundedRectangle(Rectangle, int32_t radius, Color)` and `StrokeRoundedRectangle(Rectangle, int32_t radius, int32_t width, Color)`.
- The body is rectangle fills. Each corner uses a quarter-disc `Mask` for its radius, computed once and cached, with the 8x8 sample rule of D6. A stroke's corner is the outer quarter-disc's coverage less the inner one's.
- A radius of half the height gives pills and circles (switches, radios, slider thumbs, badges). A radius larger than half the smaller side is cut to it.
- `DrawHorizontalLine` and `DrawVerticalLine` are 1 px rectangle fills.

### 1.5 Outlines and their renderer (step B4)

**The file** (`/system/gui/outlines.fvo`, magic `FVOL`, little-endian, FNV-1a checksum as in FFNT):

- A header (magic, version 1, file size, drawing count, checksum), a table of drawings sorted by name, then the data.
- **A drawing** has a name of at most 31 characters, a view box (width and height in units), an optional hotspot, and a list of items.
- **An item** is a fill or a stroke with: a paint, an opacity 0 to 255, for a stroke its width, and one or more polylines, each open or closed.
- **A paint** is `Current` (the caller's colour), `Fixed` (an ARGB value in the file) or `Slot` 0 to 7 (a colour the caller passes, such as the accent or a wallpaper tone).
- **Points and widths** are `int32_t` in 1/256 of a unit.
- The loader refuses a damaged file with a status per reason, as `FontView::Parse` does: size, magic, version, length, checksum, an unsorted or duplicate name, an item that runs past its drawing, a polyline with fewer than 2 points, a paint or slot out of range. A file over 4 MiB is refused, and so is one with more than 65536 points in all or more than 8192 in one drawing (status `Points`), which bounds the work a hostile file can ask for.

**The API** (`outlines.{h,cpp}`, `outline_renderer.{h,cpp}`):

- `Outlines::Load(path)`, `LoadMemory(bytes, size)`, `Find(name) -> int32_t`, `ViewBox(index)`, `Hotspot(index)`, `SinglePaint(index)`.
- `struct OutlinePaints { Color current; Color slots[8]; }`.
- `struct OutlineOptions { int32_t stroke_width = 0; }`: a non-zero value, in 1/256 of a unit, replaces every stroke's width (the thicker strokes on small app tiles).
- `Canvas::DrawOutline(const Outlines&, int32_t index, Rectangle destination, const OutlinePaints&, const OutlineOptions& = {})`: maps the view box onto the destination and draws the items in order.
- `RenderOutlineMask(...) -> Mask`, for a drawing whose items all use `Current`.

**The renderer:**

- Points are scaled to a fixed-point grid of 1/256 of a sample, rounding to nearest. From there everything is exact integer arithmetic (D2).
- Each item is rasterized into sample bits, 64 per pixel, so a stroke that crosses itself is covered once, then composited with its paint and opacity. Coverage is `(samples_inside * 255 + 32) / 64`.
- Work goes one pixel row at a time (8 sample rows). Every point is mapped once per draw into a list of segments with each item's rows of reach, and a pixel row visits only the items and segments that can reach it, so the work is at most the drawing's points times its 8 sample rows per pixel row (measured: 0.24 MB with two 4096-gons, 1.8 million segment tests over 1080 rows). Memory is the visible width's row buffers (161 KB at 3840, 0.7 MB at the 16384 maximum) plus under 0.25 MB for a drawing at the 8192-point cap, never the height.
- A sample row is a list of covered runs, not a bitmap: a fill adds a winding step at each edge crossing (the first sample at or right of it, found with integer division), a stroke adds the interval of each segment's capsule (two end discs and the strip between them, solved with an integer square root and 128-bit products, never 128-bit division). A scan of the steps gives the runs, so a wholly inside pixel costs no sampling.
- Limits that keep every product in 128 bits: a destination side above 65536 draws nothing; the loader accepts points from one view box before to one after the view box on each axis, and a stroke width of at most twice the smaller side. Stroke widths follow the smaller of the two scales when the destination is stretched.

**The cache** (`outline_cache.{h,cpp}`): `OutlineCache::Mask(outlines, index, width, height, options)` and `Image(outlines, index, width, height, paints, options)` return a cached `Mask` (single-paint drawings: icons) or premultiplied `Surface` (pointers). Least recently used entries go first once the cache holds more than 2 MiB.

### 1.6 Shadows, 9-slice and scaling (step B5)

- `struct NineSlice { Mask mask; int32_t left, top, right, bottom; }`.
- `NineSlice MakeShadow(int32_t corner_radius, int32_t blur)`: a rounded rectangle's mask blurred by three box passes of width `blur | 1` in each direction. Its insets are the corner radius plus twice the spread `3 * (blur / 2)`, so a stretched shadow equals the blur of the larger box byte for byte. Radius and blur are cut to 128.
- `Canvas::DrawNineSlice(const NineSlice&, Rectangle outer, Color, bool skip_centre)`: corners copied, edges and centre stretched by repeating their middle row or column. The compositor skips the centre, which lies under the opaque window.
- `Rectangle ShadowBounds(Rectangle box, int32_t offset_y, int32_t blur)`.
- `Canvas::DrawSurfaceScaled(const Surface&, Rectangle destination)`: an area average when shrinking, for thumbnails; nearest pixel when enlarging.

### 1.7 Artwork sources and the outlines script (step C1)

- **Sources**, all in the repo:
  - `tools/gui/art/icons.json`: each glyph's name and SVG path string, copied from the prototype's `P` table, with the grid (24) and stroke width (1.75);
  - `tools/gui/art/feather.json`: the vane, the shaft and the quill from the prototype's `featherSvg`;
  - `tools/gui/art/wallpaper.json`: the feather tint, the shaft line and the three ridges, with a slot per colour;
  - `docs/design/gui/cursors/svg/*.svg` and `cursors.json`: the pointers.
- **`tools/gui/outlines.py`** reads them, flattens every curve and arc to within 1/4096 of the drawing's width, and writes `initramfs/gui/outlines.fvo` and `initramfs/gui/SHA256SUMS`. `--check` regenerates and compares.
- **`tools/gui/fvol.py`** is the Python reader and writer, used by the script, the checks and the smoke test, as `ffnt.py` is for fonts.
- **Arcs without the maths library** (D5): an elliptical arc is converted with square roots and half-angle formulas, never `sin`, `cos` or `atan2`.
- `build.sh` copies `initramfs/gui` into `/system`, next to the fonts.
- **CTests:** `gui.files` (checksums; the file parses with `fvol.py`; every name the C++ code asks for exists), `gui.reproducible` (`outlines.py --check`), `gui.prototype` (`icons.json` equals the prototype's `P` table, so the two cannot drift).

### 1.8 Icons, app tiles, pointers and the wallpaper (steps C2 to C4)

All in `src/user/ui/art.{h,cpp}`, drawing through one process-wide `Outlines` and `OutlineCache`.

- **`DrawGlyph(Canvas&, GlyphId, Rectangle, Color)`:** the cached mask, tinted. `GlyphId` is generated from `icons.json`.
- **`DrawAppTile(Canvas&, Rectangle, const AppTile&, TileStyle)`** (step C2), composed live:
  - a rounded square with radius `(size * 23 + 50) / 100` in the app's colour;
  - `TileStyle::Full`: the fold, black at 16% over the lower-right triangle, and a white hairline at 22%, 1.5 px wide along the diagonal, both clipped to the square; then the glyph in white at `(size * 56 + 50) / 100`;
  - `TileStyle::Small` (Quill rows, the Feather menu, switcher labels): no fold, and the glyph's stroke widened to 2.3 units;
  - `TileStyle::Plain`: no fold, normal stroke (Quill's detail pane);
  - in a high-contrast theme: the theme's `surface` with a 2 px `text` border and the glyph in `text`.
- **`DrawPointer(Canvas&, PointerId, int32_t x, int32_t y, int32_t size, Color accent, uint32_t frame)`** (step C3):
  - `outlines.py` converts each SVG to items in paint order. The parts in `#f0a840` become `Slot` 0, the accent. The hotspot comes from `cursors.json`.
  - Working and Busy get 8 drawings each, the spinner's arc rotated in 45 degree steps on the host.
  - Sizes are 24, 32 and 48. The hotspot scales as `(hotspot * size + 12) / 24`.
  - `PointerHotspot(PointerId, size)` returns it.
- **`DrawWallpaper(Surface*, const Theme&)`** (step C4): fills `desk`, then draws the wallpaper drawing scaled to cover the surface (the larger of the two scale factors), centred.
- **`ShadowFor(ShadowRole)`** returns the cached `NineSlice` for a role from the tokens.

## 3. Invariants

**Arithmetic**
- **I1.** No floating-point type appears in `src/user/graphics/` or `src/user/ui/`. The host, x86-64 and AArch64 draw the same bytes. **Riskiest,** because every later GUI test compares a host render with a `screendump`.
- **I2.** `Div255` is the only rounding in a blend, and a canvas text draw equals `Surface::DrawText` pixel for pixel on an opaque surface.
- **I3.** A premultiplied pixel never has a colour channel above its alpha.

**Clipping and memory**
- **I4.** No operation writes outside the target surface or outside the canvas's clip, for any coordinates, sizes or radii, including negative and extreme ones. Geometry uses 64-bit arithmetic, as `Surface` does today.
- **I5.** `Restore()` returns the origin and clip to exactly what the matching `Save()` saw.
- **I6.** The outline renderer's working memory stays under 1 MiB for any destination size.

**Regions**
- **I7.** A region is always in canonical form after every operation, so equal pixel sets compare equal.

**Outlines**
- **I8.** A damaged or hostile file is refused by the loader; the renderer never reads outside the file's bytes for a file the loader accepted. **Riskiest** of the file handling.
- **I9.** Drawing an outline twice with the same arguments gives the same pixels, with or without the cache.
- **I10.** A sample inside two polylines of one item is covered once: a self-crossing stroke has no darker patch.

**Sources**
- **I11.** `tokens.json` and `icons.json` are the only source: the generated C++ and the prototype are both checked against them.
- **I12.** `outlines.py` writes the same bytes on every host.

## 4. Edge cases

| Case | Result |
|---|---|
| Rectangle with zero or negative width or height | Nothing drawn |
| Radius 0 | The same pixels as a plain rectangle |
| Radius above half the smaller side | Cut to half the smaller side |
| Stroke width at least half the smaller side | A filled shape |
| Colour with alpha 0 | Nothing drawn, and nothing read |
| Opaque colour, full coverage | A copy, with no blend arithmetic |
| `DrawOutline` to a destination of zero size | Nothing drawn |
| `DrawOutline` to a destination partly or wholly outside the clip | Only the visible part is rasterized |
| Outline index out of range, or no outlines loaded | Nothing drawn; `Find` returns -1 for an unknown name |
| Outlines file missing at run time | Icons draw as an empty box with a 1 px border, and the program still runs |
| Stroke narrower than one sample | Still covers the samples within its half width; it may vanish at small sizes, as in the browser |
| `Save()` beyond depth 16 | Returns false and changes nothing; the matching `Restore()` is then a no-op |
| Text that fits exactly | Drawn without an ellipsis |
| Text whose first glyph does not fit | Nothing but the ellipsis, or nothing if that does not fit either |
| Font without U+2026 | Three full stops |
| `MakeShadow` with blur 0 | The rounded rectangle's own mask |
| Region arithmetic near `INT32_MIN` and `INT32_MAX` | Clamped to the 16384-pixel limit that surfaces have |
| Cache asked for an entry larger than its limit | Null, nothing rendered or kept |
| Accent `Default` | The theme's own accent, unchanged |

## 7. Measurements

Filled in by steps C3 (the pointer check) and D1 (the drawing times).

**Pointer check** (T18, measured in step C3): `tools/gui/pointers_check.py --report` compares the premultiplied RGBA of each pointer from `guirender` (frame 0, accent `f0a840`) with the design's PNG, premultiplied the same way. The differences are in 0 to 255 levels of a premultiplied channel, over all pixels of the image; "far" counts pixels that differ by more than 64 in any channel.

| Size | Mean over the 13 pointers | Worst mean (pointer) | Largest single difference (pointer) | Far pixels | Limit: mean, largest |
|---|---|---|---|---|---|
| 24 | 2.63 | 8.93 (Not allowed) | 136 (Resize nesw) | 16 | 9.0, 140 |
| 32 | 1.86 | 3.54 (Not allowed) | 66 (Busy) | 1 | 3.6, 70 |
| 48 | 1.34 | 2.64 (Not allowed) | 132 (Resize nesw) | 6 | 2.7, 135 |

The limits sit just above the worst measurement of each size and apply to the mean and the largest difference of any channel, so a missing, moved or recoloured part fails them. What the numbers are: no shape is missing or misplaced. The largest differences are single pixels at the concave corner of a diagonal arrow and at the ends of the spinner's ring, where the reference's rasterizer and our 8x8 grid resolve an edge differently. Not allowed at 24 px is the worst mean because the reference's outer white ring at that size is about 0.2 px smaller than the geometry (a 5 px stroke on a circle of radius 7.6, reaching 1.9 units from the box edge): its top row has no ink where ours has 28/255, and the same ring at 48 px agrees to within 15 levels.

**Drawing times** from `uicard`, QEMU with TCG:

| Target | Build | Page 2 (all glyphs) | Page 3 (tiles, pointers) | Page 4 at 1024x768 (wallpaper) | Page 4 at 1920x1080 |
|---|---|---|---|---|---|
| x86-64 | Debug | 1530 | 1100 to 1460 | 870 to 940 | waits for M35 |
| x86-64 | Release | 350 to 390 | 280 to 290 | 220 | waits for M35 |
| AArch64 | Debug | 690 to 750 | 710 to 720 | 530 to 600 | waits for M35 |
| AArch64 | Release | 170 to 180 | 130 to 180 | 130 to 140 | waits for M35 |

Milliseconds as `uicard` prints them (the monotonic clock ticks every 10 ms), the range over the `dusk` and `hcl` runs of one `PIXELS_TEST` session on a quiet host; they include loading the six fonts. Page 4 at 1024x768 is the wallpaper plus the eight shadowed boxes. The host draws the 1920x1080 wallpaper in about 0.2 s; at 2.6 times the pixels of 1024x768 the x86-64 Debug figure is expected near 2 s, so the budget below needs the real measurement once M35 can boot at that size.

**Budget:** in a Debug build, page 2 under 2 s and the wallpaper at 1920x1080 under 2 s. If either is missed, the sample grid drops to 4x4 for destinations above 256 px, and the change is recorded here with new checksums.
