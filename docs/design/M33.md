# M33: Wickdeep, a turn-based dungeon crawler (design)

**Scope.** M32 gave user programs the screen (`/dev/fb0`, `<featheros/framebuffer.h>`), raw key events, and the C++ graphics library `src/user/graphics/` (`Surface`, `DirtyRegion`, `Display`). Swift imports the library as module `FeatherGraphics`. `featherfall` showed the pattern for a game: a pure state machine, `--selftest` and `--demo --seed N` run in QEMU by the `GRAPHICS` smoke mode, and a played part driven by QMP keys and checked with `screendump`. This milestone uses the same pattern for a larger game with procedural levels, hidden map, saved games and drawn art.

**Pitch.** *Wickdeep* is a turn-based descent through the Wickdeep, a flooded lamp-works sunk under an old town. Every floor below is darker than the one above. You are the last wick-keeper. You carry one lamp, and its oil is both your sight and your clock: the radius you can see shrinks as the oil burns down, and only the flasks you find refill it. Eight floors down, the Hearthwarden guards the Heartwick, the flame that once lit the town. Take it and the run is won; fall on the way and the run is over. Each run starts from a seed. Floors are built anew from it, and the only save is the one made when you stop playing.

This milestone:

1. Adds a tile layer to the graphics library: tiles drawn as palette-indexed text in source and drawn lit or remembered.
2. Adds `wickdeep`, an original dungeon crawler in Embedded Swift (`FEATHEROS_SWIFT_CXX_PROGRAMS`), with all rules in a pure state machine.
3. Adds saved games on disk with a versioned, checksummed format that refuses damaged files.
4. Adds a new smoke mode, `DUNGEON_TEST=ON`: self-test, demo hashes, a played session, and a save, resume and corruption round trip, on both architectures.

**Done when:**

1. `./build.sh unit-test`;
2. `bash tools/quality.sh check`;
3. `tools/check.sh --arch both --modes "GRAPHICS DUNGEON SHELL"`;
4. `tools/check.sh --arch both --matrix`.

## Decisions for the user to confirm

- **D1. Name, setting and content size.** *Wickdeep*, as in the pitch: 8 floors, 8 kinds of monster, 10 kinds of item, a level-up track and a lamp that runs down. No identification game, no shops, no climbing back up. *Recommended: as listed.* The alternative is fewer floors and kinds to start, with more added in a later milestone.
- **D2. Drawn tiles, not glyphs.** All map art is our own 16x16 pixel tiles, so no character conventions are borrowed from other games of the genre. Text (the panel and the message log) uses the kernel's 8x16 font. *Recommended: drawn tiles.* The alternative is letters from the font, coloured per kind, which is less work but looks like the genre's classics.
- **D3. The whole floor on screen.** A floor is 60x40 cells of 16 pixels (960x640) at (32, 8). A 112-pixel panel below shows hit points, the lamp gauge, depth, level, attack and defense, the last three messages and a key hint. There is no scrolling camera. *Recommended: whole floor, 16 px.* The alternative is 32 px cells with a camera that follows the player, which is bigger art but adds scrolling and a renderer that changes every move.
- **D4. Save on quit, one slot.** Esc, or Ctrl+C as a key or `SIGINT`, saves the run and exits. Starting `wickdeep` resumes the save if there is one. Death or victory deletes it. A run can only be replayed by copying the file by hand. *Recommended: this.* The alternative is saving at any time with several slots, which drops the permadeath feel.
- **D5. Controls.** Arrows and keypad 8/4/6/2 move. Keypad 7/9/1/3 move diagonally. Space waits a turn, Enter takes the stairs, I opens the pack (Up/Down to choose, Enter to use or equip, D to drop, Esc to close), H shows help, Esc saves and quits. A press or a kernel repeat is one command; releases are ignored. *Recommended: this.* The alternative is vi-style letter keys as well.
- **D6. A new library type.** `Graphics::TileSheet`, plus `Surface::BlitPart`, goes in `src/user/graphics/` with host tests, so later programs can draw tiles too. *Recommended: yes.* The alternative keeps the tile code inside `wickdeep`.
- **D7. Branch (settled by the user, 2026-11-21).** M33 is worked on `feat/graphics`, after M32.

## Detailed decisions (left to Claude)

### The library

- **D8. `TileSheet`** (`src/user/graphics/tile_sheet.{h,cpp}`, in `featheros_user_support` and module `FeatherGraphics`):
  - `Load(const char* const* rows, int32_t tile_count, int32_t tile_size, const uint32_t* palette, int32_t palette_size)` reads `tile_size` rows of `tile_size` characters per tile. `.` is transparent; `a` to `p` index a palette of up to 16 colours. It returns a status and refuses bad lengths, unknown characters and indexes past the palette.
  - It builds two atlases as `Surface`s: *lit* (the palette as given) and *remembered* (each channel times 3/8, plus a blue tint of 0x000010).
  - `Draw(Surface* target, int32_t tile, int32_t x, int32_t y, Shade shade, bool keyed)` copies one tile through the new `Surface::BlitPart(source, sx, sy, width, height, x, y, keyed, transparent)`, clipped with the same 64-bit arithmetic as `Blit`.
  - Host tests go in `tests/unit/user/tile_sheet_tests.cpp`: parsing and refusals, the remembered colours, keyed and clipped part-blits, and the checksum of a known tile.
- **D9. The art lives in C++ source:** `src/user/wickdeep/art.{h,cpp}` (`FEATHEROS_SWIFT_CXX_SOURCES_wickdeep`), with the palette and about 28 tiles, all drawn for this game:
  - terrain: floor, two wall variants, rubble, stairs down, the Heartwick's plinth;
  - the wick-keeper;
  - 8 monsters;
  - 10 items;
  - panel icons: heart and lamp.

  `LoadWickdeepTiles(TileSheet*)` is the only thing Swift calls, through a new module `WickdeepArt` in `src/user/swift_cxx/module.modulemap`.

### The rules

- **D10. A pure state machine.** `Game.step(_ command: Command) -> [Event]` (`rules.swift`).
  - `Command` is `move(Direction)`, `wait`, `descend`, `use(slot)`, `equip(slot)` or `drop(slot)`.
  - `Event`s are message codes with numbers. They become text only in `render.swift`. The last three are kept in the state so that a resumed game shows them.
  - The rules use integers and arrays only, never `Dictionary`, `Set` or floating point, so the order and the results are the same on both architectures.
  - The generator is SplitMix64 from `featherfall/random.swift` (`FEATHEROS_SWIFT_SHARED_SOURCES_wickdeep`). Floor *n* is built from `seed ^ (n &* 0x9E3779B97F4A7C15)`. Combat and the monsters use the run's own generator.
- **D11. Map generation** (`map.swift`, 60x40 cells).
  - Split the map into 4x3 sectors. Each sector gets a room of 4x3 to 11x7 cells, or, with chance 1/6, a one-cell junction.
  - Neighbouring sectors are joined by a random spanning tree plus two extra links for loops, using L-shaped corridors (bend chosen at random). Rubble is placed only where it cannot cut a path.
  - The player starts in a random room. The stairs, or on floor 8 the Hearthwarden's room and the Heartwick, go in the room farthest from the start by breadth-first distance.
  - Monsters (3 + depth, at most 16) and items (4 + depth/2) are placed from tables weighted by depth, never in the start room.
- **D12. Field of view.** Recursive shadowcasting over 8 octants, with slopes kept as integer fractions and radius test `dx*dx + dy*dy <= r*r + r`.
  - Cells in view are *lit*. Cells seen before are *remembered* and are drawn without monsters or items.
  - The lamp holds 0 to 1000 oil and burns 1 per player turn. The view radius is 6 at 500 or more oil, 5 at 200 or more, 3 at 50 or more, 2 above 0, and 1 when the lamp is out.
  - A flask adds 400 oil, up to 1000.
- **D13. Turns by energy.** Each actor's speed is 6 (slow), 12 (normal) or 18 (fast). Every tick adds its speed to its energy, and an actor with 12 or more acts and pays 12. Ties go to the player first, then monsters in array order. `step` runs ticks until it is the player's turn again.
- **D14. Combat.**
  - Hit chance in percent = clamp(70 + 5·(attack − defense), 20, 95).
  - Damage = max(1, attack + roll(−1...1) − defense/2).
  - Monsters drop nothing. Each kill gives its worth in embers (experience). Levels come at 10, 25, 50, 90, 140, 200 and 270 embers, and each level gives +4 maximum hit points (with the same amount healed) and +1 attack. The player starts with 20 hit points, attack 3 and defense 1.
  - Score = 100 per floor reached below the first + embers + 1000 for the Heartwick.
- **D15. Monsters** (`actors.swift`; hit points / attack / defense / speed / worth). All except the Hearthwarden start asleep and wake when they stand in the player's light (1 in 3 per turn), or at once when hit.
  - **dustmite** 3/2/0/12/1: weak and common.
  - **gnawling** 5/3/0/18/3: fast, placed in pairs.
  - **oilmoth** 6/1/0/12/4: drawn to the lamp. When adjacent, it drinks 25 oil instead of biting.
  - **sootcrawler** 10/4/1/12/6.
  - **shardback** 14/4/5/6/9: slow and hard to wound.
  - **rootgrip** 12/6/2/0/8: never moves. It strikes whoever is next to it.
  - **bellwraith** 18/7/2/6/14: slow, from floor 5.
  - **Hearthwarden** 45/9/4/12/30: floor 8 only. It stays in its room until hit or until the player takes the Heartwick.

  An awake monster steps along a breadth-first distance map from the player, built once per player turn over the floor's walkable cells. A cell in use counts as blocked. When the player is out of reach it steps at random.
- **D16. Items** (`items.swift`). The pack holds 10; items are picked up by stepping on them.
  - **Uses:** oil flask; salve (heals 8 + depth); flare stone (deals 6 to every monster in view within 4 cells); blink feather (moves the player to a random remembered floor cell); cartographer's moth (marks the whole floor as remembered).
  - **Gear:** hooked knife (+1 attack), iron crook (+3), warden's pike (+5); quilted coat (+1 defense), tin plate (+3). One weapon and one coat are worn at a time; equipping swaps.
- **D17. Limits.** At most 64 monsters and 64 floor items per floor, and a pack of 10. A game state is under 16 KiB.

### Saves and the hall

- **D18. Save format, version 1** (`save.swift`, little-endian):
  - The header is magic `WDSV`, a `u16` version, a `u16` reserved (0), a `u32` payload length and a `u64` FNV-1a checksum of the payload.
  - The payload is every field of `Game`: the seed, depth, turn and generator state, the player, the pack, the lamp, the floor's cells and remembered bits, the monsters, the items and the message codes.
  - `decode` refuses, with a reason, a file over 64 KiB or shorter than its header, a wrong magic, an unknown version, a length that does not match the file, a bad checksum, any field out of range (a position off the map or on a wall, a kind past its table, counts over D17) and trailing bytes.
  - Any rule change that alters the payload bumps the version. There is no migration: an older save is refused with `version`.
- **D19. Files.** The save is `$HOME/.wickdeep-save` (or `/tmp/.wickdeep-save` without `HOME`), written to `.tmp` and renamed into place, as `saveHighScores` does.
  - A refused save is renamed to `.wickdeep-save.bad`. The game starts a new run and says why in the log.
  - The hall of runs, `$HOME/.wickdeep-runs`, keeps the 10 best scores, one per line: `score depth turns outcome`.
  - `wickdeep --check-save PATH` prints `wickdeep: save ok depth D turn T` or `wickdeep: save rejected <reason>`.
- **D20. Determinism and tests**, as D17 of M32:
  - `wickdeep --selftest` (`selftest.swift`) checks:
    - the generator values;
    - every floor of seeds 1 to 50 is fully connected, with the stairs reachable;
    - shadowcasting on fixed small maps: a pillar's shadow, corridors, symmetric open rooms;
    - the lamp radii and oil;
    - energy order with speeds 6, 12 and 18;
    - the hit chance and damage bounds;
    - level thresholds;
    - each item's effect;
    - each monster's special rule;
    - save round trip: 300 turns, save, load and 300 more turns give the same hash as 600 turns straight;
    - every refusal in D18: one flipped byte in the header and in the payload, a truncation, an appended byte, an unknown version, an out-of-range position.
  - `wickdeep --demo --seed N` plays a fixed bot with no display. The bot attacks an adjacent monster, uses a salve below 40% hit points, a flask below 150 oil and a flare stone when three monsters are in view, and equips better gear. Otherwise it walks breadth-first to the nearest unexplored edge, then to the stairs. It stops at death, victory or 20,000 turns. It prints `wickdeep: demo turns T depth D level L score S outcome O hash H`, where H is the FNV-1a hash of the encoded save, the same on both architectures. Two seeds are checked.

### The program

- **D21. Files** in `src/user/wickdeep/`:
  - `main.swift` (the arguments);
  - rules: `rules.swift`, `map.swift`, `sight.swift`, `actors.swift`, `items.swift`;
  - saves and the hall: `save.swift`, `runs.swift`;
  - tests: `selftest.swift`, `demo.swift`;
  - the program: `render.swift`, `play.swift`, `art.{h,cpp}`.

  `wickdeep --seed N` fixes a new run's seed; without it the seed comes from `CLOCK_REALTIME`. A save on disk always wins over `--seed`.
- **D22. Drawing and the loop** follow `featherfall`:
  - The renderer redraws only cells whose view changed (tile, shade, occupant), compared with the last drawn view, and the panel when its numbers change. The rectangles go to `Display::Invalidate`.
  - The loop waits on `Display::WaitEvent` with no timeout, since nothing moves between commands.
  - `Hidden` does nothing. `Shown` redraws everything. A grown `dropped_events` count is ignored, since nothing is held.
  - The screen must be at least 1024x768, or the game says so on the terminal.
  - The pack, help, death and victory screens are overlays over the map. Death and victory add the run to the hall and show it.

## Steps

1. **The tile layer.** `Surface::BlitPart`, `TileSheet` (D8) with host tests, the module map entry, and `gfxcheck` extended to load a two-tile sheet and print its checksum, which the SHELL part `swift_cxx.py` compares with a value computed in C++ (`gfx_check.cpp`). This part can be shipped and tested on its own.
2. **Floors and sight.** `wickdeep` with `rules.swift` (movement, waiting, stairs, the lamp), `map.swift` (D11), `sight.swift` (D12), D13 with the player alone, and `--selftest` plus `--demo` with an exploring bot that only descends. New smoke mode `DUNGEON_TEST=ON` (`tools/smoke/cases/dungeon.py`, matrix entry `*Both(N, "dungeon", DUNGEON_TEST=ON)`) runs both and checks the hashes. The shared screendump and QMP helpers move out of `graphics.py` into `tools/smoke/cases/screen.py`.
3. **Monsters, combat and items.** `actors.swift`, `items.swift`, D14–D17, levels, death and victory on floor 8, the full bot. Self-test groups are added for each rule, and new demo hashes are recorded.
4. **Saves.** `save.swift` (D18), `runs.swift` and the files of D19, `--check-save`, and the self-test round trip and refusals. `DUNGEON` saves the encoded state of a demo run to a file with `wickdeep --demo --seed 1 --save-at 500 PATH`, checks it with `--check-save`, appends a byte (the shell's `>>`, or a small helper if the shell has no `>>`) and checks it is refused with `length`.
5. **The game.** `art.{h,cpp}` (D9), `render.swift`, `play.swift`, controls (D5), overlays, and Esc and `SIGINT` saving.
   - The played part of `DUNGEON` (`HOME=/home`) does the following:
     - runs `wickdeep --seed 7` and checks the panel's frame colours, the player's colour inside the floor, and that most of the floor is still dark;
     - opens and closes the pack;
     - presses 20 arrow keys and checks that the floor area changed;
     - switches to Alt+F2 and back and checks that the screen is the same;
     - presses Esc and checks the text console returns;
     - runs `--check-save` (`ok`);
     - starts `wickdeep` again and checks that the floor area is identical to the dump taken before Esc;
     - quits, corrupts the save, starts it, and checks that the new run's floor matches the first dump of seed 7 and that `.wickdeep-save.bad` exists.
   - Docs: `docs/development.md` (the `DUNGEON` mode, the library type), the `add-program` checklist, and `CLAUDE.md`'s test toggles.
