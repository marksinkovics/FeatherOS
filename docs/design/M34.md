# M34: Better fonts (design)

**Scope.** Text today is one 1-bit 8x16 font of ASCII 33-126 (`src/kernel/framebuffer/font.c`, `font16_8`), made once by `tools/gen_font.sh` from Ubuntu Mono with ImageMagick. The kernel's `Term` draws it in a fixed cell grid. User programs draw it through `Surface::DrawText` at an integer scale (`featherfall`, `wickdeep`, `gfxcheck`). Bytes above 0x7E show as blanks, and the input side drops them: canonical mode keeps only 0x20-0x7E (`src/kernel/terminal/terminal.cpp`), and the shell's `LineEditor` counts bytes, not characters. This milestone replaces that font with pre-rendered, anti-aliased fonts from openly licensed families. It adds a monospace and a proportional family in several sizes, with UTF-8 everywhere text is drawn.

This milestone:

1. Adds a font file format of our own (`FFNT`), a host generator that writes the files, and committed generated files in `/system/fonts/`.
2. Adds `Graphics::Font` and `Surface::DrawText(font, ...)` with coverage blending, over a parser and a UTF-8 decoder that the kernel shares (`src/user/text/`).
3. Switches the kernel console to the new monospace font, compiled in, anti-aliased, and decoding UTF-8 into one code point per cell.
4. Lets typed or pasted UTF-8 through the line discipline and the shell's line editor.
5. Moves `featherfall`, `wickdeep` and `gfxcheck` to the new API, deletes `font.c` and `gen_font.sh`, and adds `fontview` with the smoke mode `FONTS_TEST=ON`.

A runtime TrueType rasterizer is out of scope. It may come later as its own milestone and would produce the same in-memory form (D8).

**Done when:**

1. `./build.sh unit-test`;
2. `bash tools/quality.sh check`;
3. `tools/check.sh --arch both --modes "FONTS GRAPHICS DUNGEON SHELL"`;
4. `tools/check.sh --arch both --matrix`.

## Decisions

Confirmed by the user on 2026-11-21: D2 (with Greek and Cyrillic added to D3), D3, D4, D5, D6. **D1 (the families) is still open:** the user asked whether the fonts are free to use (yes, all four pairs are SIL OFL 1.1) and for samples, which are in `docs/design/M34-font-samples.html` (open it in a browser; it loads the faces from Google Fonts). Ask the user to pick a pair before Part 1.

- **D1. Families: JetBrains Mono Regular and Inter Regular,** both under SIL OFL 1.1. JetBrains Mono's `OFL.txt` declares no Reserved Font Name as far as checked. Inter's declares "Inter" as one, so the derived files must not be called Inter. They are named `mono-N` and `sans-N`, with the source credited in the notice and the licence files. JetBrains Mono is made for code and has box drawing, block elements, arrows and Latin Extended-A. Inter has the same text coverage. Alternatives:
  - IBM Plex Mono / IBM Plex Sans (OFL 1.1, Reserved Font Name "Plex");
  - Fira Mono / Fira Sans (OFL 1.1, Reserved Font Name "Fira");
  - Noto Sans Mono / Noto Sans (OFL 1.1; the widest coverage).

  Only the regular weight; bold can come later. Whatever is chosen, the `OFL.txt` shipped with the pinned release is checked at import, and the generated names never use a Reserved Font Name.
- **D2. Sizes, named by line height in pixels.** The old scale *s* was a 16*s* pixel line, so the names map directly:
  - mono 16 (the console's 8x16 cell), 20, 24 and 32;
  - sans 16, 20, 24, 32, 48 and 64.

  That is ten files of about 1.5 MB together.
- **D3. Character coverage (about 770 glyphs per file).**
  - ASCII U+0020-007E, Latin-1 U+00A0-00FF and Latin Extended-A U+0100-017F (Central European letters such as ő ű ł č);
  - the common punctuation (en and em dash, curly quotes, dagger, bullet, ellipsis, per mille, angle quotes), € and ™;
  - the arrows U+2190-2199, ↵, ⇥ and ⇧;
  - box drawing U+2500-257F, block elements U+2580-259F and a few geometric shapes (■ □ ▲ ▶ ▼ ◀ ◆ ○ ●);
  - U+FFFD.

  - Greek U+0370-03FF (the modern monotonic letters and tonos) and Cyrillic U+0400-045F plus U+0490-0491, added at the user's request (about 250 more glyphs, so about 770 per file).

  Not included: combining marks, wide (CJK) characters and right-to-left text. Every code point takes one console cell.
- **D4. Console cell: keep 8x16.** At 1024x768 the grid stays 128x48 with one cell of padding (126x46 cells, the status bar on the first). The status bar, `TermConfig`, `STATUS_POINT` (1011,24) in `graphics.py`, the padding checks in `framebuffer_tests.cpp` and every full-screen program's size stay valid. JetBrains Mono fits the cell at about 13.3 px em. The alternative is 10x20 for a larger, crisper face: the grid becomes 102x38 (100x36 cells) with 4 and 8 spare pixels centred. That would mean new values for `STATUS_POINT`, `PADDING_POINT` and the padding tests, and a status bar of 100 cells. The cell size comes from the generated `console_font.h` either way, so changing it later is a regeneration.
- **D5. The generator may use a host package:** Python 3 with `freetype-py` (pip, in a virtual environment, an exact version pinned in `tools/fonts/requirements.txt`; its wheels bundle FreeType). It is needed only to regenerate; a normal build reads the committed files. The alternative is our own TrueType rasterizer in Python: about 600 lines, no hinting, and blurrier at 16 px.
- **D6. Branch.** `feat/graphics`, after M33, since the library exists only there.

## Detailed decisions (left to Claude)

### Format and generator

- **D7. `FFNT` version 1** (little-endian, extension `.ffnt`).
  - **Header, 64 bytes:**
    - magic `FFNT`;
    - `u16` version 1;
    - `u16` header size 64;
    - `u32` file size;
    - `u32` flags (bit 0 monospace, the rest 0);
    - `u16` em pixel size and `u16` line height;
    - `i16` ascent and `i16` descent;
    - `u16` cell width (every advance for monospace, 0 otherwise);
    - `u8` coverage bits (4) and `u8` reserved;
    - `u32` glyph count;
    - `u32` offset and size pairs for the glyph table, the bitmaps and the text;
    - `u32` reserved;
    - `u64` FNV-1a of the whole file with these 8 bytes read as zero.
  - **Glyph records, 20 bytes each:** `u32` code point, `u32` bitmap offset, `u16` width and height, `i16` left (from the pen) and top (rows above the baseline), `u16` advance and `u16` reserved. Records are sorted by code point and looked up by binary search, with a direct index for the dense ASCII run.
  - **Record 0 has code point 0 and is the missing-glyph box.**
  - **Bitmaps:** 4-bit coverage, two pixels per byte with the left pixel in the high nibble, and rows padded to a byte with a zero nibble. A byte value *v* blends with alpha *v*·17.
  - **Text section:** two NUL-terminated UTF-8 strings, the name (`mono 16`, never a Reserved Font Name) and the notice (the source family, its copyright and `SIL Open Font License 1.1`).
  - **No kerning in version 1:** FreeType reads only the legacy `kern` table, and Inter keeps its kerning in GPOS. A later version can add a section.
- **D8. One in-memory form.** `Text::FontView` (`src/user/text/font_data.{h,cpp}`, namespace `FeatherOS::Text`, freestanding, no allocation) is a checked view over FFNT bytes:
  - `Parse(bytes, size, &view)` returns a `FontStatus`;
  - `Find(code_point)` returns a record or record 0;
  - `Coverage(record, x, y)` reads one pixel's coverage.

  The kernel parses its compiled-in array with it. The library parses file bytes it owns. A future rasterizer writes the same bytes in memory.
- **D9. Refusals, in this order:**
  - `size` (over 4 MiB) and `short` (under the header);
  - `magic`, `version`, `header` (header size 64, coverage bits 4, unknown flags), `reserved` (a nonzero reserved field or padding nibble), `length` (file size field against the bytes) and `checksum`;
  - `layout`: sections out of order, overlapping, unaligned to 4 or past the end;
  - `order`: code points not strictly ascending;
  - `range`:
    - a code point past U+10FFFF or a surrogate;
    - a bitmap outside its section;
    - a width or height over 256;
    - bearings or advance over 4 lines;
    - a monospace advance other than the cell width;
    - ascent plus descent over the line height;
  - `missing`: no record 0;
  - `text`: a string not terminated or not UTF-8.
- **D10. Generator** `tools/fonts/generate.py`, with `ffnt.py`, a reader, writer and reference renderer that the tests and the smoke harness also use.
  - **Rendering:** FreeType with `FT_LOAD_TARGET_LIGHT` (vertical-only hinting), coverage quantised as (a·15 + 127) / 255.
  - **Synthesised glyphs:** box drawing and block elements are drawn by the generator to the exact cell, so lines join across cells: light lines max(1, w/8) px, heavy twice that, double lines two light ones a pixel apart, arcs and diagonals anti-aliased, shades ░▒▓ as uniform coverage 4/8/12. The missing box is a 1 px hollow rectangle inside the advance. A requested code point that the family lacks is left out and reported.
  - **The console face:** the mono 16 baseline is chosen so `ÁŐ` and `gjpqy` fit the 16-row cell. ASCII must clip no pixel; other glyphs are clipped to the cell and counted in the report.
  - **Sources:** the TTF files are committed in `tools/fonts/sources/` with their `OFL.txt` files and `sources.txt` (URL, version, SHA-256, which the generator checks).
  - **Outputs:**
    - `initramfs/fonts/{mono,sans}-N.ffnt`;
    - `LICENSE-JetBrainsMono.txt`, `LICENSE-Inter.txt`, `README.txt` (attribution, what the files derive from, under OFL 1.1, not the FeatherOS licence) and `SHA256SUMS`;
    - `src/kernel/framebuffer/console_font.{c,h}`: the bytes of `mono-16.ffnt`, the notice as a comment, and `CellWidth`/`CellHeight`;
    - `tests/unit/user/data/font_reference.txt`: checksums of reference strings rendered by `ffnt.py`.

    There are no timestamps and the order is fixed, so regeneration is byte-identical.
- **D11. Installation.** `build.sh` copies `initramfs/fonts/` to `/system/fonts/`, so fonts exist with any root and in rescue. The disk root gets no copy.

### Text in the library

- **D12. UTF-8** (`src/user/text/utf8.{h,cpp}`, shared with the kernel).
  - `Utf8Decoder::Push(byte, char32_t out[2])` returns 0 to 2 code points, keeping state across calls. `DecodeNext(text, length, &used)` handles whole strings.
  - Invalid input becomes U+FFFD per maximal subpart, as Unicode recommends:
    - C0, C1 and F5-FF are one U+FFFD each;
    - second bytes are checked per lead (E0 A0-BF, ED 80-9F, F0 90-BF, F4 80-8F), so overlongs, surrogates and values past U+10FFFF are caught at the byte where they go wrong;
    - a byte that breaks a sequence gives U+FFFD and is then read again;
    - a string ending mid-sequence gives one U+FFFD.
  - libc's `unicode_conversion.cpp` keeps its `mbrtowc` semantics.
- **D13. API** (`src/user/graphics/font.{h,cpp}`, in `FeatherGraphics`). `Font` is move-only with a move constructor, like `TileSheet`, so Swift keeps it behind `UnsafeMutablePointer`.
  - `Load(path)` reads at most 4 MiB, parses and owns the bytes. `LoadNamed("sans-24")` reads `/system/fonts/sans-24.ffnt`. `LoadMemory(bytes, size)` borrows. `Font::Console()` is a static over the compiled-in `console_font.c`, so a program always has a font.
  - Getters: `Valid`, `LineHeight`, `Ascent`, `Descent`, `Monospace`, `CellWidth`, `Advance(code_point)`, `HasGlyph`, and `MeasureText(utf8)` (the width in pixels). `FontStatusName(status)` gives `length` and the other names.
  - `Surface::DrawText(const Font*, x, y, utf8, color) -> int32_t` returns the pen's end. `y` is the top of the line box, as before, with the baseline at y + ascent.
    - It blends over the pixels already there; coverage 15 writes `color` exactly and 0 leaves the pixel.
    - It is clipped with 64-bit arithmetic.
    - C0 controls and DEL draw nothing and do not advance. A missing code point draws record 0.
  - `DrawTextOn(font, x, y, utf8, color, background)` first fills the measured box. There is one line per call, and positions are whole pixels.
- **D14. Blending, the same everywhere.** `Text::Blend(background, foreground, coverage)` works per channel: (f·a + b·(255 - a) + 127) / 255 with a = coverage·17, in sRGB with no gamma, integers only. Both architectures, the host and `ffnt.py` give the same pixels.

### The console

- **D15. Compiled in, no allocation.** `Term::Init` parses `console_font.c` once into a static `FontView`. A failure would log to serial and draw every cell as a missing box, never stopping the boot; a host test makes it impossible. Early logging and panic only draw cells, so they never allocate.
- **D16. Cells hold code points.**
  - `m_buffer`/`m_attributes` and their screen and main-screen copies become one `uint32_t` per cell: the code point in bits 0-20 and attributes in 24-31. That is 72 KiB per `Term` instead of 36, 288 KiB for the four.
  - `CharacterAt` returns `char32_t`. `TermConfig` takes its sizes from `console_font.h`.
  - `Term` keeps a `Utf8Decoder` beside its escape state, since sequences split across writes. The decoder sees bytes first:
    - code points below 0x80 go to `HandleEscape`/`WriteCharacter` as today;
    - C1 controls (U+0080-009F) are dropped;
    - the rest go into the cell;
    - an ESC or newline inside a sequence first gives U+FFFD.
- **D17. Drawing.** `Framebuffer::drawGlyph(view, record, x, y, palette)` replaces `drawCharacter`; the unused `drawString` goes.
  - `Term` keeps two 16-entry packed palettes, normal and inverted, from `Blend` and `PackColor`, rebuilt only when the colours change. A cell is a background fill of the glyph box plus a nibble lookup and a store per pixel.
  - It never reads the back buffer and does no multiplication per pixel. The cost under `display_lock` with IRQs off stays in the order of today's bit test.
  - The status bar keeps its row, its right alignment and `DrawDot`, its text now anti-aliased black on white; `SetStatus` text is decoded the same way.
- **D18. UTF-8 input.**
  - The canonical line editor (`terminal.cpp`) keeps bytes 0x80-0xFF. Erase removes a whole sequence and calls `erase_character` once, as Linux's `IUTF8`.
  - `KeyDecoder` passes such bytes as printable. `LineEditor` keeps bytes but moves the cursor, erases and computes columns by code point (`Text::CellCount`).
  - `vi` stays byte-based, a stated limit.

### Programs, smoke checks, determinism

- **D19. Migration.**
  - Numbers that change in place use mono so their width holds; labels and headings use sans.
  - `featherfall`: scale 1 → sans 16, scale 2 → sans 32 (scores mono 32), scale 3 → sans 48, the initials sans 64.
  - `wickdeep`: the panel and messages in mono 16 (the same 8x16 metrics, so the layout keeps), titles sans 32.
  - `gfxcheck`: draws with sans 16 and mono 32 against a plain-loop reference in `gfx_check.cpp`, so the pinned `checksum 1833110056` line in `shell/swift_cxx.py` gets a new value.
  - `fbdemo` draws no text.
  - Afterwards the scale API (`DrawText(x, y, text, color, scale)`, `DrawTextOn`, `TextWidth`, `GlyphWidth`/`GlyphHeight`), `font.{c,h}` and `tools/gen_font.sh` are deleted.
- **D20. Smoke checks stay valid** because they look for colours, not glyph shapes.
  - `graphics.py`'s `ExpectPaused`, `ExpectInitials` and `ExpectTable` use `Found(..., ACCENT|TEXT)`, and every stem of 32 px or more has full-coverage pixels. Their rectangles are re-measured against the new layout and changed only where a text moved.
  - `dungeon.py` compares floor and box bytes between dumps of one build, which deterministic blending keeps equal. Its panel points (`PANEL_X + 948`) must stay off text.
  - `STATUS_POINT` and `PADDING_POINT` hold with D4's default.
  - New checks render their expected pixels with `ffnt.py` from the committed files, so they are exact.
- **D21. `fontview`** (`src/user/fontview.cpp`, C++):
  - `fontview [name]` pages through a font's glyph table (PgUp/PgDn, Esc quits);
  - `fontview --card` draws a fixed test card on `/dev/fb0`: each size's sample line at fixed places, light on dark and dark on light, and a missing box. It prints `fontview: card drawn` and waits for a key;
  - `fontview --check PATH` prints `fontview: font ok glyphs G line L` or `fontview: font rejected <reason>`.

## Tests

- **Host, `[font]`** (`tests/unit/user/font_data_tests.cpp`, with a C++ FFNT writer in `tests/unit/support/font_builder.{h,cpp}`):
  - every refusal of D9, plus a flipped byte in each section, a truncation and an appended byte;
  - binary search at both ends, the dense run and the missing record;
  - one glyph's coverage bytes against values written in the test;
  - `Blend` at coverage 0, 15 and the midpoints per channel;
  - every committed file parses, and `console_font.c` equals `mono-16.ffnt`.
- **Host, `[utf8]`** (`utf8_tests.cpp`):
  - valid 1-4 byte forms, U+FFFF and U+10FFFF;
  - overlongs (C0 80, E0 80 80, F0 80 80 80);
  - surrogates (ED A0 80), past U+10FFFF (F4 90 80 80) and F5-FF;
  - truncated sequences at the end and broken by ASCII;
  - byte-at-a-time decoding equal to whole-string decoding over 10 000 seeded random strings, against a plain reference.
- **Host, `[graphics][font]`** (`font_tests.cpp`):
  - `MeasureText` (monospace counts, proportional sums, controls and the missing box);
  - `DrawText` blending over a non-black surface, clipping at the edges and at `INT32_MIN`/`MAX`;
  - checksums of rendered strings against `font_reference.txt`, which ties `ffnt.py` to the C++.
- **Host, `Term`** (`framebuffer_tests.cpp`):
  - UTF-8 split over `Print` calls, U+FFFD cells and ESC inside a sequence;
  - a known glyph's pixels in the back buffer;
  - reverse video and cursor palettes;
  - scroll and the alternate screen keeping code points.

  `line_editor_tests.cpp` covers cursor moves and erase over 2-4 byte characters. Canonical-mode erase is tested as well.
- **Generator:**
  - CTest `fonts.files` runs `tools/fonts/check.py`: `SHA256SUMS`, every file parsed by `ffnt.py`, and the licence files present;
  - CTest `fonts.reproducible` runs `generate.py --check`, which regenerates into a temporary directory and compares byte for byte. It is skipped (code 77) when `freetype-py` is missing.
- **QEMU, new mode `FONTS_TEST=ON`** (`tools/smoke/cases/fonts.py`, matrix cases 51-52):
  - `cat /system/fonts/sample.txt`: accented Latin-1 and Latin Extended-A, arrows, box drawing, blocks and a line of invalid bytes. The screendump is matched cell by cell against cells rendered by `ffnt.py`, with the rows found on the grid;
  - `echo` of typed accented text and `┌─┐`, checked on serial and on screen;
  - `fontview --check` of every file, and of a copy with a byte appended (`rejected length`);
  - `fontview --card` against a reference rendered whole by `ffnt.py`.

  `GRAPHICS`, `DUNGEON` and `SHELL` keep passing with the D20 changes.

## Steps

1. **Format, generator and parser.**
   - `tools/fonts/` (D10) and the committed files in `initramfs/fonts/`, installed to `/system/fonts/` (D11);
   - `src/user/text/font_data.{h,cpp}` and `utf8.{h,cpp}` in `featheros_user_support` and the tests;
   - host tests `[font]` and `[utf8]`, CTest `fonts.files` and `fonts.reproducible`.

   This part can be shipped and tested on its own.
2. **The library.**
   - `Graphics::Font`, `Surface::DrawText(font, ...)`, `DrawTextOn` and `MeasureText`, with the module map entry;
   - `font_tests.cpp`;
   - `gfxcheck` loads `sans-16` from `/system/fonts` and prints `gfxcheck: font checksum N, match true` against `gfx_check.cpp`, checked in `shell/swift_cxx.py` on both architectures. The old scale API stays for now.
3. **The console font.**
   - `console_font.{c,h}`, D15-D17 in `term.{h,cpp}` and `framebuffer.{h,cpp}`, and `src/user/text/` compiled into the kernel;
   - `Term` host tests;
   - new mode `FONTS_TEST=ON` with the `sample.txt` screendump, wired into `build.sh`, `smoke_test.py` (`--expect-fonts`) and `tools/matrix.py`.
4. **UTF-8 input.** D18 in `terminal.cpp`, `key_decoder.cpp` and `line_editor.{h,cpp}`, with their tests, and the `echo` part of `FONTS`.
5. **Programs move.**
   - `featherfall` and `wickdeep` renderers and `gfxcheck` per D19, with the coordinates in `graphics.py` and `dungeon.py` re-measured;
   - the scale API, `font.{c,h}` and `gen_font.sh` deleted, and `graphics_tests.cpp` updated;
   - the full matrix.
6. **`fontview` and docs.**
   - `fontview` (D21, the `add-program` skill), its card and `--check` in `FONTS`;
   - docs: `docs/development.md` (the `FONTS` mode, the format, regenerating fonts), `docs/posix.md` (UTF-8 in canonical mode), and `CLAUDE.md`'s test toggles and known limits (no combining, wide or right-to-left text, `vi` byte-based).
