# M22 Part 6 step 4: jbd2 transactions (design)

**Split into four sub-steps.** Each must pass `./build.sh unit-test` and `bash tools/quality.sh check` and can be committed on its own.

- **4a — the log format writer and metadata routing.** Nothing changes in how the filesystem behaves.
- **4b — transactions.** ext3 and ext4 volumes with an internal journal mount writable in the core and in `fscli`. Every change is one atomic transaction. A change too big for a transaction on its own fails with `NoSpace`.
- **4c — orphans.** Writes, truncations and removals too big for one transaction are split into several. An orphan entry (in the orphan file or the `s_last_orphan` list) makes them crash-atomic. A writable mount processes every orphan entry, ours and Linux's.
- **4d — crash and model tests, fscli and docs.** Crash tests at every write, checked against both replays; the random model test; `fscli` tests; the docs (`finish-step` skill).

The kernel does not change: `Drivers::MountExt3`/`MountExt4` still pass `MountMode::ReadOnly`. Everything lives in `src/fs/core/`.

**Step 5 requirement (from this design):** the kernel adapter calls `Sync` on every writable ext3/ext4 mount every 5 seconds. The core has no timer. Its 5 s commit rule (§6.1) acts only when the next change arrives.

**Decisions taken (accepted by the user):**
- `needs_recovery` stays set for the whole writable mount and is cleared at unmount.
- A writable mount adjusts the journal superblock's features as Linux does (§7.1).
- `StateClean` stays set on disk while a journalled volume is mounted.
- At most 4 MiB of block copies per layer (`JournalMemoryBytes`).

## Settled questions

- **Split writes (accepted):** atomic for the file size and everything past the old end; inside the old size each block may show old or new bytes (ordered mode, as Linux; no `data=journal`).
- **Removal that cannot finish (accepted):** the name is gone and the orphan entry stays; the next writable mount or e2fsck finishes the release, as on Linux.

## 1. Model and terms

- **Layer.** Block copies in memory, keyed by home block number (`BlockLayer`). There are three:
  - **step** — the changes of the operation in progress;
  - **running** — whole steps not yet committed, which make up transaction `T`;
  - **committed** — transactions in the log that are not yet written home.
- **Reads and writes.** Metadata reads look at step, then running, then committed, then `BlockCache`/disk. Metadata writes go only to the step layer. Data writes go to the device at once (`cache.Write`).
- **Step.** One public change: `SetAttributes`, `Write`, `Truncate`, `Create`, `MakeDirectory`, `Remove`, `RemoveDirectory`, `Rename`, `Link` or `SymbolicLink`. A step can also be one piece of a split change (4c) or one piece of orphan processing. A step succeeds whole (merged into running) or leaves no trace (rolled back). A transaction holds only whole steps.
- **The ring.** The ring is journal blocks `[s_first, s_maxlen)`, and `ring_len = s_maxlen − s_first`.
  - `head` is the next ring position to be written.
  - The log is the committed transactions not yet checkpointed. On disk, `s_start` names the oldest of them, or is 0 when the log is empty.
  - An **epoch** runs from the first commit after an empty log to the next checkpoint, which always empties the whole log.
- **Footprint.** A transaction with `n` distinct blocks (the superblock's always counted) and `r` revoke records takes `F(n, r) = ceil(n / TagsPerDescriptor) + n + ceil(r / RevokesPerBlock) + 1` ring blocks.
- **Limits.** With `M = JournalMemoryBytes / block_size`:
  - `hard = min(ring_len − 1, M)`;
  - `soft = min(ring_len / 4, M / 2)`;
  - `committed_cap = M`.

## 2. Metadata versus data

| Journalled (metadata) | Written in place (data, ordered) |
|---|---|
| The superblock's block (block 0 or 1, the whole block), group descriptor blocks, block and inode bitmaps, inode table blocks, directory blocks (leaves, htree index blocks, new directory blocks), extent tree nodes below the root, indirect blocks, extended attribute blocks, slow symbolic link blocks (as Linux 6.x's `ext4_init_symlink_block`), orphan file blocks (4c) | Regular file contents: `WriteFile`'s block-map loop, `WriteDataBlocks`, `ZeroFrom` |

- Never written: backups and the resize inode.
- The log and the journal superblock are written directly with `cache.Write`.
- Data blocks never enter a layer. A block enters a layer only as metadata, and it leaves every layer when it is freed (§6.4).

## 4. On-disk layout written

### 4.1 The journal

**Journal superblock.**
- At a writable mount, once (§7.1): `s_feature_compat` (0x24), `s_feature_incompat` (0x28), `s_checksum_type` (0x50; 4 with v2/v3) and `s_checksum` (0xFC).
- At epoch start: `s_start` is the epoch's first block and `s_sequence` its transaction ID.
- At a checkpoint: `s_start` is 0 and `s_sequence` the next transaction ID.
- The checksum is stored again on every write.

**Transaction `T`.** It is written from `head` and wraps from `s_maxlen − 1` to `s_first`. In order:

1. **Revoke blocks**, when there are revokes:
   - type 5, sequence `T`;
   - `r_count` at offset 12, counting the 16-byte header;
   - records from offset 16: be32, or be64 with 64BIT;
   - with v2/v3, a CRC32C tail.
2. **Descriptor groups.** Each is a descriptor block (type 1, sequence `T`, tags), then the copies it tags, in running-layer order.
   - A copy that begins with `C0 3B 39 98` has those 4 bytes zeroed and its tag gets ESCAPE.
   - The tag checksum is `JournalTagChecksum(seed, T, escaped copy)`.
   - The first tag is followed by `s_uuid`.
   - With v2/v3, the descriptor has a tail.
3. **The commit block:** type 2, sequence `T`; `h_commit_sec` at 48 and `h_commit_nsec` at 56; with v2/v3, `h_chksum[0]` at 16. Every other byte is zero.

**`needs_recovery`** is set by a direct write at a writable mount and cleared at unmount. The superblock copies inside the journal have it set.

### 4.2 Orphans (4c)

**Orphan file.**
- The inode is `s_orphan_file_inum`, a regular file of whole blocks whose size `mke2fs` set. Its blocks are metadata (journalled).
- Each block holds `OrphansPerBlock` slots of le32 inode numbers (0 for a free slot), then the tail: `ob_magic` (le32 `0x0B10CA04`) at `block_size − 8` and `ob_checksum` (le32) at `block_size − 4`.
- **Checksum** (only with metadata_csum): CRC32C seeded from the volume seed, then fed the orphan inode's number and generation (as for inode checksums), then the block's physical block number as le64 (confirmed against mke2fs images in 4c; not the logical index), then the slot area. The implementer must reproduce `ext2fs_orphan_file_block_csum` (e2fsprogs `lib/ext2fs/orphan.c`) byte for byte; T18 checks this against the blocks `mke2fs` writes.
- **Slot choice:** we take the first free slot from logical block 0 on. Linux spreads entries per CPU, but processing takes any slot.
- **`orphan_present`** (ro_compat 0x10000) is set in the superblock in the same transaction that fills the first slot, and cleared in the transaction that frees the last one. So it is set exactly while some slot is nonzero, which e2fsck requires.

**`s_last_orphan` list.** Used on volumes without the orphan file, and as a fallback when the orphan file is full, as Linux does.
- The list is a chain from `s_last_orphan` through each listed inode's `i_dtime`, ending at 0.
- Adding: `inode.dtime = s_last_orphan; s_last_orphan = node`, with the inode and the superblock in the same step.
- Removing our own entry: `s_last_orphan = inode.dtime; inode.dtime = 0`. If the inode is being freed, `dtime` is set to the current time instead.

  Our entry is always the head: changes are serialised, a split operation finishes before the next change starts, and processing at mount leaves the list empty. If the head is not our inode, that is `Corrupt`.

**State of a listed inode.**
- **Truncation:** `i_size` already holds the target, and the blocks past it are being freed.
- **Removal:** `i_links_count` is 0 and the name is gone. With the orphan file, `i_dtime` is 0. With the list, it holds the next entry.
- **Write:** `i_size` still holds the old size, and blocks past it are being mapped.

**Processing an entry** (the same rule as Linux's `ext4_orphan_cleanup` and e2fsck's `release_orphan_inodes`):
- Links 0: release the contents, then the inode.
- Links > 0: truncate to `i_size`, keeping the mapping (`ShrinkTo`).

## 5. Write orders and what a crash leaves

| Point | Writes, in order | Crash here, after `RecoverJournal` (+ orphan processing) or e2fsprogs (`e2fsck -fy`; `debugfs jr` plus orphan release) |
|---|---|---|
| Mount M1 | recovery (step 1), if needed | as step 1 |
| M2 | journal superblock features (if changed), Flush | log empty: the volume as before |
| M3 | superblock: `needs_recovery`, mount count; Flush | `needs_recovery` with an empty log: the sequence goes up and the flag is cleared |
| M4 (4c) | orphan processing: steps and commits, as below | entries not yet finished are processed again by the next mount |
| A change | data in place only | the last committed state; new blocks unreachable; overwrites may show new bytes (ordered) |
| Commit C0 | (memory) the superblock with its counts into running | as above |
| C1 (`F(T) > ring_len − 1 − used`) | full Checkpoint K1–K4 | see K |
| C2 (`used == 0`) | journal superblock: `s_start = head`, `s_sequence = T` | last committed state |
| C3/C4 | revoke blocks; per group, the descriptor and then each copy (one write per block) | torn tail: state `T−1` |
| C5 | Flush | `T−1` |
| C6 | commit block | `T` |
| C7 | Flush | `T` |
| C8 (memory) | revoked blocks leave committed; committed absorbs running; `head`/`used` advance; transaction ID + 1 | n/a |
| C9 (`committed.Count() > limits.committed`) | Checkpoint | see K |
| Checkpoint K1 | committed blocks home, ascending | last committed state (replay is idempotent) |
| K2 | Flush | same |
| K3 | journal superblock: `s_start = 0`, `s_sequence` = next ID | no replay needed |
| K4 | Flush; (memory) committed cleared, `used = 0` | same |
| Unmount U0 | Commit, then Checkpoint if `used > 0` | as above |
| U1 | superblock: `needs_recovery` cleared, `s_wtime` | log empty, flag cleared at the next mount |
| U2 | Flush | `e2fsck -fn` exit 0 without replay |

**Split operations (4c).** A split operation is transactions `T1..Tk`:
- `T1` adds the orphan entry.
- `Tk` removes it and completes the operation.

What a crash leaves:
- **Before `T1` commits:** nothing of the operation is visible.
- **`T1` to `Tk−1` committed:** the entry is pending. Processing (ours or e2fsck's) completes a truncation or removal, and rolls a write back to its old size.
- **After `Tk`:** the operation is done.

All data was written before each commit (C5), so a truncation or removal is either fully done or not done. A write is not done or done in size, with Q-A's caveat for bytes inside the old size.

## 6. Commits, limits, full journal, wrap, splitting, orphans

### 6.1 When a transaction commits

- In `BeginStep`, and again after a step, when `Footprint(running) ≥ limits.soft` or the running transaction is ≥ 5 s old by `Host::WallClockNanoseconds`.
- When a step overflows while other steps are running; the step is then retried alone.
- After a `NoSpace` that the running transaction's freed blocks could cure; the step is then retried once.
- In `Sync` and `CloseJournal`, and after `NoteError`.
- At the end of orphan processing at mount.

A commit with nothing running writes nothing. Step 5's adapter calls `Sync` every 5 s.

### 6.2 Limits

- **Overflow.** Adding a new block to the step layer overflows when `|running ∪ step| > limits.hard` or `Footprint(|running ∪ step|, revokes + pending_forgets) > ring_len − 1`. `WriteMetadata` then sets `overflowed` and returns `NoSpace`, and `Journalled` rolls the step back.
- **Full log.** A log without room for `T` gets a full checkpoint first (C1).
- **Memory.** If the committed layer goes over its cap after a commit, it is checkpointed (C9).

### 6.3 Wrap

`head` advances modulo the ring, and `wraps` counts passes over the end. A transaction may straddle the end of the ring.

At mount, `head = s_first`, and the first transaction ID is `s_sequence + 1`, as jbd2 does for an empty journal.

### 6.4 Freeing and reuse

- **`FreeBlock`:** drop the block from the step layer. If running or committed holds a copy, add the block to `pending_forgets`. Add its group to `freed_groups`.
- **`EndStep`:**
  1. `WriteGroups` puts the dirty descriptors into the step layer.
  2. Each pending forget the step did not write again leaves step and running. If committed holds it, it is added to `revokes`. A forget whose block the step holds again is dropped (E1, `docs/design/review-E1.md`).
  3. Running absorbs step.
- **At C8:** revoked blocks leave committed.
- **Allocation:** it excludes blocks that the committed view of a `freed_groups` bitmap still marks as used. A block freed in `T` is therefore never handed out before `T` commits, so it is never both revoked and journalled in the same transaction.

### 6.5 Rollback (`AbortStep`)

1. Drop the step layer, `pending_forgets` and `overflowed`.
2. Restore `superblock` from `step_superblock`, keeping the errors bit in `state`.
3. Reload into `descriptors` every descriptor block that was in the dirty range or in the step layer. Read them from running, then committed, then disk.
4. Clear the dirty range.

Outside a step, the in-memory descriptor table always equals the layered view, which is why the reload is exact.

### 6.6 Split operations and orphans (4c)

In 4b, a change that overflows with nothing else running fails with `NoSpace` and changes nothing. From 4c on, the following paths catch "overflow alone". The volume uses its orphan file, or the list (§4.2). Every piece is a step under `Journalled`, and a commit may fall between any two pieces.

**Truncation (shrinking), `TruncateSplit`:**
1. Piece 1: `ZeroFrom` at the new size; store `i_size = target` and the times; `AddOrphan`.
2. Pieces 2..n: `ShrinkTo` from the end, halving the span after each overflow. Each piece stores `i_blocks`.
3. Last piece: the final `ShrinkTo` and `RemoveOrphan`.

**Removal** (`Remove`, or `Rename` onto a regular file whose last link goes, when the plain change overflows):
1. Piece 1: drop the name, or point it at the source for a rename; links 0; `AddOrphan`. The rename itself is then atomic.
2. `ReleaseSplit`: `ShrinkTo(0)` in pieces as above.
3. Last piece: the extended-attribute block, `FreeInode` with `dtime`, and `RemoveOrphan` in the same step.

Directories that are removed are empty, so they never split.

**Write, `WriteSplit`** (a write that would end past `i_size`):
1. Piece 1: `AddOrphan`, then write the first chunk. `i_size` stays at the old size; blocks past it may be mapped.
2. Further chunks halve after an overflow. In this mode, step 3's rule "the size before the mapping" does not apply: the orphan entry stands in for it.
3. Last chunk: store `i_size = offset + written` and remove the entry.

A short write (volume full) ends the same way with the bytes written. A write entirely inside `i_size` splits into chunks without an entry: each chunk is consistent and visible, as in ordered mode (Q-A).

**Processing at mount (`ProcessOrphans`).** It runs after `MarkMounted`, before `Mount` returns:
1. `CheckOrphans` validates first and writes nothing:
   - every orphan file block has the magic and, with metadata_csum, the checksum;
   - every slot and list entry is in `[s_first_ino, s_inodes_count]` and marked in the inode bitmap;
   - the list has no repeats (at most `s_inodes_count` steps).
2. Then each entry is processed, file slots first and then the list from its head (§4.2):
   - links 0: `ReleaseSplit`, finishing with `RemoveOrphan`;
   - a linked regular file: `ShrinkTo` to `ceil(i_size / block_size)` in pieces, then `RemoveOrphan`;
   - a linked inode of another type: `RemoveOrphan` only, with a log line.
3. A commit follows. `orphans_processed` counts the entries.

These cover our own entries and Linux's.

**Volumes without the orphan file** (ext3, and ext4 made before e2fsprogs 1.47) use the `s_last_orphan` list. That is the recommended choice, for three reasons:
- the list is the format every Linux and e2fsck since ext3 processes;
- for us it costs O(1), since our entry is always the head;
- the alternative leaves split operations non-atomic on exactly the volumes (ext3) most likely to come from older systems.

## 7. Mount, unmount, errors, edge cases

### 7.1 `StartJournal`

It runs on a writable mount with `has_journal`, after `Mount`'s recovery. It uses `OpenJournal` and `CheckJournalSuperblock`.

With the log empty, it adjusts the features:
- set REVOKE;
- set 64BIT when the volume has `64bit`;
- set CSUM_V3 when the volume has `metadata_csum` and the journal has neither v2 nor v3;
- keep v2;
- clear `JournalCompatibleChecksum`;
- keep ASYNC_COMMIT when v2/v3 is present.

If any feature changed, it encodes them, writes the journal superblock and flushes (M2). Then it allocates the state, sets the limits and maps every ring position once; a hole is `Corrupt`.

### 7.2 Refusals

Each of these mounts read-only, with the line `ext2: mounted read-only: <reason>`. `Mount` succeeds, `writable` is false, and nothing is written.

| Case | Reason |
|---|---|
| journal on another device (`s_journal_inum` 0) | "the journal is on another device" |
| journal superblock version 1 | "a version 1 journal cannot hold revoke records" |
| `s_maxlen < 1024` | "the journal is shorter than 1024 blocks" |
| unknown jbd2 incompatible features (incl. fast commit 0x20); async_commit without v2/v3 | "unsupported journal features" |
| another fault in the journal superblock or journal inode | "the journal superblock does not hold together; run e2fsck" |
| `s_start ≠ 0` with `needs_recovery` clear | "the journal holds transactions but needs_recovery is clear; run e2fsck" |
| ext4 compat `fast_commit`, `stable_inodes`, unknown compat features | existing compat-mask reason |
| orphan file without a journal | existing (compat mask) |
| `s_orphan_file_inum` not a regular file of whole blocks | "the orphan file does not hold together; run e2fsck" |
| `CheckOrphans` fails (bad magic or checksum, an entry out of range or free, a loop) | "the orphan list does not hold together; run e2fsck" |
| a volume without a journal with `s_last_orphan ≠ 0` | "orphan inodes are left to finish; run e2fsck" |
| a device that refuses writes at M2/M3 | "the device is read-only" |

A change that does not fit even alone fails with `NoSpace` and changes nothing:
- in 4b: any change;
- from 4c on: only changes that cannot be split, such as a hash index drop larger than `limits.hard`.

### 7.3 Errors

**`Corrupt` in a step.**
1. The step is rolled back.
2. `NoteError` sets `StateErrors` and stops writes unless `s_errors` says continue.
3. The running transaction commits.
4. The next mount is read-only until e2fsck has run.

During orphan processing, a `Corrupt` entry stops processing the same way, and the mount ends up read-only.

**`Io` in the log, home writes, the journal superblock or a Flush** (`AbortJournal`):
- This mount writes nothing more, and `read_only` becomes true.
- The failing call returns `Io`, and later changes return `ReadOnly`.
- `Sync` and `CloseJournal` return `{}` without writing.
- `needs_recovery` and any orphan entries stay on disk for the next writable mount.

## 8. Invariants

- **I1 — Write-ahead.** Metadata reaches its home location only through Checkpoint, which writes only committed copies, after their commit block has been flushed.
- **I2 — Ordered mode.** Every data write of a transaction completes before the Flush (C5) that precedes its commit block. New blocks never become reachable with stale bytes.
- **I3 — Commit order.**
  - C2, the revoke blocks, the descriptors and the copies of `T` are flushed before `T`'s commit block.
  - The commit block is flushed before `T` enters the committed layer.
- **I4 — Whole steps.**
  - A transaction holds only whole steps.
  - A failed or overflowing step leaves no trace in the layers, in `superblock`, in `descriptors`, or in the revoke and freed sets.
  - A committed state is `e2fsck -fn` clean once its orphan entries are processed; without pending entries it is clean as it stands.
- **I5 — `needs_recovery`.**
  - It is set and flushed (M3) before any log block of the mount.
  - It is cleared (U1) only after the log is empty on disk.
  - `StateClean` stays set while the journal is in use.
- **I6 — Log position.** `(s_start, s_sequence)` on disk is either the epoch's first transaction or `(0, next ID)`. It becomes nonzero only at C2 and returns to 0 only at K3.
- **I7 — Ring space.**
  - `used + F(T) ≤ ring_len − 1` whenever `T` is written.
  - The running transaction never exceeds `limits.hard`.
  - `limits.hard ≤ ring_len − 1`.
- **I8 — Sequence numbers.**
  - The first transaction ID of a mount is `s_sequence + 1`, and IDs then increase by one per commit.
  - Every block of `T` carries `T`.
  - No ring block reachable from `s_start` carries a stale sequence number of the epoch.
- **I9 — Escaping.** A copy that starts with the magic is logged with those 4 bytes zeroed and ESCAPE set. No other byte of any copy differs from the block.
- **I10 — Format.** The journal blocks follow §4.1 for the features as written. Step 1's decoders and e2fsprogs read them back, and tag checksums cover the escaped copy.
- **I11 — Revoke and forget (restated as E-I2, E-I3).**
  - A freed block that has a committed copy gets a revoke record in the running transaction, and leaves the committed layer at that commit.
  - A freed block's step and running copies are dropped, unless the same step wrote it again as metadata (E-I1): the step's copy then joins running, and the block carries no revoke.
  - No transaction both revokes a block and logs a copy of it.
  - Revoke records are written only with REVOKE set.
- **I12 — No reuse before commit (restated as E-I4).** A block that is set in the committed bitmap and freed in the running transaction is not allocated again before that transaction commits. A block born in the running transaction may be re-used within it.
- **I13 — Read your writes.** Metadata reads look at step, running, committed, then disk. Data reads never see a layer.
- **I14 — Classification.** Exactly the blocks in §2's journalled column are journalled.
- **I15 — Checkpoint.**
  - It writes the whole committed layer home, flushes, then empties the log on disk and flushes.
  - It runs only when the ring or memory runs short, or at unmount.
- **I16 — Unmount.** Commit, then checkpoint, then clear `needs_recovery`, then Flush. The result is `e2fsck -fn` exit 0 without replay, with no orphan entries and `orphan_present` clear.
- **I17 — Abort.** After an `Io`, nothing more is written, and `needs_recovery` and any orphan entries stay.
- **I18 — Journal features.** They change only at mount, with the log empty, before M3, as in §7.1.
- **I19 — Limits.** Running plus step stays ≤ `limits.hard`. Committed stays ≤ its cap after every commit. `LimitJournal` only lowers the limits.
- **I20 — Every transaction is self-consistent.** Every transaction holds the superblock with exact free counts, `s_last_orphan` and `orphan_present`, and every changed descriptor block with exact counts, flags and bitmap checksums.
- **I21 — Unjournalled volumes unchanged.** Without a journal, the writes and flushes are exactly those of steps 2 and 3.
- **I22 — Freed metadata never shadows data.** After a metadata block is freed and the freeing transaction commits, neither a layer copy nor a replayable log copy can overwrite data written to that block later.
- **I23 — Orphan protection.**
  - A split operation's first transaction adds the entry. It does so together with the stored target size (truncation), the dropped name and zero links (removal), or the old size kept (write).
  - Every intermediate transaction keeps the entry, and the completing transaction removes it.
  - Outside a split operation, no entry of ours is in any committed state.
- **I24 — Orphan structures.**
  - Every committed orphan file block has the magic and, with metadata_csum, the right checksum.
  - `orphan_present` is set exactly while some slot is nonzero.
  - The list is a chain from `s_last_orphan` through `i_dtime`, ending at 0, without repeats.
  - Our own entry is always the head.
- **I25 — Processing at mount.**
  - A writable journalled mount validates every entry before writing.
  - It processes every entry in transactions before `Mount` returns: truncate a linked file to `i_size`, release an unlinked inode.
  - An entry leaves in the transaction that finishes it.
  - Afterwards `s_last_orphan` is 0, every slot is 0 and `orphan_present` is clear.
- **I26 — Agreement with e2fsck.** For the same crashed volume, our replay plus processing and `e2fsck -fy` give the same tree, sizes and contents, and the same free block and inode ranges per group.

## 9. Known hard limits and `WriteRefusal` masks

**Masks.**
- `CompatibleWritable` gains `CompatibleHasJournal`.
- `CompatibleOrphanFile` is writable only together with `has_journal`.
- `ReadOnlyCompatibleOrphanPresent` (4c) is writable only with the journal and the orphan file.
- A volume without a journal with `last_orphan ≠ 0` is refused (4c).
- The refusal "a journal, which writes would have to go through" goes away. The journal and orphan refusals of §7.2 apply in `StartJournal` and `CheckOrphans`.

**Known hard limits (`CLAUDE.md`, done in 4d).**
- **Replaced.** "ext3 and ext4 with a journal read-only in FeatherOS (the core writes ext2 and ext4 without a journal …)" becomes "ext3 and ext4 with a journal read-only in FeatherOS until step 5 (the core writes them through an internal jbd2 journal in ordered mode …)".
- **New.**
  - These mount read-only: journals on another device, version 1 journals, journals shorter than 1024 blocks, journals with fast commits or unknown features, malformed orphan lists or orphan files, and volumes without a journal that have orphans.
  - Commits happen at Sync, at unmount, at a quarter of the journal, or at 5 s between changes; the kernel syncs every 5 s from step 5 on.
  - Checkpoints are whole-log.
  - A change that does not fit in one transaction (`min(journal − 1, 4 MiB of blocks)`) even alone, such as a very large hash index drop, fails with `NoSpace`.
  - Overwrites inside a file are not atomic across a crash (ordered mode).
  - `needs_recovery` is set while the volume is mounted.
- **Gone.** The orphan-related read-only fallback on journalled volumes.

## 10. Acceptance tests

**Conventions.**
- Every test that writes ends with `CheckClean` (`e2fsck -fn`, exit 0) after unmount, unless it says otherwise.
- **"Both replays"** means two copies of the device:
  - (a) mounted writable (`RecoverJournal`, then orphan processing in 4c and later), then unmounted;
  - (b) `e2fsck -fy`, which must exit ≤ 1 and print nothing but journal recovery and orphan release lines.

  Then `e2fsck -fn` must return 0 on each. Before 4c there are no orphans, so (b) may also be `debugfs -w -R jr`, and then (a) must equal (b) byte for byte, ignoring the superblock's times, `s_kbytes_written` and checksum (step 1's comparator). From 4c on, after orphan release, (a) and (b) are compared by tree (names, types, sizes, links, contents) and by `dumpe2fs` "Free blocks"/"Free inodes" per group, since `dtime` values differ.

**Images** (`make_ext2_image.sh` and the CMake list):
- New `ext4-journal-gdtcsum`: `-t ext4 -b 1024 -O ^metadata_csum,uninit_bg`. It has 64BIT tags without checksums (12 bytes). If `mke2fs` insists, add `^orphan_file`, in which case this ext4 image uses the list.
- New `ext4-4k`: `-t ext4 -b 4096`, 16 MiB, a 1024-block journal.
- `ext3` (list only), `ext4`, `ext4-blockmap` and `ext4-64bit` (with orphan file) already have 1024-block journals.
- v2 journals are made with `debugfs -w "jo -c -v 2"` then `"jc"`. COMPAT_CHECKSUM and ASYNC_COMMIT are set by patching the journal superblock and its checksum.

### 4a

- **T1 — Encoders round-trip** (no images). For each of none, v2, v3, 64BIT, 64BIT+v2 and 64BIT+v3:
  - a full descriptor reads back through `JournalTags` (blocks, flags, checksums), and one more `Add` returns false;
  - tails and commit blocks match, and fail after a flipped byte;
  - `JournalTagMatches` accepts `JournalTagChecksum`;
  - a revoke block reads back, and `JournalRevokesPerBlock` is exact;
  - `EscapeJournalBlock` touches only blocks led by the magic;
  - `EncodeJournalFeatures` passes the decoder and the check.
- **T2 — Hand-built logs against both replayers.** Images and tag sizes: `ext3` (8), `ext4-blockmap`+v2 (10), `ext4-journal-gdtcsum` (12), `ext4-64bit`+v2 (14), `ext4` (16, 64-bit), `ext4-blockmap` (16).
  - Find the ring with `debugfs "blocks <8>"`.
  - Write two committed transactions and a torn one, starting 3 blocks before the ring's end. They hold: `hello.txt`'s inode table block with mode 0600, a spare block led by the magic, and a revoke.
  - Set `s_start`, `s_sequence`, the features and `needs_recovery`.
  - `logdump` lists exactly these, and both replays agree.
- **T3 — Routing changes nothing.** The whole existing suite passes unchanged.

### 4b

- **T4 — Writable or read-only.**
  - `ext3`, `ext4`, `ext4-blockmap`, `ext4-64bit`, `ext4-extents`, `ext4-journal-gdtcsum` and `ext4-4k` mount writable.
  - Each journal case of §7.2 mounts read-only, with every byte unchanged and `flush_count` 0.
  - async_commit with v3 is writable.
  - Remove the journalled images from the existing tests that expect them to be read-only.
- **T5 — Mount and unmount state.**
  - After mount: `needs_recovery` and `StateClean` are set on disk.
  - `dumpe2fs -h` "Journal features": `ext3` has revoke; `ext4` has revoke, 64bit and checksum_v3; v2 is kept; COMPAT_CHECKSUM is cleared.
  - The first sequence number is `s_sequence + 1`.
  - After unmount the volume is clean without replay.
- **T6 — One transaction's content** (`ext3`, `ext4`, `ext4-extents`).
  - Create `/a.txt`, write 3 blocks, Sync, take a copy.
  - `logdump`: the tags are exactly the superblock block, both bitmaps, the descriptor block, the inode table block or blocks and the root directory block. No data block appears.
  - The data blocks are at home, and the home inode table block is as it was in the original.
  - Both replays agree.
  - The commit costs 2 flushes.
- **T7 — Read your writes.**
  - Without Sync: creates, writes, renames, removals and a slow symlink.
  - Lookup, ReadDirectory, ReadLink, GetAttributes and Statistics all see the changes.
  - Non-data bytes on disk are unchanged until Sync.
- **T8 — Escaping** (`ext4-64bit`, `ext4-4k`, plus a v2 variant).
  - Set image bytes 0–3 to the magic, change something, Sync.
  - `logdump` shows block 0 with flag 0x1, and the log copy starts with 4 zero bytes.
  - After both replays, bytes 0–3 are the magic again.
- **T9 — Revoke and forget** (`ext3` with indirect blocks, `ext4` with a two-level extent tree).
  - Write the file, Sync, remove it, Sync. `logdump` shows revokes of its logged tree or indirect blocks.
  - A new file reuses those blocks (checked with `debugfs stat`); Sync.
  - Both replays and the checkpoint at unmount keep the new file's bytes.
- **T10 — No reuse before commit; NoSpace retry.**
  - On a volume full except for X's blocks: remove X, then write Y in the same transaction. Exactly one retry happens, and Y takes X's blocks.
  - With free space elsewhere, Y's blocks are disjoint from X's.
- **T11 — Wrap and checkpoint** (`ext3`, `ext4`, `ext4-4k`).
  - 600 synced changes give `wraps` ≥ 2 and `checkpoints` ≥ 2.
  - 10 copies whose log wraps pass both replays.
  - A model of the files matches after unmount.
- **T12 — Commit policy.**
  - 2000 changes without Sync commit on their own, within `limits.hard`.
  - An empty Sync writes nothing.
  - Each commit and each checkpoint costs 2 flushes.
  - `LimitJournal({8, 24, 32})` forces checkpoints by memory.
- **T13 — Overflow** (4b).
  - With `LimitJournal({8, 24, 32})`, a change that overflows while others are running commits them and retries (`retries` grows).
  - In 4b, a 2 MiB `Write`, a truncation of a 3 MiB file, its removal, and a name added to `ext4-htree-gdtcsum`'s `large/` each fail with `NoSpace` and change nothing (Statistics, reads, the next Sync's `logdump`).
  - From 4c on, only the `large/` case still fails; T21 covers the others.
- **T14 — Rollback.** A `NoSpace` mid-step (create in a full directory on a full volume) and an `Io` mid-step (`FailReadsFrom` on a bitmap) leave Statistics and every read as they were. The next Sync commits only earlier changes.
- **T15 — Errors and abort.**
  - A damaged bitmap gives `Corrupt`. Earlier changes and `StateErrors` are committed, and the next mount is read-only.
  - `FailWritesAfter` inside a commit: the Sync returns `Io`, then changes return `ReadOnly`, and unmount returns `{}`. The next writable mount replays, and the volume is clean.
- **T16 — Existing scenarios over journals.** The write, tree, htree and extent-write scenario lists gain `ext3`, `ext4`, `ext4-blockmap`, `ext4-64bit` and `ext4-extents`/`ext4-4k`. Each must be clean after unmount.
- **T17 — Feature edge cases.** COMPAT_CHECKSUM is cleared, and e2fsprogs then replays our commits. ASYNC_COMMIT with v3 is kept, and both replays agree.

### 4c

- **T18 — Orphan file format.**
  - `OrphanBlockChecksum` equals the stored checksum of every block of the fresh orphan files of `ext4`, `ext4-blockmap`, `ext4-64bit` and `ext4-4k`.
  - Slot fill and clear round-trips.
  - `s_orphan_file_inum` and `s_last_orphan` decode as `dumpe2fs -h` shows them.
  - After T21's split operations, `e2fsck -fn` reports no orphan file block problems.
- **T19 — Linux-style orphans, processed and compared with e2fsck.** Made with debugfs on copies:
  - an unlinked inode with blocks (`sif links_count 0`, `unlink`, `ssv last_orphan`);
  - a linked file with blocks past `i_size` (`sif size`) on the list;
  - a chain of three;
  - the same in orphan file slots, written with T18's checksum, with `feature orphan_present`.

  A writable mount processes them all (`orphans_processed`), and they are cleared. Both replays agree by tree and free ranges.
- **T20 — Malformed orphans and refusals.**
  - Each of these mounts read-only with nothing written: a list loop, an out-of-range entry, a free inode in the list, a bad orphan block magic, a bad orphan block checksum, a bad orphan file inode, and a volume without a journal with `s_last_orphan`.
  - A read-only mount of T19's volumes reads them as they are.
- **T21 — Split operations complete.** With `LimitJournal({8, 24, 32})` on `ext4` (orphan file), `ext3` (list) and `ext4-4k`, run:
  - a 2 MiB extending `Write`;
  - a 2 MiB overwrite inside the size;
  - truncation of 3 MiB to 1000 bytes and to 0;
  - removal of a 3 MiB file;
  - a rename onto a 3 MiB file.

  All succeed (`splits` > 0, `orphans_added` > 0), read back correctly, and leave no entry and `orphan_present` clear.
- **T22 — States in the middle of a split.** For each operation of T21, cut with `FailWritesAfter` just after the commit of its first transaction, and just before its last commit:
  - (a) **e2fsck on a pending entry.** `debugfs jr` alone, then `e2fsck -fn`. From e2fsck's source, `check_super_block` calls `release_orphan_inodes` only without `-n`, so we expect a nonzero exit (the orphan's size or link report). The test records the actual exit status and first report line; nothing else depends on it.
  - (b) **The operation is done or not done.** Both replays leave it fully done or not done: a truncation at its target size with the blocks freed, a removal gone (a rename done), a write at its old size or its new one. Both replays agree by tree and free ranges.
  - (c) **e2fsck output.** `e2fsck -fy` prints orphan release lines and no orphan-file checksum complaints.
- **T23 — Flag and list are empty after every change.** After every change and Sync of T16's scenarios: `s_last_orphan` is 0, every slot is 0, and `orphan_present` is clear (debugfs `stat <12>`/`dumpe2fs`).

### 4d

- **T24 — Crash at every write** (`ext3`, `ext4`, `ext4-blockmap`+v2, `ext4-journal-gdtcsum`, `ext4-64bit`).
  - A scenario of about 25 synced changes, from mount to unmount, cut at every write. Both replays.

- **T26 — Crash in split operations** (with `LimitJournal({8, 24, 32})`, on `ext4` and `ext3`).

  - After both replays, plus orphan processing, each operation is fully done or not done.

- **T27 — Interrupted replay and processing.** For 5 crash images with at least 2 transactions in the log and a pending orphan, stop `RecoverJournal` and then `ProcessOrphans` at every write. The next writable mount reaches the same tree and free ranges as an uninterrupted one.

- **T29 — `fscli`.**
