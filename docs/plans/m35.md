# M35: screen and input foundations

Branch `feat/screen-input`, cut from `main`. Requirements: `docs/roadmap.md` milestone 35 (`grep -n "### 35\." docs/roadmap.md`). Design: `docs/design/M35.md`: decisions D1-D9, the reserved ABI numbers, the design by part in section 1, files and signatures per step in section 2 (`**Step <id>:**`), invariants in section 3, edge cases in section 4, the step table in section 5 and the tests in section 6. A finished task also gets its "done" sentence in the roadmap and in CLAUDE.md's Status through the `finish-step` skill.

The full matrix runs after parts A, B and C (part C's is the final run). Within a part, a task is verified by its unit tests and affected smoke modes on both architectures.

## Part A: run-time screen size

- [x] A1. The framebuffer and console take their size from the bootloader. Risky (the boot path on both architectures). Design 1.1, D1, D2, invariants I1-I3, tests T1 and T2. `Framebuffer::init` takes the caller's back buffer, `InitializeDisplay` allocates it and logs `Display: WxH, console CxR`, `TermConfig` becomes the 320x100 maximum, `Config` goes. Unit tests `framebuffer` and `terminal`; smoke `SHELL GRAPHICS FONTS DUNGEON PANIC`. Mutation: capacity one byte short accepted (T1).
- [x] A2. `SCREEN=WxH`, the harness and `SCREEN_SIZE_TEST`. Design 1.2, D3, tests T13 and T14. **First boot AArch64 with `SCREEN=1920x1080` and record the mode it gets in design section 7**; if the firmware does not offer it, use the largest listed mode at least 1280 wide for the AArch64 cases. Matrix cases `screen_size` for both architectures. Smoke `SCREEN_SIZE`. Then the Part A matrix.

## Part B: input for a compositor

- [x] B1. The Super modifier and the Meta key codes. Design 1.3, D4, invariant I6, tests T3, T4 and T15. Bit 16 in the kernel, `syscall_abi.h` and `<featheros/framebuffer.h>`; `E0 5B` and `E0 5C` on the PS/2 path. Unit tests `keyboard` and `graphics_mode`; smoke `GRAPHICS USB_KEYS INPUT`.
- [x] B2. `FB_ACQUIRE` flags: raw keys and keep screen. Design 1.3, D5, invariants I4, I5 and I7, tests T5, T6, T16 and T17. `fbtest --raw` and `--keep`; `Display::Open(flags)`. Unit tests `graphics_mode` and the user `graphics` tests; smoke `GRAPHICS SHELL`. Mutations: `TakeKey` signalling a raw owner (T16); blanking with keep-screen (T17).
- [x] B3. Absolute pointers. Design 1.4, D6, invariant I8, tests T7, T8 and T18. The HID parser, `EV_ABS` on `/dev/mouse`, `mousetest`, `USB_TABLET_TEST` with matrix cases for both architectures. Unit tests `hid_report`, `hid_driver`, `pointer`; smoke `USB USB_TABLET`. Mutation: the scale without its clamp (T7). Then the Part B matrix.

## Part C: time and present cost

- [x] C1. The fine clock and syscall 75. Risky (architecture code, the syscall ABI). Design 1.5, D7, D8, invariants I9-I11, tests T9, T10 and T19. `Arch::FineCounter` on both architectures, `kernel/time/monotonic.{h,cpp}`, `Time::MonotonicNanoseconds`, libc `clock_gettime`. Unit tests `monotonic` and `./build.sh unit-test-tsan` for `[concurrency]`; smoke `TIMER SHELL SMP`. Mutations: `Interpolate` without its cap (T9); the reader ignoring the sequence counter (T10).
- [x] C2. `fbbench` and the "before" measurements. Design 1.6, test T20. Use the `add-program` skill. Run it in Debug and Release at both screen sizes on both architectures and fill the "Before C3" column of design section 7. Smoke `SHELL`.
- [x] C3. The present copies only its span. Design 1.6, D9, invariant I12, tests T11 and T12. Fill the "After C3" column and record the decision on the bounce row in design section 7; if the bounce pass is at least a fifth of a full-screen present in Release, add step C3b under this task for the direct copy and do it. Unit tests `framebuffer`; smoke `GRAPHICS FONTS DUNGEON SHELL`. Mutation: the span draw using the whole row's offset (T11).
  - [x] C3b. The direct copy of XRGB8888 rows. Added by C3: the bounce pass was 74-77% of a full-screen Release present. `Console::PresentRowDirect`, `Framebuffer::directRow`, `CopyPixelBytes`; other pixel formats keep the bounce row. Tests T11/T12 plus `CopyPixelBytes` and `directRow` unit tests; smoke `GRAPHICS FONTS DUNGEON SHELL`.

## Run log

- A1: sonnet high, 0 fix rounds; smoke SHELL GRAPHICS FONTS DUNGEON PANIC both arches pass (affected only; matrix after A2). Mutation I1 caught by T1. Display line prints after "Framebuffer console initialized" (dmesg head check), console 126x46 at 1024x768. Accepted: back buffer frames leak if init fails after RequiredBytes succeeded (cannot happen).
- A2: sonnet high, 1 fix round (Select called issubclass on the RootOption function: cases 39-46). AArch64 has no mode above 1024x768 (ramfb firmware list; bochs-display, VGA, virtio-gpu give no linear framebuffer), so its screen_size case is 800x600; the user deferred a virtio-gpu driver to docs/ideas.md. fbdemo now draws for any size. Marker-ended smoke cases (BootToShell, KernelTest) get a 30 s limit: under another session's QEMU load, x86-64 boots took 14-17 s and 01/41 timed out at 10 s. Part A matrix: 91/100 then the 9 failures pass on re-run.
- B1: sonnet high, 0 fix rounds (stopped once by a usage limit, resumed); GRAPHICS USB_KEYS INPUT both arches pass (affected only). T15 drives `fbdemo --keys` rather than `fbtest`. Accepted: a letter typed with Super held on the text console is unit-tested only.
- B2: sonnet high, 0 fix rounds; GRAPHICS SHELL both arches pass (affected only); mutations I4 by T16, I7 by T17. `ioctl(FB_ACQUIRE)` now reads its argument, so every caller passes `0UL`. `fbtest --keep` turns off echo and the cursor, and T17 skips the top 32 rows (padding, status bar).
- B3: sonnet high, 0 fix rounds; USB USB_TABLET both arches pass, cases 102-103 pass; mutation I8 by T7. `mousetest` prints one line per axis (`mouse: abs x N`); the tablet binds to the generic `hid` driver. Part B matrix: 100/102, then both failures pass on re-run (flakes): 19_x86_64_calculator_command (empty session under host load) and 84_x86_64_nvme_release (`init` restarted the shell and dhcp after SIGKILL during shutdown, so "some processes did not stop"; a shutdown race, unrelated to Part B).
- C1: sonnet high, 1 fix round (the finer clock showed `nanosleep(30 ms)` ending after 20 ms: the kernel sleeps whole ticks from the next one; `nanosleep`, `usleep`, `poll` and `pthread_cond_timedwait` now finish their remainder against `CLOCK_MONOTONIC`). TIMER SHELL SMP both arches and unit-test-tsan pass (matrix after Part C). Mutations I10 by T9, I11 by T10. Step about 1 µs on both arches; x86-64 boot spends about 110 ms calibrating the TSC. Accepted (reviewer): during the instant between `ticks + 1` and the sample's publish, `UptimeMilliseconds` can lead the fine clock by under a tick; `tick_nanoseconds` truncates for a rate that does not divide 1e9 (only 100 Hz is used). `poll`'s re-poll has no test of its own.
- C2: sonnet, 0 fix rounds; SHELL both arches pass (affected only); section 7 "Before C3" filled (lower of two runs, host shared with other sessions' QEMU). AArch64 at 800x600: a 640x480 present costs about as much as the full screen (480 of 600 whole rows copied).
- C3 and C3b: sonnet high, 0 fix rounds; GRAPHICS FONTS DUNGEON SHELL both arches pass (matrix after D1); mutation I12 by T11 (T12 too). The bounce pass was 74-77% of a Release full-screen present, so C3b copies XRGB8888 rows from the program straight into the back buffer (other formats keep the bounce row); a full 1920x1080 Release present went from 21.6 ms to 4.9 ms on x86-64. Accepted: a program that frees its pages during its own present can leave one of its rows part-written; on AArch64 at 800x600 a 640x480 present still costs about as much as the full screen (unexplained).
- D1: sonnet, 0 fix rounds; docs only (most items already landed with their tasks). Final matrix: 102/102 passed first time.
